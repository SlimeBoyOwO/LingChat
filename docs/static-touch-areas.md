# 静态立绘触摸区域

角色的 `settings.yml` 里 `body_part` 描述「摸到立绘的哪一块要发什么话」。触摸模式下，
`TouchAreas.vue` 把这层不可见的多边形铺在立绘上，点中即把提示词作为玩家消息发给 AI。

Live2D 角色不走这条路——它的可摸范围由模型侧配置决定，见 `docs/live2d/`。

## 数据形状

```yaml
body_part:
  默认:
    head:
      message: 莱姆摸了一下你的头
      polygons:
        - [[0.41, 0.17], [0.49, 0.14], [0.47, 0.3]]
  泳装:
    head: { message: "...", polygons: [[[0.4, 0.2], [0.5, 0.2], [0.45, 0.3]]] }
```

- 顶层键是**服装的显示名**，与 `scan_clothes` 给出的 `ClothesItem.title` 一致；根目录那套是「默认」。
  空串、「默认」与大小写不限的 `default` 都归到「默认」，规则同 Rust 侧的 `canonical_clothes`。
- 每个部位一句提示词；同一部位可以挂多块互不相连的多边形，共用这句提示词。
- 每条消息留空时，运行时回落到「{玩家名}戳了一下你」。

## 坐标约定

`polygons` 里的点是**相对立绘图片自身**的 0..1，原点左上。它与窗口尺寸、角色 `scale`、
`offset_x/offset_y`、应用级缩放都无关，所以换分辨率、调缩放、多角色同台时区域都跟着立绘走。

成立的前提是**同一套服装的每张情绪立绘共用同一块画布**（同宽高比即可，不必同尺寸）。
出厂数据满足这一点；若某套立绘按情绪裁切过，区域会偏，此时应改用同一张底图。

## 运行时如何对齐

多边形叠层挂在 `ImageAcrossFade` 的 `overlay` 插槽里——两个背景层都是该元素内的
`absolute inset-0`，放进去的东西用同样定位就与立绘的绘制盒子结构上重合，不需要任何测量或换算。

叠层本身是 `viewBox="0 0 1 1"` 且 `preserveAspectRatio="none"` 的 SVG，盒子由
`imageRectInBox()` 算出的立绘落位摆放，于是 SVG 的 user 坐标就是图片归一化坐标，取点只需按
元素矩形做一次除法。`imageRectInBox()` 同时吃下宽屏的 `contain` 与窄屏的 `auto NN%` 两种取景，
后者是「高度锁死、宽度溢出、被容器裁掉」，`preserveAspectRatio` 表达不了，所以不靠浏览器对齐。

这么放的另一个好处是叠层自动跟随角色的位移、缩放、投屏偏移与呼吸动画——早期版本只看
`window.innerWidth/innerHeight`，多角色同台时所有角色的多边形会叠在正中央。

## 旧数据

早期形状是「部位名 → X/Y 数组 + clothesName + message + 截图分辨率」，坐标相对某次截图的
视口、以视口中心为锚点、按高度等比缩放。`touch-regions.ts` 在读取时把它换算到图片坐标，
**在同一次几何下换算再渲染是精确往返**，所以旧角色在游戏里的显示位置与改动前一致。

旧坐标表达的是「视口相对位置」而不是「图片相对位置」，换算结果只在换算时用的那个取景下等价。
用编辑器打开并保存过一次之后，数据就落到新形状，不再有这个性质。

## 编辑器

人物设置的「触摸区域」标签页 → 编辑触摸区域，打开一个全屏编辑器：

| 操作              | 行为                                                   |
| ----------------- | ------------------------------------------------------ |
| 侧栏「新增区域」  | 建好一个空区域并聚焦名字，命名之后再到画布上画         |
| 空白处单击        | 已有选中的区域就往它上面再加一块，否则等同「新增区域」 |
| 双击 / 回车       | 闭合（顶点不足三个则丢弃，空区域留着可以接着画）       |
| 点回第一个顶点    | 同上                                                   |
| Esc               | 放弃正在画的，否则清除选中                             |
| 拖动顶点          | 移动（夹在图片范围内）                                 |
| 选中顶点后 Delete | 删除该顶点；只剩三个时删除整块多边形                   |
| 侧栏「＋多边形」  | 给该区域追加一块                                       |

区域名与提示词都在右侧的卡片上编辑，提示词按部位共用（同一部位的多块多边形是一句话）。
只命名不画画的区域会在保存时被丢掉——没有多边形就永远摸不到。

区域名的输入框不能直接绑到部位键上：键是改名的结果而不是输入源，而 Vue 每次重渲染都会把 DOM 的
value 强制写回绑定值，绑键的话只要别处触发一次重渲染（比如在右边填提示词），刚敲进去的名字就会
被抹掉。所以输入框走一份独立的草稿，失焦或回车时才提交改名。

编辑器在深拷贝上工作，按钮「保存并关闭」直接落盘，不需要再回到弹窗底部点保存；取消时若有未保存的
改动会二次确认。做成自带保存是因为它是个子流程，两步走（先应用、再保存）很容易让人以为点了应用
就已经写进去了。

编辑器为什么不做成弹窗内的一个普通标签页：弹窗外层是点击关闭，而「按下与抬起落在不同元素」
的手势会被判成点击背景——拖顶点时手滑出面板就会把整个弹窗关掉、改动全丢。
