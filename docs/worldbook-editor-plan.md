# 世界书正则 key 与角色可视化编辑计划

状态：第一期开发完成并收尾，自动验证通过。日期：2026-10-17。

已确认：同一个条目内，每个 key 可以独立选择普通关键词或正则，允许混用。

## 目标与范围

在现有角色可视化编辑器中增加「世界书」页签，支持条目管理、普通关键词与正则混合触发、匹配测试；随角色编辑器底部的保存统一提交，取消不影响正式文件。旧世界书无需迁移即可继续使用。

本期保持角色私有世界书、只扫描本轮原始用户输入、任一 key 命中即触发、按优先级稳定排序等现有行为。不增加共享世界书、历史扫描、递归触发、概率触发、RAG、SillyTavern 导入或独立的全局管理页面。

## 数据格式建议

保留原有 `activation.type: keyword`，把它理解为「按 key 触发」。普通字符串继续表示普通关键词；正则使用显式对象。界面名称显示「按关键词/正则触发」。

```yaml
name: 角色世界书
entries:
  - id: family
    name: 家庭背景
    enabled: true
    priority: 50
    activation:
      type: keyword
      keys:
        - 家庭
        - 母亲
        - type: regex
          pattern: "(小时候|童年).*(住|家)"
          case_sensitive: false
    content: |
      角色小时候住在海边。
```

- 编辑器中普通 key 与正则 key 都有类型选择；写回文件时普通 key 仍用字符串，避免旧文件无谓变化。
- 不用 `/表达式/flags` 自动识别正则，避免把含斜杠的普通文本误判为规则。
- 普通关键词保持去除两端空白、忽略空值、不区分大小写的现有逻辑。
- 正则默认不区分大小写，可逐个 key 切换；按原始输入匹配，不先转小写。保留表达式原始空白，不套用普通关键词的 trim 规则。
- 任一有效 key 命中即触发；一个条目只注入一次。常驻条目不需要 key。
- 不增加正则替换、捕获组插值或内容模板；匹配仅用于决定是否注入。
- 编译使用仓库已有的 Rust `regex` 依赖；语法能力和错误信息以该引擎为准。加载/保存时编译，聊天时复用编译结果。
- 编译对象不写入 YAML 或 IPC；序列化配置与运行时匹配状态分开，避免每轮重复编译。

兼容性：新版本兼容旧文件；新增的对象 key 需要新版本读取。含正则的新世界书分享给旧版本时可能无法加载，需在文档中说明，不承诺向旧应用兼容。

## 角色编辑器中的交互

入口：设置 → 角色 → 编辑 →「世界书」，放在角色提示词附近。

1. 没有文件时显示空状态和「创建世界书」。仅打开页签不创建正式文件。
2. 顶部编辑世界书名称，下方提供条目列表和当前条目表单；窄窗口改为上下布局。
3. 列表显示名称、启用状态、触发方式、优先级，支持新增、复制、删除和上移/下移。复制时生成新 ID；普通用户无需手工填写 ID。
4. 表单提供名称、启用开关、优先级、常驻/按 key 触发、内容多行输入。
5. 每一行 key 提供普通/正则类型选择、输入框和删除按钮；正则额外显示大小写选项和定位到该行的校验错误。
6. 切换到常驻时界面暂存 key，切回可恢复；保存为常驻条目时不输出无效 key 字段。
7. 匹配测试区输入一段模拟玩家发言，点击测试后展示最终会注入的条目、命中的 key 和注入顺序。常驻、禁用、空白内容等按实际注入规则处理，不调用 LLM、不写历史。
8. 使用角色编辑器现有底部保存/取消，不增加一个直接写正式文件的世界书保存按钮。切换页签保留草稿；关闭和取消沿用现有处理方式。
9. 如提供「移除世界书」，需与清空条目区分：前者保存后删除文件，后者保存为 `entries: []`。删除条目/整本书的交互遵循现有删除确认风格。

第一期不需要拖拽排序、语法高亮代码编辑器、原始 YAML 双向编辑或独立导入导出按钮；现有角色归档继续携带世界书。

## 校验与异常处理

- 保存前检查数据结构、非空且唯一的条目 ID、整数优先级、正则可编译性；按 key 触发的启用条目需要至少一个有效 key。
- 空白内容保持运行时跳过；UI 显示提示，不自动生成内容。旧文件重复 ID 等问题在编辑器定位后再保存，不静默修改标识。
- 编辑器允许用户暂时输入不完整正则；校验和测试返回条目 ID、key 索引与原因。未通过校验不得提交正式文件。
- 手工编辑的文件若有无效正则，建议仅跳过该 key 并记录警告，其他有效 key/条目仍工作；YAML 无法解析时延续整本跳过的现有运行时容错。编辑器展示读取错误，不能把错误当成空世界书覆盖。
- 世界书版本以文件存在状态和内容摘要判断；打开编辑会话后如被外部修改，保存拒绝覆盖并保留草稿。
- 新增、修改、删除都进入统一提交和回滚。普通角色配置保存且世界书未改动时，不重写世界书，保留原始格式与注释。
- 结构化编辑会重写被修改世界书的 YAML，默认不保留原注释与排版；应在界面首次编辑说明中提示。
- 保存后的刷新只替换相应已加载角色的世界书，不重置对话、存档或角色其他状态；已在生成的回合继续用原上下文，下一轮采用新内容。
- 非当前角色下次加载时读最新文件；多角色已加载实例也需按角色身份准确更新。运行时刷新失败必须与文件写入失败区分，不能错误宣称文件未保存。

## 验收标准

- 旧世界书原样可用；同一条目可混合普通关键词与正则。
- 用户能在角色编辑器中完成创建、编辑、禁用、复制、排序与删除，无需手写 YAML。
- 测试器与真实聊天使用同一匹配逻辑，显示结果与实际入选条目一致。
- 取消不落盘，保存统一提交；并发外部编辑不会被静默覆盖，失败保留可重试草稿。
- 保存成功后下一轮立即生效；动态资料依旧不写入历史或永久记忆，角色之间不串用。
- 无效文件与无效正则有可定位反馈，错误读取不会被空数据覆盖。

## 已采用的取舍

1. 正则默认不区分大小写，逐 key 提供开关。
2. 匹配测试包含在第一期，帮助用户确认正则和实际注入效果。
3. 编辑器阻止保存无效正则；运行时对外部文件中的无效正则仅跳过该 key。
4. 第一阶段不提供原始 YAML 编辑模式，修改后的文件允许规范化重写，不保留注释排版。
