# 车万女仆桥接

LingChat 通过本机 WebSocket 连上《车万女仆》的 NeoForge 桥接模组：MC 里主人说的话进对话，
角色的回话变成游戏内气泡与语音；模组把世界与她的状态推成事件，插件写成旁白；玩家可以用工具
指挥她走动、坐下/躺下、做事、战斗、挖方块、交东西。

- 协议字段与事件表：[`extension/maid_mod/README.md`](../../extension/maid_mod/README.md)
- 待办与真机验收：[TODO.md](TODO.md)

## 铁律与约定

**分工与顺序。周期采样、变化判定、状态与计时都在模组侧；中文措辞与阈值在插件侧。**
插件脚本每次调用新建解释器、跑完即弃，既没有定时器也没有跨调用状态（见
`docs/plugin-dev-guide.md`），所以「每隔几秒看一眼」「跟上一次比」「她躺了多久」只有常驻且
有 tick 的模组做得到。

改动顺序永远是 **宿主 → 插件 → 模组**：

- `PluginManifest` 带 `deny_unknown_fields`，插件 manifest 里写了宿主还不认识的新键，插件直接
  加载失败；
- 插件 `from plugin_host import ...` 有一个名字宿主没有，**整个插件的所有 handler 全部消失**
  （现象是桥接彻底不出声，日志里没有任何报错）。

**感知只走旁白入口。** 世界与她的状态变化一律由模组推事件、插件写成旁白交给
`add_prompt_line`。不要在玩家发言后面用括号追加「（她此刻：…）」之类的处境：玩家说的话原样
送进对话，「谁在说」必须始终只有玩家一个人，处境是旁白而不是玩家的补充。工具的查询回执
（`maid_look_around`）只回答当次问题，不算这条通道。

**旁白一律第三人称、直接叫名字**（`naming.py`，名字来自宿主 `current_names()`），不写
「你」「玩家」；「她」只在名字已经出现过的同句里作指代。提示只陈述事实，不写「注意什么」
「主动说一句」这类指令；要她开口就 `trigger_proactive("")`。

**动作接口不收绝对坐标。** 参数全部过白名单，端口只监听回环且没有鉴权；最坏只能让她动一动、
说一句话。挖掘的 `at` 是相对她脚下那一格的偏移，且要过认知校验。

## 系统结构

```
LingChat 宿主（Rust）
  └─ plugin_host 接口（台词表、玩家消息、主动开口、抓屏、TTS、ws_*）
       └─ mc_maid_bridge 插件（Python / RustPython）
            └─ WebSocket ws://127.0.0.1:48920
                 └─ 桥接模组（NeoForge，Java 21，服务端主线程）
                      └─ 车万女仆 / Minecraft
```

**模组侧**：

| 目录                                           | 管什么                                                                                                                            |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `perception/world`                             | 全局：维度、群系、天气、昼夜、血量；首帧 `state_snapshot`                                                                         |
| `perception/nearby`                            | 身边：视线、脚下、遮蔽、光照、主人远近、附近活物、载具、结构、姿势；差分与冷静期                                                  |
| `perception/spatial`                           | 地形快照、视线、30 秒记忆、危险方块；格子寻址的关系与成团投影                                                                     |
| `perception/query`                             | 按需快照 `maid_look_around`（关系、团、小图、背包、头饰）                                                                         |
| `action/core`                                  | 单槽位动作框架：去玩家/床边、坐、站、就地躺下、看向玩家                                                                           |
| `action/{attack,mine,task,give,headwear,feed}` | 战斗、挖掘、工作模式、交物品、头饰、喂食                                                                                          |
| `mixin`                                        | 长任务时拦住跟随传送；动作与冷却期间按住随机游荡；地上躺下/昏迷时挡住姿势重置；昏迷时挡住叫醒与非床吸附；躺姿碰撞箱与昏迷同步标记 |
| `bridge` / `maid`                              | WS 与消息路由、找女仆/主人与序列化                                                                                                |

**插件侧**：`hooks.py` 生命周期与事件落地；`bridge.py` 通道与配置；`naming.py` 称呼；
`wording.py` id/枚举/数字 → 中文；`events/` 一类事件一个模块（格式器 + `EventSpec`）；
`tools/` 一个工具一个模块，`tools/entry.py` 是 manifest 指向的入口；`tools/context.py` 共用
快照与旁白措辞。

**协议**：帧是 `{type, request_id, data}`。响应必须原样带回 `request_id`，推送事件**绝不**
带它——宿主按 `request_id` 认领响应，误带会让事件被当成某个请求的应答吞掉。帧里只给注册表
id 与枚举串，中文全在插件。老模组缺的新帧（`maid_look_around`、`maid_set_task`、`at`、
`ground` 目标）会被插件如实降级说明，不假装成功。

## 当前能力

- **对话**：游戏内聊天 ↔ LingChat；回话按「上屏」时机变成女仆气泡；连上 MC 自动切短回复。
- **语音**：TTS 改由女仆在游戏里的位置播放；她死亡或断线时回到本机播，复活后交回去。
- **感知**：全局一层、身边一层、危险一层；按需「看一眼周围」；认知口径是「此刻看见或 30 秒内
  看见过」，不透视。
- **事件旁白**：换群系/维度、天气、昼夜、血量告急、受伤、被雪球鸡蛋这类零伤害的投掷物砸中、
  死亡/复活、附近生物死亡、成就、主人远近/视线、敌人靠近、来了活物、遮蔽、光照、脚下、
  泡进液体里与埋头游泳、载具、结构、危险方块、姿势、捡到/收到/被拿走/被喂/自己吃了东西、
  主人拿出她最喜欢的食物、被抱起/放下、任务切换、动作收尾、放置收尾、追打没能打完。
- **动作**：走到玩家/床边、坐下、站起、就地躺下、找普通床或女仆床躺下睡着（躺床上歇着每
  10 秒回一滴血）、到主人前面探路；同一时刻只有一个动作。- **战斗**：按名字/类别/另一个玩家点名，可以一次点好几只（默认一只），排队一只一只打完；
  追打或轻打一下；不占用她的工作模式。打不了时说明原因：目标先被自己、玩家或别的生物
  打死，还是已经不在附近了。
- **挖掘**：按方块名、玩家准星方向或相对地址 `at`；数量、换工具、挖穿挡路方块、掉落进背包。
  整团拆（`whole`）按六面相连收同种方块，区域拆（`area`）按两个相对角收长方体，两者一次
  最多 64 块，收尾交代拆掉多少、还剩多少、卡在哪一格。
- **放置**：把背包里的一块方块放到主人准星指着的那一面，或一个相对地址的空格；朝向、台阶
  上下半与含水都按原版规则算，材料从她身上扣一块。
- **物品**：交给她、戴在头上、潜行右键喂食、捡起与背包差分（放了什么、被她拿走什么）；捡起时按
  掉落物身上的来源戳（玩家丢的 / 方块崩的 / 生物掉的）说来源，带碗的食物吃完剩下什么也一并交代。
  她自己用掉的（吃掉的那口、放方块用掉的那块）先记账，不会被说成主人从她身上拿走；比的位置
  含车万女仆吃饭时临时寄存手里物品的那一格，那顿饭的时间里她的东西不会凭空少一件。
  主人拿出她最喜欢的食物时，她像见到蛋糕一样凑过来讨（走车万女仆自己的讨食任务），并推一条紧急旁白。
- **工作模式**：切换车万女仆自己的任务，并如实说明日程/居家模式会不会让她此刻真去干活。
- **Carry On**：抱起/放下事件；被抱时她不在世界里，相关工具直接拒绝。
- **屏幕**：按需抓玩家游戏窗口给模型看（单独声明隐私能力）。

## 感知的做法

- **两档**：`auto`（周期采样、出事顺手带的）看得见 `max(noticeRadius, min(工作范围, 32))`、
  默认 12 格，看不见只听 6 格，最多 3 个活物；`query`（玩家明确问）看得见 32 格，附方块与
  背包清单。`perceptionEnabled` 管周期采样，`noticeEnabled` 管身边与物品，按需查询不受影响。
- **认知不是全知**：方块要此刻视线命中或 `TerrainMemory` 在半分钟内记过；只列露在外面的方块，
  竖直只从脚下往上。看不见的活物只在听觉半径内保留，说成「听到声音」。
- **活物记忆**：看见过的活物在 `CreatureMemory` 里留两分钟（最多 16 只），记着类型、类别、
  最后的位置与距离；她身边死掉的就补上死在谁手里。追打落空、玩家问「刚才那只呢」都查它；
  一条记忆被用来解释一次「打不了」之后就删掉，下次看见再记——记忆说的是过去感知过什么，
  不是一份永远正确的世界账本。
- **危险**：8 格内露在外面、视线真落到的岩浆/火/灵魂火/岩浆块/细雪，每种只报最近一处，
  只在**新进入视野**时报；离开又回来有 1 分钟冷静期。脚下那一列交给 `ground_change`。
- **头顶**：三档——露天；半遮（树荫、屋檐、洞口：四格内还有一列看得见天）；屋内（房间、
  洞穴：这一圈一列露天都没有，中间隔着墙的列不算）。带上头顶第一块挡路方块的 id 与距离
  档位（压得低 / 很高，不报格数）；三档都算变化，沿用一分钟冷静期。
- **姿势**：`posture` 取 `standing` / `sitting` / `sleeping` / `lying` / `unconscious`，
  由一处判定；首帧带上，之后变化推 `posture_change`。昏迷优先于睡姿，避免被说成「睡着了」。
- **差分与频率**：连续量要连续两次采样一致才认；环境类（脚下、泡进液体、遮蔽、光线、群系、
  进出结构）一分钟最多报一次，它们变得比旁白能说的还快，踩到火上不受这条限制；姿势、上下载具
  这类离散量变了就报。首帧只建基线，重连不喷一屏变化。
- **排队**：事件带 TTL、合并键与严重度交给宿主；同类只留最后一次/最重的一次。紧急的当场请她
  开口，其余攒够 `proactive_after_events`（默认 3）条且这期间没人说话才开口。同一批事件按
  **危险 > 与主人相关 > 新奇**排序后推送。

## 动作的做法

- **单槽位**：新动作顶掉旧动作，被顶掉的那次仍推一条 `cancelled` 的 `action_done`，否则插件
  永远等一个不来的收尾。攻击、挖掘、换工作模式与动作互斥，都会先互相收掉。
- **走路**：每 tick 往 brain 写 `WALK_TARGET`，由原版寻路驱动；受理时只清一次 `PATH`。计时用
  游戏 tick，Esc 暂停不计。卡住、走不到、目标消失、超时都如实收尾。
- **躺下与睡觉**：躺姿一律「睡位 + `Pose.SLEEPING`」两件一起按，和昏迷走同一套——YSM 的
  闭眼与躺姿、车万女仆的「别乱走」都只认 `isSleeping()`，光设姿势在游戏里等于没躺下。
  `ground` 就地按一个脚下的睡位；`bed` 先在 POI 里找最近的空床（普通床与女仆床都认），走到
  床头再摆上去。**床上的睡位一定压在床头那一格**：车万女仆每 tick 把人吸到睡位中心，渲染又
  按睡位那格床的朝向把身子往床尾铺开一格半，睡位落在床尾就会整体错出去一格；所以床尾要顺着
  `FACING` 翻到床头，人不在床头那格就摆回床头中心，`onMaidSleep` 的放行也按床头比。床上不调
  `startSleeping`：它会回满血、涨好感，一句「躺下」就刷满太便宜了；改成躺着休息慢慢回血，
  每 10 秒一滴，地上的躺姿不回。
  睡着期间原版「睡位不是床就起来」与车万女仆「日程不在睡觉时段就叫醒」由
  `LivingEntityStopSleepingMixin` 拦掉，先清动作槽再叫醒，自己人不会被拦。躺下之后不再收尾：
  挨打、泡进液体、身下没地、被抱走、床没了或主人让她做别的事时才起来并推 `action_done`
  （`reason_code` 写原因）。车万女仆的游泳管理器每 tick 会把不在水里的姿势改回站立，躺下
  期间仍用 `EntityMaidPoseMixin` 挡住 `updateSwimming`。地上的躺姿抬离方块 0.2 格，避免 YSM
  模型陷进地里；躺姿碰撞箱由 `LivingEntityLyingDimensionsMixin` 放宽到 0.9 宽、0.4 高，
  右键与搬运不必再对着脚（真在床上睡觉仍用原版尺寸）。
- **探路与游荡冷却**：探路是持续动作，落点按主人朝向取正前方约 8 格、站得下的那一格，
  逐格往回试并跳过水面与岩浆，新落点跟原来差不到 2 格就不换，免得主人晃视角时她打转；
  主人走动、转身就跟着换点。结束只有两种：被新指令顶掉，或她自己撑不住（血不足四分之一、
  被抱走、动不了、主人离开或走散到 24 格），后几种推 `action_done` 并写明原因。这段时间
  与动作收尾后的十秒里，`MaidRunOne`（四处看看 + 随机走动）的启动被 `WanderGuard` 挡掉，
  插件在每轮最后一句上屏时发 `maid_settle` 提前放开，主人走远需要跟随也立刻放开。
- **昏迷**：致命普通伤害在死亡判定前把血拉回 1 点，进入 `unconscious`；普通伤害在昏迷期间
  取消，只有 `/kill` 与掉虚空仍走旧死亡。闭眼靠写入睡眠位置（不调用会回满血的 `startSleeping`），
  并拦掉原版与车万女仆的叫醒；非床睡位跳过 `onMaidSleep` 的吸附。被搬运模组抱在手里时姿势
  交还给站立，睡位只负责闭眼，YSM 的 `is_sleep` 看姿势、`is_close_eyes` 看 `isSleeping()`，
  所以公主抱动画能正常播放而眼睛仍是闭着的；头部每 tick 对齐身体朝向。普通床或女仆床连续躺
  1200 tick 后醒来，离床重置，醒来 1 点血；状态与进度存实体持久化 NBT。昏迷期间动作、攻击、
  挖掘、换任务、交东西、戴头饰与「看一眼周围」都拒绝，自发感知暂停，只保留被抱/放下、上床、
  醒来、真死、主人死与玩家喂食。
- **追打**：一次可以点好几只（默认一只），按最近的顺序排队一只一只打，每只最多追 30 秒。
  目标不见了就查活物记忆：被自己打死的算打完（死亡旁白会交代），被玩家或别的生物先打死的、
  已经走了的、以及她被抱起来时推 `attack_failed` 并写明原因，剩下的目标继续打。
- **挖掘**：先挑目标与落脚点，走到才动手；目标埋在别的方块后面时从眼睛打射线、挖穿挡路块
  （最多 24 块）；水、岩浆、受保护方块不碰；工具不对或背包里没有就当场拒绝。指错格子时回执
  带「那一格实际是什么」与她看见过的最近同类地址，模型据此改计划。`whole` 从种子按六面
  相连收同种方块，`area` 收长方体（每条边最多 16 格）；两者都按离她远近取前 64 块，收尾的
  `maid_mine_done` 用 `remaining` 与 `stuck_at` 说清还剩多少、卡在哪。
- **失败要给改计划的料**：结构化 `scene`（方位、上方遮挡、站不下）、`nearest`、缺失的工具，
  而不是一句「做不到」。
- **放置**：先找能贴着的面（玩家指的那一面优先，其次脚下、她站的那侧），再走到够得着的落脚点，
  用原版 `BlockPlaceContext` 放下去（借一个只算朝向的假玩家），材料从她身上扣一块。目标被占、
  悬空、有人站着、材料没了、走不到都推 `maid_place_done` 说原因。一次只放一块；蓝图是下一期。

## 已知边界

- **地上躺下与昏迷的表现**：1.21.1 的睡姿方向取 `getBedOrientation()`，没有睡觉位置时返回
  `UP`、不会退回 yaw，所以地上的躺姿永远朝同一个绝对方位；这一项要碰客户端渲染才能改。
  碰撞箱已放宽到 0.9 宽、0.4 高、地上躺姿抬高 0.2 格，右键与搬运不再只对着脚。被抱着的公主抱姿势
  由 YSM 的 `is_passenger` 动画与 Better Carryon Maid 决定；没装后者时 Carry On 会把她从
  世界里摘走，抱着的这段时间没有实体姿势可看。闭眼依赖模型把眼皮绑到 `is_close_eyes`。
- **插件无状态、无时钟**：跨调用的一切（采样间隔、冷静期、任务进度）只能在模组；插件最多从
  台词表读回历史。插件 handler 并发上限 4，占满时新帧静默丢弃（日志有 warn）。
- **回环端口无鉴权**：任何本地进程都能连上来让她说话、做白名单里的动作；没有执行指令的能力。
- **单人按 Esc 暂停**：模组 tick 停摆，采样与请求响应一起迟到；动作计时暂停期间不计。
- **感知的边界**：不做逐格新奇广播，不单独判「主人站在崖边」；视线是无遮挡判定、不要求面朝；
  记忆只有 30 秒（方块）与两分钟（活物），快照之外的东西一律不知道；活物记忆被查询用掉、
  过期或挤出上限之后就没了，下一只同名目标不会继承上一条的解释。女仆离开已加载区块时查不到，
  回来后全局层重推 `state_snapshot`。
- **讨食的边界**：食物清单是软件里插件配置的一部分（`favorite_food`），连上时与玩家每次
  开口前发给模组。模组只把它接进车万女仆自己的诱惑物，所以条件与原版蛋糕一致——主人拿在
  主手上、她看得见且六格以内才讨，干活、打架、睡着时不讨；带负面效果的食物（毒马铃薯、
  河豚这类）填了也不算。旁白只在她真的讨起来时推。
- **探路的边界**：只按主人此刻的朝向取点，不查视线与来路，带进死胡同、带到崖下都有可能；
  站不下人的格子直接跳过，一路都是墙时退回跟住主人。居家模式只在她自己的活动范围里找点。
- **首帧只建基线**：换监控对象、重连、重新加载区块都不把当前状态当成「变化」再报一遍。
- **动作冲突**：跟随与工作模式都会写寻路目标；她有活且主人超出原版回头线时，mixin 让跟随
  行为让路（**不改活动半径**）。玩家开着女仆 GUI 时也可能抢目标，最后按 `unreachable` /
  `timeout` 如实认输。
- **挖掘范围**：只挖够得着或挖得穿的方块，不为了追一块矿无限开隧道；掉落进背包，装不下才掉地上。
  整团/区域拆除一次最多 64 块、每条边最多 16 格；被挡住或打断就停下，剩余与卡住的格子由收尾
  事件交代，不会自己接着拆。
- **工作模式**受她自己的日程与居家设置限制：切成功只是换了任务，不等于此刻已开工；插件不替
  玩家改日程与活动范围。
- **Carry On 抱着时**她不在世界里：气泡、动作、查询都用不了，放下后照常重推现状；控制器不会
  为了叫她起来而把她从手上拽下来。
- **进入 MC 的提示行按内容幂等**：写法变了会在下次连接补写一条，老那条留在历史里。
- **连接刚建立时别问「连上了吗」**：宿主登记可能还没落定，`ws_status` 会说没连上；绑定直接
  问女仆是谁，每次上屏时再幂等重申。
- **工具只在主聊天可用**：主动对话与剧本拿不到工具；按需「看一眼」只在玩家跟她说话那一轮用得上。
- **模组 jar 要手动拷**：改模组后必须关游戏、拷 `extension/maid_mod/build/libs/*.jar` 到 mods；
  只改插件则重启 LingChat 即可。没拷 jar 时旧功能照常、新功能彻底静默。
