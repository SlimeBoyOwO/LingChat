一格的进度：搁置与补试只有一轮

顶层只有四个相位，RETRY_ROUND 动的是每一格自己的进度。hold 只记原因；真正改状态的是这条链， 全部迁移都经 CellFlow 一个入口。颜色：蓝＝候选，橙＝搁置，紫＝补试中，绿＝完成，红＝失败。

hold 不改状态 放置失败、到站看不见、够不着这类「这一遍先放着」只记原因和 attempted，不迁移状态； 所以它不会把格子从待做推到失败，也不会打断这一遍的进展计数。
搁置不是定论 搁置可以走补试，也可以直接收账；完成与失败才是定论，之后只有完成还能再进。 拿「开格」当迁移判据会漏掉搁置转补试，补试轮就会一格都放不回来。
补试会清记忆 进入补试中时清空这一格的 triedStands、unreachable、steps、bridges、drops、hopUntil、 waits、propped、navFails：周围已经变样，上一轮的尝试全部作废。
收账才进失败清单 失败时按原因计数，缺料单独计入 missing；从没真正试过的格子记 incomplete， 不拿默认的「没站位」顶数。

一层扫完的去向：endPass 的决策

BuildRules.endPass 是纯函数，只看这一遍数好的账，从上到下命中即止。BuildLayer.applyEnd 按返回的顺序执行动作，遇到 FINISH 就收工，其余情况冷却 2 tick 回扫描。 橙色的两个叶子就是 RETRY_ROUND 的全部入口。

闭环与有界性：哪些会绕回来，靠什么停下
闭环怎么绕退出条件有界性
重扫 SCAN → endPass(RESCAN) → 冷却 2 tick → SCAN 连续 3 遍没有新进展（放方块或垫脚都算）；有进展、或本层剩格全在等活物时重新计数 stallPasses 到 3 就转搁置；等活物最多暂停计数 200 tick（10 秒）
搁置与换层 3 遍没进展 → DEFER_LAYER（本层开格全部转搁置）→ 有下一层就 NEXT_LAYER，没有就 RETRY_ROUND 图纸所有层都过完 每层最多搁置一次；补试过之后同样的停顿改为 SETTLE_LAYER 直接收账
补试轮 RETRY_ROUND → 所有搁置格转补试中，清空这一格的站位、垫脚、跑跳记忆 → 从第一个开格所在层重新扫 补试中的格子再放弃直接记失败，不会再搁一次 每格最多补一次。补试轮之后仍可能因「换满 4 个站位」产生新的搁置，从而再触发一次 RETRY_ROUND（retried 只影响口 B，不挡口 A）
总闸 每个 tick 累加 run.ticks 超过 48000 tick（约 40 分钟）强制收尾 硬上限。所有闭环最终都被它截断；调试栏表现为心跳一直涨、进度不动
retried 是整次施工共用的 只在 retryRound 真正补过一格时置真，且换层不重置。它决定「3 遍没进展之后是搁置还是直接收账」， 不决定「本层无开格时还能不能补试」。
怎么读调试栏 停 层：RETRY_ROUND×N 是最后一次 endPass 的出口；停遍 是连续没进展遍数； ·已补 表示 retried；全 待/补/败/搁置 是全图计数。补试轮如果在跑， 「补」应该从 0 涨起来；「补」一直是 0 而 RETRY_ROUND 反复出现，就是搁置格没能转进补试。
补试轮的已知坑（2026-11-24 已修） 迁移守卫曾把搁置当成「已有定论」，拒绝搁置 → 补试中；补试轮因此每遍都空转， 只置 retried 而不改任何一格，最后一路耗到总超时。现在允许的迁移单独成一条规则并有单测。

读图：圆是状态，箭头是迁移，箭头上的字是迁移条件。虚线框里是寻路模块的内部状态——规划挑一种手段， 执行到这条腿结束；它对外只报两个结果。放置本身仍在扫描相位里完成，到站之后只是再试一次。 虚线框里的细节见 寻路状态机与手段。
