女仆寻路：状态机与手段

NeoForge 1.21.1 · lingchat_maid_bridge 0.1.0 · 调用方只给目标和边界，走法由寻路自己挑

进入 每个 tick 都从这里走一遍 检查 终态、超时、歇脚、是否已到位 规划 按代价挑一条腿 赶路 执行一条腿 到站 走不通 带原因回调用方 正常迁移 判死

一、外层状态机

一次目标开一个小状态机：没有腿在跑就规划，选中一条腿就跑到底。终态只有两个：到站、走不通。

入口先算三件事 已经到站或走不通就直接返回；离目标连续 45 秒没再靠近，才报超时；起跳后的歇脚还没数完，本 tick 不动。终点判定比规划更早——站在能动手的位置、又不在目标格里，才算到。
一条腿跨很多 tick 进入时 enter 一次，之后每 tick 推进，结束（成或败）时 exit 一次。垫脚接走路这类连招会在腿结束时当场接上下一条，不等到下一 tick。
单条腿失败不算走不通 记下这次的站位，整条路线作废重算。腿失败计数只在成功时清零；连续失败超过 5 条，或图上再也搜不出路线，才判死。

二、规划：落脚点图上的搜索

手段不再是按顺序试的兜底，而是图上的边。搜索把走、跳下、跑跳、搭一格、垫一格按代价组合成路线，搜不到才算走不通。

原版寻路不再一票否决 以前先问原版「走不走得到」，算不出路径的站位直接出局；原版不会跳坑、不会垫、不开门，很多能到的位置就这样被筛掉了。现在它只是最便宜的一条边。
高目标先上高度 目标比她高时，垫脚与原地起跳才是边；沿外墙绕一圈上去（螺旋上升）由这些边自己组合，不需要单独写一条腿。
世界边算边改 搭路、垫脚会改世界，所以路线一段一段执行，哪一段没走通就丢掉重算；图上算出来的支撑，执行时一定先放下去再走。

三、跑跳的几何

一格按一跳算：先按玩家手感验几何，再用自己的弧线摆位置，不靠冲量。图上的距离是格数，不是像素。

跑跳的三道否决：任何一条不成立就改走路或垫方块
检查不通过的典型地形为什么
飞行包络全空半空有树叶、栅栏、屋檐摆位置会把她塞进方块里
落点是整格面台阶、半砖、栅栏顶顶面高度对不上，落地会卡在碰撞盒
断口下三格安全岩浆、火、仙人掌、细雪半路被打断就救不回来，宁可多垫一块

四、五种手段的判据

每一种手段都是一类边：先决条件成立才连，代价决定搜索先试谁。能走就不跳，能跳就不动方块。

边的判据与代价
边代价什么时候连得上
走每格 1，斜角 1.41目标格站得住；抬高一步要头顶让得开；斜着走要求两边都站得住，不穿墙角
跳下3这个方向走不过去；落点站得住又是整格面；下落 4～10 格；飞行包络全空
跑跳4同上，跨度 2～4 格、最多抬高 1 格；中间必须有断口，断口下三格不能是岩浆、火这类
搭一格7，耗 1 块前方同高、脚下悬空；脚下那格能放、够得着又看得见；不占图纸格
垫一格7 或 11，耗 1～2 块旁边一格空着、头顶让出三格；目标不比自己低；站上去身体不压目标格；没依托就先补托底（+4）
原地起跳8，耗 1 块目标在正上方；脚下实心、头顶让出两格；站上新高度后身体不压目标格
目标站不住也能算 垫脚和搭路落脚的格子现在还可能是空气：搜索认为「这一步自己铺出了脚下的方块」，就算站得住。执行时先把方块放下去，再走上去。
记忆会挡路 试过站不上去的格子、放不成功的垫脚位都记在这个目标名下，搜索不再连它们；补试轮开始时全部清空。
改了世界就要重新对账 搭路和垫脚用她站到格心后的理想眼睛验一遍，真放的时候再用实际眼睛验；放不下就记下这块位置，换一条路。

失败原因：寻路只报这五种，翻译成格子账由调用方做
寻路报的调用方记的什么时候出现
NO_STANDNO_STAND图上搜不出能动手的站位（现成的站不住，也垫不出来）
NO_PATHNO_PATH路线里的某一段没走通，反复失败到上限
NO_HEADROOMNO_HEADROOM她待的地方头顶太低，跳不起来也垫不上去
OUT_OF_REACHOUT_OF_REACH站到了，但够不着目标

收尾是另一种目标 收工不走上面的手段阶梯。她不在垫脚块上就直接拆净；在垫脚块上就先找最近的一格实地走过去；实在没有落脚点，等 30 tick 连脚下一起拆，让她落回地面。
记忆按目标分开存 试过的站位、放不下的垫脚位、垫了几次、铺了几块、跳了几次，都由调用方按自己的粒度持有。建筑按格子存，换一格就从干净的记忆开始。
垫脚账本只记位置 谁放的、为什么放不记。赶路时护着，走开后拆掉，收工或被打断时拆净；生存模式下拆下来的方块还回她背包，塞不下就掉在脚边。

读图：第一张是状态机——圆是状态，箭头上的字是迁移条件；第二张是规划：一次图搜索算出整条路线，再一段一段执行； 第三张是跑跳的几何，距离按格算。手段的先后不再由代码顺序决定，而是由代价决定：走最便宜，动方块最贵。
