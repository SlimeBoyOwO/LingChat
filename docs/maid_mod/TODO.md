## 扩展方向：自己拆与自己建（未排期）

现在的感知是「按需查询 + 30 秒记忆」的感官，不是规划器。要走到 numen 那种「她自己拆、自己建」，缺的不是感知分辨率，而是**放置原语、计划状态与蓝图**。按下面顺序做，每一期都能单独验收。

- [ ] **一期：区域拆除（模组 + 插件）**
  - 做：给 `maid_mine` 加区域目标（长方体或按相连团选出的集合），复用现有挖掘控制器逐块推进，掉落照旧进背包。
  - 验收：玩家说「把这堵墙拆了」，她按合理顺序拆完；拆到一半被挡住时回执说明剩下多少、卡在哪。
  - 为什么先做它：破坏原语、格子寻址、相连团与失败现场都是现成的，只是把「一块 / 一种方块若干块」扩成「一个集合」。

- [ ] **二期：单格放置工具（模组 + 插件）**
  - 做：新增放置工具，参数是格子地址加方块 id；模组校验目标格是否为空、有没有支撑、会不会压到人或动物、朝向与材料够不够，失败给结构化原因（照 `maid_mine_result` 的 `scene` / reason 那一套）。
  - 验收：指哪放哪；材料不够、悬空、被占用时模型能改计划。
  - 边界：只在她活动范围内、只放不放拆；材料必须来自她背包或玩家给的，不凭空生成。

- [ ] **三期：小蓝图（模组 + 插件）**
  - 做：模组持有蓝图与进度（要建什么、放到第几块、哪块失败、下一步），插件只把玩家意图翻成蓝图；先限制在 9×9×9 以内，蓝图来源可以是玩家给的结构文件，或模型给一个很小的形状描述（墙 / 地板 / 坡屋顶）。
  - 验收：能按蓝图盖一个凉亭；中途缺材料时说缺什么、停在哪一步；重启游戏后进度不丢（或明确作废）。
  - 前置：二期。计划状态必须放常驻的模组侧——插件没有跨调用状态。

- [ ] **四期：自主（模组 + 插件）**
  - 做：常驻任务槽 + 定时推进 + 完成 / 失败事件，让她在工作模式或空闲时自己接着往下干，而不是一次指令只做一件事。
  - 验收：给她一个目标后走开，回来能看到进度与结果；被打断（战斗、跟随、死亡）后能恢复或如实说明。
  - 前置：三期。到这一步才谈得上「她自己找活干」。

明确不做：为建造单独做完整 A*、稠密体素与跨区块地图——瓶颈在放置与计划，不在寻路精度；真要做大建筑再评估。
