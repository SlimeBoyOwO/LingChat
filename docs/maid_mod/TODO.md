- [x] **施工器：决策表第一动作 RETRY_ROUND 没人执行（2026-11-24 已修）**
  - 真机现场（2026-11-23）：她卡在绿色落脚点里不动，状态栏原文——`阶段：扫描下一格`、

    1 格还是待做、0 格失败。`停 层：RETRY_ROUND/NONE×1` 说明最后一次 `endPass` 给出的去向是
    「第一动作 RETRY_ROUND、第二动作 NONE」。
  - 根因：`BuildRules.endPass` 在「本层没有开格、没有下一层、还有搁置格可补试」时返回
    `new PassEnd(Action.RETRY_ROUND, Action.NONE)`，但 `BuildLayer.applyEnd` 的第一段 switch
    只处理 DEFER_LAYER / SETTLE_LAYER / RESCAN / NEXT_LAYER / FINISH，没有 RETRY_ROUND；
    第二段 switch 才会执行 RETRY_ROUND。于是这个去向被整个吞掉：只设了 2 tick 冷却，
    下一轮又得到同一个决定，形成无动作闭环。这和之前 NEXT_LAYER 只写在第二段 switch 里
    是同一类错误——决策表给的动作，执行侧必须两个槽位都能接。

    所以修复后不仅是搁置的 37 格，待做的那 1 格也会一起进入补试。
  - 修法（已落地）：`PassEnd` 从两个固定槽位改成有序的 `List<Action>`；`applyEnd` 改成
    「按顺序执行、收工即停」的一段循环，动作由 `perform` 的 switch 表达式分发，`default`
    全部删掉——以后往 `Action` 里加动作，执行侧不实现就编译不过，同类漏接不可能再静默通过。
    `RETRY_ROUND` 作为第一动作现在会真正执行。
