# 功能 Agent（好感度 / 选人）

上帝 Agent 的无头决策分支：输入一次任务、输出一次结果，不持有会话。两个分支都住在
`ai_service/god_agent/capabilities/`，共用中枢 `GodAgentCore`，副作用由
`ai_service/tools/builtin/god_agent.rs` 里的真实工具落地。

## 共同底座

- **中枢**：`GodAgentCore` 持有 LLM 槽位（运行时热切换）、配置（`RwLock` 热更新）、专用工具注册表。注册表与聊天工具隔离，不进工具权限页——这两个能力由上帝 Agent 自己的 LLM 驱动，没有用户侧权限矩阵语义。
- **任务抽象**：一次决策 = `AgentTask { system_prompt, payload, tool_names, max_rounds }`，由 `tools::agent::run_tool_agent` 无头运行：不流式、不呈现、不翻译、不写台词表。system 只放任务说明与判断原则，数据载荷放 user——只发单条 system 时 Codex（Responses API）会出现空 input 被 400 拒绝。
- **LLM 解析**：上帝 Agent 专用 provider → 角色分配的 `god_agent_provider_id` → 聊天主 provider → 第一个可用 provider；都没有则整个上帝 Agent（含导演、选人、好感度）停用。
- **感知来源**：`GameStatus`（在场角色、当前发言者、场景、好感度全局变量）+ 台词表 `line_list` + 角色设置与关系数据。台词取样统一走 `tail_lines`，跳过硬编码的系统行与空正文载体行，取最近 `recent_window` 条（默认 20，最小 5）。
- **激活判定**：`should_activate` = 自由对话（`script_status` 为空）且在场角色 > 1（玩家 + 至少一个 NPC）。剧本模式不参与。
- **配置热更新**：`save_settings` 保存上帝 Agent / 好感度相关设置后立即生效，无需重启。

两边的共同取舍：**不落任何会话或快照**。每次调用现取现场，跑完即弃；结果只以工具副作用（切发言者、改好感度）留在存档里。

## 选人 Agent

### 职责

在多人自由对话中决定下一位发言者：某个 NPC 的 `role_id`，或 `0` 表示交还玩家。它只回答「谁来说」，不管「说什么」，也不加载角色、不重建在场集。

### 上下文存储构成

无持久层。每次调用现装配一份 `SpeakerView`：

- 每位在场已加载 NPC：`role_id`、展示名、副标题、简介、该角色对玩家的私下称呼、玩家对 ta 的认知、ta 对玩家的关系认知、玩家对 ta 的好感档位；
- 角色之间的关系认知（两两解析，说话者侧优先、对方侧回退，两边都没写就跳过，并标注是否来自对方自述）；
- 玩家身份名（旁白与系统提示里的公共名）；
- 最近 `recent_window` 条台词；
- 当前发言者及其展示名。

system 里写明分配优先级：玩家点名或称呼了谁 > 谁的关系与情感使 ta 最有接话动机 > 话题内容（只决定接话之后说什么，不决定由谁说）。

### 生命周期

完全无状态，一次调用一条命：取快照 → `run_task` → 解读工具结果。`max_rounds = 1`，选完即止，结果不回填给 LLM。工具未调用、调用失败、结果解析失败都会向上报错，该轮生成失败——宁可让玩家重试，也不猜一个发言者。

单 NPC 时直接返回该角色，不调 LLM。

### 调用时刻

- **发言前**（`generator/pre.rs`）：玩家发出消息后、构建角色上下文之前，决定谁先回应；选到 0 则保持当前发言者。
- **发言后**（`generator/post.rs`）：每轮 NPC 回复落地后判断是否继续。先查连续 NPC 轮数预算（`max_consecutive_npc`，默认 3），到顶直接交还玩家；再看激活条件与快照，最后问 LLM。

发言权的实际切换发生在 `select_next_speaker` 工具内部（再取一次 `GameStatus` 锁），所以视图必须在锁内取完并释放后再调 LLM，否则自死锁。

## 好感度 Agent

### 职责

定期阅读最近对话，评估它对在场角色情感状态的影响，按角色调用 `update_affection` 工具落地：六维好感（好感 / 信赖 / 亲密 / 默契 / 兴趣 / 思念）与六维负面情绪（愤怒 / 受伤 / 失望 / 冷漠 / 嫉妒 / 疏远）。评估原则写在 prompt 里：日常互动 ±1~2，明显打动或冒犯 ±3，严重伤害 ±4~5，没有受影响的维度不调，保守为主。

### 上下文存储构成

无持久层，但**结果**落在存档里：`global_variables` 的 `affection.{role_id}.{player_role_id}`（旧档回落 `affection.{role_id}`），随存档保存，读旧档即回到当时的感情状态。`total` 是六维平均的派生值，手改无效。

每次评估现装配：

- 每位在场已加载 NPC：展示信息、当前好感六维与负面六维数值、对玩家的关系认知；
- 最近 `recent_window` 条台词。

### 生命周期

后台一次性任务，`spawn` 出去后不影响已呈现给玩家的回复：

1. 判定触发并推进游标 `affection_eval_cursor`——先推进再评估，失败也不会形成重试风暴；
2. 锁内取 `NpcAffectionView` 与台词快照，锁外调 LLM；
3. 工具落地：改 `GameStatus` 全局变量、落存档、向前端广播 `affection_changed`、返回一条旁白文本；
4. 旁白进近期记忆队列，锚定到本轮玩家行所在的那一块，等生成锁空闲后写进台词表。

失败只记日志；工具返回「角色不在场」这类跳过不算失败。好感度**不再逐轮注入**角色上下文——变化以旁白台词的形式出现在历史里。

### 调用时刻

一轮生成循环全部结束后（`maybe_evaluate_affection`），同时满足：

- 好感度总开关开启（高级设置，可热更新）；
- 当前不是剧本模式；
- 台词表里真实对话条数累计达到 `affection_eval_interval`（默认 25 段，不含工具行与临时行）；
- 在场至少一个已加载 NPC。

## 边界与已知限制

- 剧本模式两个分支都不参与：选人被激活条件挡在门外，好感度显式跳过（剧本事件接口另行扩展）。
- 选人的决策质量完全取决于关系数据与好感档位；台词表面措辞不参与归属判断。
- 好感度评估是异步的，本轮回复不会瞬时反映刚刚的调整，要等旁白写进历史后的下一轮。
