# 导演 Agent

上帝 Agent 的交互会话分支：持有会话、落库、流式推事件。代码在
`ai_service/god_agent/director/`，命令层 `api/director.rs`，前端侧栏在
`src/components/director/`。与选人、好感度不同，它由玩家直接对话驱动，不是后台决策。

## 职责

玩家在主聊天页右侧侧栏里直接和导演沟通剧情走向。导演站在舞台之外观察现场，能读到当前场景、在场角色与最近台词，但**不代替角色说话，也不替玩家做决定**。

本期只做「对话通道 + 现场感知」：工具集为空，剧本事件工具（插旁白、切场景、换角色、动舞台）留给步骤二，工具事件与消息字段已预留。

## 上下文存储构成

两层：

**持久层（导演的记忆）**

- 复用通用 Agent 会话表：`agent_conversation`（`kind = 'director'`、`save_id`）与 `agent_message`（role / content / reasoning / tool_calls / tool_call_id / usage）；
- 一档一条导演线，取该存档最新的一条；首次发言才建行，不建空会话；
- 有存档时逐条落库，读档、切档后从库重新载入；自由对话（无存档）只在内存，重启即失；
- 历史即记忆：MVP 不设独立记忆字段，也不做摘要压缩。

**临时层（现场）**

每轮按当前 `GameStatus` 现算的 system，不落库。四段：

| 分段     | 内容                                                                                      | 上限                          |
| -------- | ----------------------------------------------------------------------------------------- | ----------------------------- |
| 导演人设 | 写死在代码里的固定身份描述                                                                | 计入总限                      |
| 当前现场 | 模式（自由对话 / 剧本名）、时间、场景、背景、音乐、氛围、天气、当前发言者                 | 计入总限                      |
| 在场角色 | 玩家身份 + 至多 12 位在场角色（名字、副标题、是否在舞台、简介截断）                       | 简介 200 字符                 |
| 最近对话 | `tail_lines` 取 `recent_window` 条，按角色标注 `[role_id] 名字(情绪): 内容`，旁白单独标注 | 单条 240 字符、整段 6000 字符 |

system 总长 10000 字符；历史预算 12000 字符，超出时从最旧的**整块**开始丢（一块 = 单条消息，或 assistant 的 `tool_calls` 加其全部 `tool` 结果），绝不拆开工具配对。装配前先清洗孤立 tool 消息。被裁多少条记进上下文快照的统计，供「查看记忆」展示。

另有一份内存快照 `last_context`：上次真正发给 LLM 的那份上下文，供「查看记忆」默认展示；「重新装配」按当前世界状态重算一份，标 `rebuilt`，不覆盖上次请求的那份。重启即失。

## 生命周期

- **实例**：`GodAgentCore` 持有 `director: DirectorAgent`，构造时用同一个 `LlmSlot` 克隆，LLM 热切换自动生效。中枢只存字段、转发命令，会话细节不外溢。
- **会话状态**：`DirectorSession { save_id, conversation_id, messages, last_context, running, cancel, task }`，封在 `Mutex` 里。
- **存档懒同步**：每条命令入口比较会话的 `save_id` 与当前 `GameStatus.active_save_id`，只在命令入口做，不侵入读档路径：

| 变化        | 行为                                                                     |
| ----------- | ------------------------------------------------------------------------ |
| 无档 → 有档 | 把内存里已聊的消息收编进该档的导演会话（自动存档会这样绑定，是常态路径） |
| 档 A → 档 B | 从 B 的导演会话重新载入消息                                              |
| 有档 → 无档 | 清空内存消息，自由对话重新开始                                           |

- **一次一轮**：`running` 互斥，生成中再发消息直接报「请稍候」。停止用 `CancellationToken` 在 chunk 之间中断，不用 abort 硬杀；`JoinHandle` 只用于观测与善后。
- **收尾**：正常结束、停止、出错都把已产出的正文落库并写回会话——已经流给玩家看的内容不会凭空消失。生成期间切了档，消息写进旧档，内存里只保留新档的线。

## 调用时刻

前端通过六个命令驱动（全部前端主动触发，没有后台定时）：

| 命令                        | 时机                           | 行为                                                                          |
| --------------------------- | ------------------------------ | ----------------------------------------------------------------------------- |
| `director_get_state`        | 打开侧栏、切档后、设置面板关闭 | 懒同步存档，返回可用性、是否绑档、运行中、消息列表                            |
| `director_start_chat`       | 玩家发送一句                   | 同步存档 → 落库 user 消息 → 装配 system → 拼历史 → 流式运行，事件走 `Channel` |
| `director_stop_chat`        | 点停止                         | 触发取消令牌，等本轮落库后返回                                                |
| `director_clear`            | 清空对话                       | 删该档导演会话的消息，清内存                                                  |
| `director_get_context`      | 切到「查看记忆」/ 点重新装配   | 返回上次请求的快照；`rebuild=true` 时按当前现场重算                           |
| `director_get_tool_history` | 切到「工具调用」               | 带 `tool_calls` 的 assistant 消息与 `tool` 结果消息                           |

事件类型：`status`、`message_delta`、`reasoning`、`tool_call`、`tool_result`、`done`、`error`。工具两类本期不发，协议先留着。

前端侧：侧栏只挂在主聊天页，关闭态是贴右边缘的竖向把手，展开态是贴右边缘、只有左侧圆角的抽屉；宽度可拖（默认 420 / 最小 320 / 最大 min(720, 55vw)），窄屏铺满。设置面板打开时自动收起（读档、开新档都在设置里），关闭后重新拉一次状态。store 只持久化开合、宽度、当前 tab，消息与快照都是运行时状态。

## 与剧本事件工具的关系（步骤二）
