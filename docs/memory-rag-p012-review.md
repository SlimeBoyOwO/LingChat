## 1. 修复前复现的缺口

以下 R1–R5 是审查编号，与构建计划的 P0–P7 阶段编号不同。

### R1：语音回填使事实未变化的来源失效

位置：`crates/ling-chat-main/src/ai_service/game_system/memory_scope.rs:231`；历史版本也在同文件 `history_version_for` 使用完整 `GameLine`。

来源指纹序列化整个 `GameLine`，因此音频路径、TTS、情绪预测和隐藏思考等字段也参与事实版本。应用已有回填 `audio_file` 并同步数据库的路径；即使正文、动作、工具请求和感知范围都没变化，也会改变来源版本，拒绝旧文档、重新生成原文向量。未来已生成的日记也会因此整体失效。

复现：从有效台词 1 建立一份带当前来源版本的日记，确认可用；只执行 `UPDATE line SET audio_file='voice-backfill.wav' WHERE id=1`，重新加载范围后，同一日记被拒绝。

建议：独立定义记忆使用的来源投影，保留台词身份、说话人、正文、动作、工具协议、影响权限的感知信息等字段。音频资源与内部推理状态不应改变事实来源版本。继续保证正文修改、感知变化和有效历史链变化能够失效；调整指纹格式版本后重建派生索引。

验收补充：音频／TTS／预测情绪回填保持记忆有效、避免重新嵌入；正文／动作／工具请求／可见性变化仍使相应来源失效。

### R2：方括号开头的普通助手台词被误删

位置：`crates/ling-chat-main/src/ai_service/game_system/memory_scope.rs:181`、`:210`；复用的识别逻辑在 `persistent_memory_system.rs:1228`。

旧格式工具识别把以 `[` 开头的助手正文视为潜在工具调用；解析失败后，范围提取直接跳过整条记录。这样 `[微笑] 我把盆栽放在书房靠东的窗台上了。` 这类正常台词无法进入长期记忆，普通 JSON 数组示例也可能被误判。

复现：把有效台词 7 改为上述文本，重新加载范围，来源 7 消失；原始数据库记录仍在。

建议：明确区分普通正文与协议数据。显式 `tool_call` 字段仍严格校验；旧内嵌格式需识别工具调用对象结构，不能只看首字符。显式损坏的协议与不完整事务继续整体排除，普通文本应正常保留。

验收补充：方括号情景文本、普通 JSON 数组、有效旧格式工具、损坏的显式工具字段及不完整工具事务。

### R3：只有动作、没有对白的可见经历漏入索引

位置：`crates/ling-chat-main/src/ai_service/game_system/memory_scope.rs:217`；复用的可见性逻辑在 `persistent_memory_system.rs:1258`。

当前“有内容”只看 `content` 和 `tool_call`，没有考虑 `action_content`。既有上下文构建器支持展示动作，P2 文档构建也会保留动作，但动作记录在更早的范围筛选阶段就被排除了。

复现：台词 7 保持当前角色发送，设置 `content=''`、`action_content='把备用钥匙放到蓝色盒子里'`，加载范围后来源 7 消失。

建议：将有意义的动作计入记忆素材判定，同时保留原角色权限、系统消息排除与工具完整性校验；是否同步调整既有摘要逻辑应单独验证，避免仅为新索引扩大旧行为。

验收补充：自己的动作、感知到的其他角色动作可以索引；未感知动作、纯空白和仅有隐藏思考的行仍不能进入。

### R4：删除角色的现有流程绕过索引外键级联

位置：`crates/ling-chat-main/src/db/managers/role_repo.rs:182`、`:184`；新索引表的外键定义在 `migration/m20261018_000001_create_memory_index.rs`。

新表依赖 `ON DELETE CASCADE` 清理角色和存档数据，但现有角色删除流程会先关闭外键，再手动清理旧业务表。新增索引表没有纳入该流程，角色删除成功后留下孤儿文档、向量和检查点；重新打开外键不会自动修复这些记录。角色删除连带删除存档时，其存档索引也有相同风险。

复现：为角色 3、存档 101 同步索引，再调用实际 `RoleRepo::delete_main_role(db, 3)`。角色已删除，仍有 **2 条该角色的文档记录**，`PRAGMA foreign_key_check` 返回 **3 项违规**。本样例没有删除存档，已经足以暴露角色清理缺口。

建议：将记忆派生索引清理纳入现有角色／存档删除路径，保证外键关闭时也能清理子记录和检查点；无需为此重构整个角色管理器。

验收补充：删除角色、连带删除其存档、其他角色在该存档的索引清理，以及其他存档和角色级笔记的保留边界；结束后外键检查为零违规。

### R5：下载脚本不能恢复缺少分词器的半成品模型目录

位置：`scripts/download_embedding_model.mjs:88`、`:106`。

只要 `model.onnx` 存在且本地／远程 `config.json` 相同，脚本便直接成功返回，没有检查 `FILES` 中其他必要文件是否齐全。首次并行下载时如果模型和配置成功、tokenizer 失败，后续重跑可能一直跳过缺失文件，模型引擎无法启用。

复现：在隔离临时目录放入模型占位文件和配置，故意不放 tokenizer；用模拟 fetch 返回相同配置运行真实下载脚本。脚本报告“无需更新”并正常结束，`tokenizer.json` 仍不存在。本复现不请求网络、不替换本机真实模型。

建议：逐个检查必要文件并补齐缺失项；下载到临时文件，验证成功后再替换最终文件。配置相同不能代表整套资源完整；固定上游版本和校验清单可作为后续可复现性改进。

验收补充：空目录、只缺 tokenizer、只缺配置、下载中断，以及完整目录的重复执行。

## 2. 优化前的工作量测量

### O1：未变化的增量同步仍重新分块和分词

位置：`crates/ling-chat-main/src/ai_service/game_system/memory_index.rs:182`。

当前顺序是对所有文档重新分块，再逐块判断向量能否复用。向量调用和写库已经避免重复，但分词仍重复执行。

在 P0 临时语料上，第二次完全未变化的同步结果为：

| 文档 | 分块 | 计数分词调用 | 累计传入字节 | 嵌入调用 |
| ---: | ---: | -----------: | -----------: | -------: |
|   21 |   21 |           92 |       12,329 |        0 |

此处使用确定性计数器记录调用和输入量，不把这些数字宣称为真实 tokenizer 的延迟。

建议：在文档版本、分块算法版本、预算和模型契约均匹配，且已有分块完整有效时，直接复用分块；只有变化文档、缺失分块或需要修复时重新分块。缺失向量仍应重试，不能用“文档没变”跳过失败恢复。

### O2：超长无标点文本重复扫描整个剩余正文

位置：`crates/ling-chat-notes/src/chunking.rs:49`。

每产生一个分块，都重新统计整个剩余串的 token、构建其全部字符边界，并在整个剩余串上二分前缀。长文本越往后，重复扫描越多。

使用同样的 480 预算和确定性计数器：

| 连续中文字符数 | 分块 | 计数分词调用 | 累计传入字节 |
| -------------: | ---: | -----------: | -----------: |
|         10,000 |   21 |          267 |      914,664 |
|         20,000 |   42 |          581 |    3,093,807 |

输入翻倍，累计处理字节增加到约 3.38 倍。该结果揭示重复扫描量，不等同于真实 ONNX 或 tokenizer 性能基准。

建议：字符边界只构建一次，按当前偏移使用受限前缀试探，逐步扩大查找范围直到达到 token 预算；避免每块先编码全部剩余正文。继续要求实际 token 计数、特殊 token 余量、Unicode 完整与全文拼接无损。

## 3. P3 验收前需要对齐的事项

- P0 人工候选文档 ID 与 P2 运行时回合文档 ID 不同，后续质量测试应使用实际索引产物并明确标签映射，避免只测手工候选而漏测整理／分块流程。
- 当前分块保留整份父文档的来源列表。质量评估不能只因返回片段引用了正确源台词就判命中，还要核对片段实际覆盖了目标事实，防止同回合其他片段造成虚假命中。
- 含工具事务的整个回合目前作为一个原子文档；其中事务之外的长正文也可能一起退化为纯词法记录。后续可按完整工具事务单元拆分，保留协议完整性；是否优化由覆盖率与预算样例决定，当前未测量其检索质量影响。
- 18 条查询适合作为小型固定回归集；P3 阈值校准应补充同名人物、相近事件、否定／计划与事实、近似日期和更多无关中文查询。模型可以推理不等于混合检索已经达标。
