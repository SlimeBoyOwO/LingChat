本阶段尚未接入聊天自动回忆、`memory_search`、混合检索、LRU 或 LLM 日记生成。后续 P3 已完成混合检索，并将分块升级为优先保留换行主题边界的 v3；实现、实测问题与兼容重建方式见 [P3 验收记录](memory-rag-p3.md)。

## 1. 实现入口

| 模块                                                                                  | 作用                                                       |
| ------------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| `crates/ling-chat-notes/src/memory.rs`                                                | 文档、分块及向量持久化契约；维度、有限值、归一化和版本验证 |
| `crates/ling-chat-notes/src/chunking.rs`                                              | 依据实际 token 数分块，保留完整文本与来源                  |
| `crates/ling-chat-notes/src/embedding/engine.rs`                                      | 共享模型适配、不截断的 token 计数、模型版本指纹            |
| `crates/ling-chat-main/src/ai_service/game_system/memory_index.rs`                    | 素材整理、分块、向量复用／生成、增量同步与重建             |
| `crates/ling-chat-main/src/db/managers/memory_index_repo.rs`                          | 范围校验后的索引读取、事务提交与并发版本保护               |
| `crates/ling-chat-main/src/migration/m20261018_000001_create_memory_index.rs`         | 四张索引表的升级／回退迁移                                 |
| `crates/ling-chat-main/src/migration/m20261018_000002_add_memory_chunking_version.rs` | 文档分块配置指纹的兼容升级／回退                           |
| `crates/ling-chat-main/tests/memory_rag/p2.rs`                                        | 隔离数据库集成验收                                         |

内部调用方式：创建 `MemoryIndexer::new(Arc<dyn MemoryEncoder>)`，然后调用 `sync(db, store, save_id, role_id, role_display_name, mode)`。实际模型由共享 `EmbeddingEngine` 实现 `MemoryEncoder`；角色显示名须由宿主可信状态提供。

- `IndexMode::Incremental`：复用内容、分块及模型版本均匹配的向量，更新发生变化的文档。
- `IndexMode::Rebuild`：重新计算当前范围的索引并提交。
- `MemoryIndexReport`：返回文档／分块数、变化数、生成／复用向量数、纯文本分块数和失败／超长计数。
- `MemoryIndexRepo::load(db, scope, model)`：读取经过来源和模型校验的派生索引快照。调用方应提供刚加载的有效范围快照。

这些入口尚未挂入 AppState、启动任务、聊天生成或工具注册；对应接入留在 P5。

## 2. 持久化结构

| 表                   | 保存内容                                                          |
| -------------------- | ----------------------------------------------------------------- |
| `memory_document`    | 文档 ID、角色、可空存档、类型、版本、分块配置指纹和完整 JSON 数据 |
| `memory_chunk`       | 分块 ID、所属文档、顺序、版本和完整 JSON 数据                     |
| `memory_embedding`   | 分块关联、分块版本、模型版本指纹和向量 JSON 数据                  |
| `memory_index_state` | 存档／角色联合检查点、提交代数、范围键与索引版本                  |

具体来源引用随文档和分块的类型化 JSON 保存，不另建来源表。标量列与 JSON 中的身份、范围和版本会交叉校验，不能仅凭表中的 `save_id` 判定可读。

对话原文与日记要求存档关联；角色级手动笔记的 `save_id` 为 NULL，保留既有跨存档含义。删除存档可级联清理其派生记录，同时保留角色笔记索引。升级迁移只新增索引表，回退只删除这些派生表。

## 3. 素材与分块方法

1. 复用 P1 当前有效历史链和角色感知快照，按用户／助手回合整理原文。保留说话人、台词属性、动作与工具文本；不把隐藏思考作为素材。
2. 原文文档使用包含存档、角色和首条源台词 ID 的稳定身份。已有笔记使用笔记 ID 和内容版本同步，外部文件修改／删除会在下次同步反映。
3. 普通文本优先按句末标点与换行切分；单句过长时按 Unicode 字符边界继续切分，不丢字符。每个分块保留所属文档的来源引用，来源粒度采用保守的整份文档范围。
4. 使用模型 tokenizer 的实际 token 数，包含特殊 token，计数器关闭截断。默认预算为 `min(480, 模型上限)`；当前模型上限为 512，不把字符数视为 token 数。
5. 含工具事务的整个回合按原子文档处理，不拆开协议。超过预算时保留全文但不生成被截断的向量，以纯文本分块等待词法检索。
6. tokenizer 不可用时保存整份文本分块；推理失败时保留分块和来源、不写无效向量，后续同步可以重试。

本阶段的“词法索引”指持久化的全文、分块与标签，尚未实现 FTS、BM25 或关键词评分。有效的已有日记文档可保留并参与索引，真实日记生成仍在 P6。

## 4. 增量、版本与失败处理

- 未变化的增量同步直接复用完整有效分块与向量，不重新分词，也不重写文档和检查点；分块配置包含算法、预算、原子事务标记与模型身份。单份素材变化只替换受影响文档，范围内已消失的素材清理其派生记录；缺失或损坏内容仍可修复。
- 向量身份包括模型文件 SHA256、tokenizer 指纹、维度与预处理信息。分块／文档版本和索引算法、预算也参与版本识别；不匹配的旧向量不能继续使用。
- 向量读取检查维度、有限值与 L2 归一化。损坏的派生 JSON 被排除，无效或过期向量作为缺失处理，可在同步／重建中修复。
- 索引准备、token 计数和推理在阻塞线程池运行；提交前重新读取历史和笔记范围。历史／笔记变化时丢弃旧任务结果。
- 提交事务再次校验有效历史版本，并检查提交代数，阻止较早的并发任务覆盖较新的已提交索引。
- 文档、分块、向量和检查点原子提交；写入失败整体回滚，不推进检查点，也不修改原始历史或笔记文件。
- 使用新鲜范围快照读取时，撤回、分支切换或感知变化导致的无效来源立即被排除；物理清理在同步／重建时进行。

模型身份在每个引擎实例中延迟计算并缓存。运行中原地替换模型资源不属于支持的热更新方式，更新后应创建新引擎或重启。若引擎因会话错误已禁用，恢复资源后也需创建新引擎或重启。

笔记 JSON 与 SQLite 之间不存在跨介质事务；同步提交前会重读笔记，但后续检索仍必须基于当前范围校验，P5 最终发送前的复核不能省略。

新增集成验收覆盖：

- 重启复用、未变化同步不重写、单份素材编辑与外部笔记增删改。
- 删除存档保留角色笔记，升级旧库保持原始历史与笔记字节。
- 模型版本改变、强制重建、推理失败重试、tokenizer 缺失与损坏索引修复。
- 跨角色／存档／分支与撤回过滤，超长工具事务完整保留。
- 推理期间历史变化拒绝旧提交，旧并发任务不能覆盖新代数。
- 人为触发 SQLite 写入失败后，索引和检查点一起回滚。

确定性集成测试使用归一化三维测试向量验证生命周期，不据此宣称检索质量。真实模型测试验证模型、分块和持久化链路，尚未测量 hit@5 或混合检索误召回。
