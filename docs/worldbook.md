# 角色世界书

世界书用于补充角色背景。将 `worldbook.yml` 放在角色资源文件夹中，与 `settings.yml` 同级即可启用，不需要修改角色卡字段。没有世界书的角色继续按原有逻辑运行。

普通角色示例：

```text
data/game_data/characters/你的角色/
├── settings.yml
└── worldbook.yml
```

剧本角色也支持，把文件放到该角色实际使用的资源文件夹中即可。世界书在角色加载时读取；修改或删除文件后，重启应用可确保生效。第一版没有在线编辑器或文件热更新。

## 示例

复制下面内容到 `worldbook.yml`，再修改为自己的设定。以下为格式示例，不代表角色的正式设定：

```yaml
name: 钦灵的世界书
entries:
  - id: core
    name: 核心设定
    enabled: true
    priority: 100
    activation:
      type: always
    content: |
      钦灵喜欢甜食，尤其是草莓蛋糕。

  - id: family
    name: 家庭背景
    priority: 50
    activation:
      type: keyword
      keys: [家庭, 父亲, 母亲, 小时候]
    content: |
      钦灵小时候和家人住在海边，经常跟母亲一起做点心。
```

## 字段和触发规则

| 字段              | 说明                                                             |
| ----------------- | ---------------------------------------------------------------- |
| `name`            | 世界书或条目显示名称，可省略                                     |
| `entries`         | 条目列表；`[]` 表示空世界书                                      |
| `id`              | 必填，建议为每个条目取一个不同的标识                             |
| `enabled`         | 是否启用，缺省为 `true`                                          |
| `priority`        | 整数，缺省为 `0`；同类条目按从高到低注入，相同优先级保持文件顺序 |
| `activation.type` | 必填，`always` 或 `keyword`                                      |
| `activation.keys` | `keyword` 必填，关键词列表                                       |
| `content`         | 必填，背景内容；空白内容跳过                                     |

`always` 每轮都提供，包括主动回复、剧本续写、后台工具通知。`keyword` 只匹配本轮原始用户输入，任一关键词以字面子串命中即可，不区分大小写；关键词两端空白会去除，空关键词忽略。不会扫描历史消息、图片内容或工具结果，也不递归匹配其他条目。

多人对话每轮使用当前发言角色自己的世界书；不同角色的条目不合并。工具调用续轮沿用该轮已经组装好的上下文。文件读取失败或 YAML 格式错误时会记录警告并跳过整本世界书，不阻断角色聊天。

## 请求、缓存与分享

常驻资料以稳定顺序放入 system，关键词命中的资料放在请求尾部，标明是背景参考资料。资料只加入请求副本，不直接写入聊天历史、存档或永久记忆；下一轮未命中的关键词条目不会再次注入。模型已经说出的相关内容仍属于正常聊天历史。

关键词变化不会改动固定 system 或已有历史前缀，有利于前缀缓存复用。但临时资料在下一轮移除后，前次请求从该位置开始的后缀无法直接复用；缓存是否命中还取决于提供商、最小长度、有效期和历史裁剪，不能保证所有历史都命中。

现有普通角色 ZIP/7z 导出会打包整个角色目录，导入会保留其中的附属文件，因此同级世界书会随角色一起分享。剧本角色使用自身资源目录加载世界书，本功能不扩展现有角色导出入口的适用范围。

第一版只支持角色私有世界书。共享世界书引用、管理 UI、历史扫描、正则、概率触发、RAG 和 SillyTavern 格式导入暂未提供。

## 验证与排查

测试时可以在条目内容中加入只有世界书才提供的名称或编号，再向角色提问。分别检查常驻、关键词命中、禁用条目以及下一轮不包含关键词的情况。不要在问题中直接给出预期答案。

需要核对实际上下文时，在「菜单 → 高级设置 → 其他高级设置 → 日志配置 → 基础设置」开启 `log.llm_request_body`，保存后重启应用。模型请求上下文记录在 `data/log/llm/`。检查完成后可关闭该开关，重启生效。

检查角色聊天请求时应确认：

- system 包含启用的常驻资料。
- 命中的关键词资料只附加在本轮请求尾部；末尾已经是 user 消息时，合并到该消息中。
- 禁用条目、空白内容和未命中条目不出现在世界书参考块中。
- 后续没有关键词的请求不再附加该参考块，历史用户消息中也不保留原始注入块。

日志目录还可能包含翻译、好感度 Agent 等请求，需要区分请求用途。只看模型回复不足以证明未命中或禁用规则生效：模型可能编造答案，也可能引用之前正常说出的内容。

`/查看记忆` 将角色持久上下文输出到程序日志；世界书在请求副本上注入，因此该命令不会显示原始世界书参考块。若修改文件后没有变化，先重启应用；若仍未加载，检查文件是否位于当前角色实际资源目录、文件名是否为 `worldbook.yml`，以及程序日志是否有“世界书读取失败”或“世界书格式错误”的警告。

开发验证命令：

```sh
cargo test -p ling-chat-main worldbook --lib
```

测试覆盖加载容错、角色目录隔离、匹配与过滤、稳定排序、请求副本隔离、提供商上下文布局、图片元数据以及 ZIP/7z 归档往返。
