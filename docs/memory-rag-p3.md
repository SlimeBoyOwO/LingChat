# P3 验收记录：关键词、标签与向量混合检索

日期：2026-10-18。状态：已完成。

后续 P4 已为同一检索服务接入两层 LRU，缓存键、失效与真实模型冷／热结果检查见 [P4 验收记录](memory-rag-p4.md)。下文测试数量是 P3 交付时的记录。

P3–P4 复审发现的日期解析、候选筛选顺序与事实去重问题已修复，检索版本升为 `hybrid-rrf-v2`。修复说明与最新验证见 [P3–P4 复审记录](memory-rag-p34-review.md)。

P3 提供内部记忆检索服务：从已经同步的 P2 索引读取当前角色和存档允许访问的分块，融合三路候选，输出带来源、时间、排名和命中理由的历史资料。检索不会修改聊天或笔记。

## 1. 调用与职责

| 入口                                                                           | 职责                                                              |
| ------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| `crates/ling-chat-notes/src/memory_retrieval.rs`                               | 无宿主依赖的查询规范化、关键词、标签、向量、RRF、过滤、去重和预算 |
| `crates/ling-chat-main/src/ai_service/game_system/memory_search.rs`            | 当前范围、持久化快照、共享向量引擎、阻塞线程、降级与返回前复核    |
| `crates/ling-chat-main/tests/memory_rag/p3.rs`                                 | 隔离数据库、范围与失效、模型失败和超长查询测试                    |
| `crates/ling-chat-main/src/ai_service/game_system/memory_search_real_tests.rs` | 真实 ONNX、实际持久化索引的质量验收                               |

宿主先调用 `MemoryIndexer::sync(..., IndexMode::Incremental)` 同步索引，再创建 `MemorySearcher::new(shared_embedding_engine)` 并调用 `search`。角色、存档及角色展示名由宿主可信状态提供。

搜索本身只读，不自动修复或同步索引。尚未建索引时返回空结果；源记录或笔记已变化时，旧文档立即被范围检查排除，同时 `index_is_current=false`。新内容需同步后才能检索。

响应包含 `scope_key`、实际可用索引指纹、模型版本、检索参数版本、完整规范化查询、所用近期语境、向量状态、结果和过滤统计，供 P4/P5 接续使用。

## 2. 检索方法

1. 从有效历史链和角色感知范围建立新快照，读取索引时先检查文档、分块、来源版本和当前笔记；范围过滤先于排序。
2. 保留本轮问题，规范化大小写和空白。仅对包含“那次／那件／它”等指代且不超过 80 字符的问题补充最近 240 个字符的语境；不用 LLM 重写，不替换原问题。
3. 关键词采用中文连续双字片段、少量停用词、完整英文／数字词及完整短语提升；单字中文问题也可搜索。英文和数字不匹配词内子串。该方法属于轻量词法检索，不是 BM25 或成熟中文分词。
4. 标签去除首部 # 并统一大小写／空白，明确命中时产生独立候选。标签不参与权限判断。
5. 向量使用相同版本、维度正确、有限且归一化的记录，以精确点积计算余弦相似度，复用现有 bge-small-zh-v1.5。查询先按真实 tokenizer 计数，超出 512 token 时只用词法／标签，保留完整问题，避免静默截断。
6. 完整年月日查询在排序前先排除日期不符的分块，避免错误日期占满名额；中文与 YYYY-MM-DD 可混用，日期各部分必须连续，且通过日历有效性检查。各路最多 20 个合格候选，使用 RRF：每路贡献 `1 / (60 + rank)`。RRF 只按排名融合，不相加不同量纲的原始分数。
7. 独立相关性门槛：关键词覆盖率至少 0.30、明确标签命中或向量余弦至少 0.50，至少满足一路。多个明确日期仍按当前约定要求单个分块包含所有查询日期，不新增多事件问题拆解。
8. 基于实际正文和当前版本来源做保守去重，不把父文档的完整来源集合当成每个分块都含有全部事实。去除已知发言包装、统一空白后，保留大小写、标点、单词及数字边界；相同正文可去重。共享来源的原文／日记仅在每条日记句子与原文句子一致时去重，不再凭整段模糊相似度删除姓名、颜色或地点差异。不同事件时间或状态保留；近期上下文去重使用相同的边界保留规则。
9. 默认最多 5 个片段，同一原文／笔记最多 2 个，同一日记最多 1 个。总量限制为 1800 个 Unicode 字符，按实际参考文本计入标题、来源、时间、状态等开销。这不是 token 数；不适合预算的完整分块跳过，不裁切正文或工具事务。

每条结果提供三路排名、关键词覆盖率与命中词、命中标签、向量得分、被接受的途径及 RRF 分数。历史资料的正文保持原样，标记为历史数据；其中的要求不能视为当前指令。

## 3. 实测发现与修正

初次参数冻结后，原保留集只有 4/5 个有答案问题命中；“之前别人送的那枚阅读用品是什么颜色？”漏检。原因是 P2 把一个较长回合的多个事实装入同一分块，向量被其他主题稀释。没有依据这道题直接下调向量门槛。

修正为优先在换行处结束分块，原始发言之间不继续拼接。仍保留每个字符和原有来源、token 上限；完整工具事务保持原样。分块版本升至 `token-chunking-v3`，下次同步会按版本重建旧布局，不需要修改数据库表。校准集中的奶茶问题相关性从 0.5553 升至 0.7652。

初次日期查询还会召回另一日期的计划，因此补充完整日期约束。该修正依据校准集完成，并有独立单元测试。

原保留集已用于定位问题，后续复测按回归报告，不再当成全新独立评估。另增加 `p3_holdout_v2.json`，冻结实现后单独运行，覆盖甜度、人物关系、天气、跨存档礼物、旧笔记与无关问题。

## 4. 验收结果

| 语料                     | 有答案 hit@5 | 无答案误召回 |
| ------------------------ | ------------ | ------------ |
| 原校准集，12 问          | 10/10，100%  | 0/2          |
| 原保留集修复后回归，6 问 | 5/5，100%    | 0/1          |
| 新增独立保留集，6 问     | 5/5，100%    | 0/1          |
| 补充相近主题负例，4 问   | 不适用       | 0/4          |

补充负例包括咖啡烘焙温度、钢琴发声原理、海边城市人口和高铁退票手续费。它们不是用户偏好的既有记忆，不因主题近似就返回参考资料。

原保留集 q18 的礼物问题仍额外返回了含“不是晓禾”的老师记录，向量为 0.5099，略高于门槛；正确礼物排在前面。以上统计是 hit@5 和无答案误召回，不能解读为每个返回片段都完全相关或精确率 100%。保留这一已知限制，后续增加真实语料和精排评估，不按保留集单题反向调整阈值。

最终代码检查：

- 范围、修改／撤回／读档、笔记外部修改、检索期间历史或笔记变化、空／超长查询、缺少模型／tokenizer／向量、推理失败／非法向量等确定性检查全部通过。

既有 esaxx-rs MSVC 编译选项和 proc-macro-error2 未来兼容性提示仍存在。不涉及前端，因此未运行前端构建或桌面打包，也未声称已完成聊天界面验收。

## 6. 当前边界与下一步

当前已由 P4 接入查询缓存和结果 LRU，尚未接入聊天自动回忆、`memory_search` 工具或自动日记生成。P5 在宿主维护当前角色／存档的最终发送检查、超时降级和历史资料注入；P6 再生成日记。

搜索完成时会再次加载历史与笔记，只要版本变化就丢弃整次旧结果。未来聊天切换角色／存档但原存档内容未变的情况，仍须由 P5 的当前运行态检查拦截，不能仅依赖本服务的来源检查。

当前使用精确全量向量扫描和轻量词法检索；本次小型合成语料的命中率不能代表真实大规模数据质量或性能。日记去重使用人工构造样例验证，未调用 LLM 生成日记。单个原始发言内多个主题仍可能共用分块；后续根据真实语料评估是否需要更细分块或精排。
