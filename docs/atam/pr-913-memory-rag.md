| 项目     | 内容                                                                                       |
| -------- | ------------------------------------------------------------------------------------------ |
| 评审对象 | PR #913 `feat：接入聊天长期记忆混合检索与缓存`                                             |
| 代码版本 | `b8c0c6b4273e6b68817dc8e2dce51d5f130fd520`                                                 |
| 评审日期 | 2026-11-27                                                                                 |
| 评审方式 | 静态代码审查 + 现有 CI 结果；未做长档压测和 ONNX 卡死模拟                                  |
| 评审范围 | 记忆索引、检索、回忆编排、生成发布集成、迁移、配置与调试接口；不评估模型精度和前端交互细节 |

本次评审的出发点是：这套功能把“长期记忆”接进了每轮聊天的主路径，任何固定成本、超时或一致性问题都会直接影响聊天体验。因此风险按“是否影响主路径”排序，而不是按代码量排序。

macOS 全量构建失败在最新 dev 上同样存在（`ort_sys` 链接阶段），不计入本 PR 的架构风险。

## 1. 质量属性场景

| ID         | 场景                                       | 期望响应                                     | 当前判断                                                             |
| ---------- | ------------------------------------------ | -------------------------------------------- | -------------------------------------------------------------------- |
| QA-PERF-1  | 5000 轮存档，用户发送短问题，自动回忆开启  | P95 不超过 2 秒；超时后普通聊天继续          | 未验证。每次检索先全量加载、解析并计算索引指纹，长档可能直接吃满超时 |
| QA-REL-1   | ONNX 推理卡住 60 秒，用户继续发消息        | 聊天不被记忆检索阻塞；推理恢复后记忆功能恢复 | 聊天不阻塞；但超时任务持有唯一许可，恢复前记忆检索一直返回 busy      |
| QA-SEC-1   | 角色 A 在当前存档检索                      | 不返回角色 B、其他存档或 A 未感知的台词      | 范围快照、来源复核和 fail-closed 校验在静态阅读下成立                |
| QA-CONS-1  | 检索或生成期间撤回台词、编辑笔记、切换角色 | 旧结果不注入；旧索引任务不能覆盖新内容       | 有快照复核和索引版本比对；缺少并发测试证明边界                       |
| QA-MAINT-1 | 新成员从入口定位到表、检索和发布           | 模块边界清楚，修改局部化                     | 分层较好，但发布、工具循环和自动存档的耦合增加了理解成本             |
| QA-TEST-1  | 修改分块、融合、缓存或范围逻辑             | 纯函数和仓库层可以快速回归                   | 覆盖不足，是本次最大的工程风险                                       |
| QA-OPS-1   | 索引损坏、模型替换或迁移升级               | 删除派生索引后可重建，不需要手工修库         | 设计支持；迁移清理有事务保护                                         |

## 2. 架构决策与战术

- **派生索引**：聊天记录、存档笔记和角色笔记文件是真源，记忆表可整体删除重建。
- **三表模型**：文档保存正文和来源，分块保存字节范围，索引状态保存范围快照与索引指纹。
- **向量并入分块**：`embedding` 作为可空列，NULL 明确表示只走词法检索。
- **来源逻辑引用**：台词和存档笔记不建 SQL 外键，来源失效由范围快照识别并重建。
- **提交前复核**：重新读取历史、存档笔记和索引版本，旧任务不能覆盖新内容。
- **单许可 + 等待超时**：同一时间只跑一个索引检索任务，忙时立即降级，避免请求堆积。
- **两层缓存**：查询向量和检索结果分别做有界 LRU，结果缓存命中后仍从当前索引还原并复核范围。
- **整轮回忆会话**：自动回忆和 `memory_search` 共用来源快照、去重和引用预算。
- **发布快照**：每句话带来源快照，发布前复核角色、存档、历史和引用是否仍然有效。
- **生成锁**：自动存档和剧本生成事件在生成期间协调，避免保存切换存档编号时误取消回复。

## 3. 敏感点与权衡点

### 敏感点

| ID   | 敏感点                                                  | 影响的属性           |
| ---- | ------------------------------------------------------- | -------------------- |
| SP-1 | 每次检索前的全量索引加载、JSON 解析、指纹计算和分块分词 | 性能                 |
| SP-2 | 全局单许可                                              | 吞吐、故障恢复       |
| SP-3 | 发布时逐句复核来源                                      | 可用性、延迟         |
| SP-4 | 默认 5 条 / 1800 字符的引用预算                         | 召回质量、上下文成本 |
| SP-5 | 检索后重新加载范围快照                                  | 一致性、延迟         |
| SP-6 | 分块完整性判定要求所有分块都有向量                      | 增量复用、重复计算   |

### 权衡点

| ID   | 权衡                   | 当前选择                              | 代价                                       |
| ---- | ---------------------- | ------------------------------------- | ------------------------------------------ |
| TP-1 | 范围隔离 vs 可用性     | fail-closed，来源校验失败就不提供资料 | 读抖动或笔记变化会丢弃整轮回复             |
| TP-2 | 一致性 vs 延迟         | 检索前先同步索引，检索后再复核范围    | 每轮固定成本高                             |
| TP-3 | 召回质量 vs 上下文成本 | 三路召回 + RRF + 阈值 + 预算          | 参数多，调优和测试成本高                   |
| TP-4 | 简化存储 vs 查询性能   | 向量放 TEXT JSON，不做 ANN 索引       | 长档只能全量扫描，后续需要预过滤或向量索引 |
| TP-5 | 发布安全 vs 吞吐       | 每句话复核来源                        | 翻译/语音较慢时复核次数多，失败会中断整轮  |

## 5. 非风险

| ID  | 决策                                          | 判断                                                         |
| --- | --------------------------------------------- | ------------------------------------------------------------ |
| N-1 | 4 张表减到 3 张，向量并入分块                 | 简化了存储和 join，NULL 向量表达降级状态，合理               |
| N-2 | 文档保存正文，分块只存字节范围                | 避免正文重复存储，来源随文档统一校验                         |
| N-3 | 台词和存档笔记不建外键                        | 索引需要在来源失效时识别并重建，逻辑引用比级联删除更可控     |
| N-4 | 单许可 + busy 降级                            | 保护聊天主路径的意图正确；风险在超时后的许可释放，见 R-REL-1 |
| N-5 | 缓存键绑定范围、模型和参数，命中后还原正文    | 没有跨范围复用，缓存失效边界清楚                             |
| N-6 | 迁移清理旧预览表和记录                        | 只删除派生索引，事务保护，不影响聊天记录和笔记文件           |
| N-7 | 无 `unsafe`、无遗留 TODO，错误基本走 `Result` | 工程卫生良好                                                 |
| N-8 | macOS 全量构建失败                            | dev 上同样失败，属于现有构建环境问题，不是本 PR 回归         |
