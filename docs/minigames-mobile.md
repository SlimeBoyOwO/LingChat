# 小游戏移动端适配

两款小游戏共用主程序的「开始游戏 → 小游戏」入口，在 Android/iOS WebView 中使用 Canvas、Pointer Events 与 Web Audio，不依赖桌面键盘或外部网页。无需锁定屏幕方向。

| 游戏     | 触摸操作                                               | 画面                                                                                  |
| -------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------- |
| 暮色节拍 | 四键点按、长按、多指和弦；点击暂停和调校               | 竖屏全宽谱面，角色与成绩置顶；触摸横屏加宽轨道；按键目标至少 48 像素                  |
| 星灯远征 | 左手移动，可滑动换向；右手跳跃、按住射击；支持同时操作 | 竖屏保留至少 480 世界像素横向视野，纵向延展背景；方向与动作按钮分列下方，至少 56 像素 |

HUD、触摸按钮和弹层继承主程序注入的 `--safe-area-inset-*`，回退到浏览器 `env()`，避开刘海、状态栏与 Home 指示器。手机横屏的暂停菜单采用两列；商店、护甲、说明、调校与结算弹层在空间不足时内部滚动。游戏页面本身不滚动。

每个手指独立记录。松开、系统取消手势或失去指针捕获时释放对应动作；暂停、旋转屏幕和离开路由时清理全部输入。切换后台或系统挂起/中断音频时暂停，用户点击继续后恢复音频；音游保留三拍恢复倒计时。键盘操作继续可用。

星灯远征会将跳跃和射击的极短点按保留到下一个物理步，避免按下与松开都发生在两帧之间时丢失输入。

## 验证方法

启动 Vite 后执行以下脚本（需要 Playwright 的 Chromium 与 WebKit 浏览器）：

```sh
node scripts/test-mini-games-mobile.cjs
node scripts/test-star-trail-audio.cjs
```

`TEST_ORIGIN` 默认 `http://127.0.0.1:1438`；`TEST_OUTPUT` 控制截图、报告与试听 WAV 输出目录；`CHROME_PATH` 可指定 Chromium；`TEST_ENGINE=webkit` 或 `chromium` 可单独检查一种引擎。

移动端检查覆盖 390×844、844×390、320×568、667×375、768×1024、1024×768，模拟上下安全区与横屏左右刘海。Chromium 使用真实触摸输入协议检查四指和弦、分别松开、三指移动跳跃射击、滑动换向与取消手势；WebKit 检查触摸点按、指针长按、横竖屏菜单、音频与原生路由组件。两种引擎都检查旋转暂停、音频中断/恢复和退出清理。

如果测试使用的 WebKit 构建不提供 Web Audio（例如本次 Windows WebKit 环境），脚本会明确跳过音游播放/长按判定和音频中断恢复，保留真实菜单、安全区、弹层、平台跳跃与路由检查，不使用假音频时钟替代。完整音频和音游输入检查在提供 Web Audio 的引擎执行。

浏览器引擎模拟验证不等于 Android/iOS 真机验收。Android 系统手势、WebView 版本、iOS 音频路由和设备延迟仍需在目标设备上检查；音游可通过输入偏移调校延迟。
