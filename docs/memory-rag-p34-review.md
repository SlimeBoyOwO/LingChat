## 1. 确认的问题

### R1 [P2] 日期筛选发生在各路候选截断之后，正确答案可能完全失去资格

位置：`crates/ling-chat-notes/src/retrieval.rs:238`、`:261`。

各路先截取前 20 项并分配排名，之后才排除日期不符的候选。排在第 21 项的正确候选即便满足关键词和向量门槛，也因为没有任何一路排名而被归为弱相关；前 20 项被排除时不会补位。

隔离复现：问题为 `2026年10月1日书签`。正确笔记为 `2026-10-01收到书签。`，查询向量为 `[1, 0]`，笔记向量为 `[0.8, 0.6]`。单独检索能够命中。加入 20 份 `2026年10月2日书签`、向量为 `[1, 0]` 的笔记后，两路排名均被错误日期占满。最终返回 0 项，日期排除 20 项、弱相关排除 1 项。

建议：把确定不合格的日期候选排除在各路排名之前，或在过滤后补充满足条件的候选。不能仅提高固定候选上限。补充超过 20 条日期干扰、仅词法降级以及三路融合的测试。

### R2 [P2] 去重会合并实际不同的日期或礼物颜色

位置：`crates/ling-chat-notes/src/retrieval.rs:318`、`:348`、`:402`。

有两种已复现的情况：

1. 正文规范化去掉日期分隔符后，`我的纪念日是2026-1-01。` 与 `我的纪念日是2026-10-1。` 都变为相同字符串。搜索 `纪念日` 时两份有效笔记只返回一份，另一个日期被当作精确重复。手动笔记没有 `event_time`，前面的事件时间比较无法保护这种正文日期差异。
2. 不同来源的两份长笔记，仅把 `银色书签` 改为 `金色书签`，会越过 0.9 的双字相似度阈值。搜索 `书签` 时只返回一份；当前事实标记只保留数字和少量否定／计划词，无法保护颜色变化。

颜色复现正文为：`那天下午我们沿着青榆公园的小路慢慢走到银杏树下躲雨，回家之前晓禾把一枚银色书签送给了我作为生日礼物。` 第二份只替换颜色。两种复现都得到命中 1 项、重复排除 1 项，预算足以容纳两份内容。

建议：精确去重的规范化保留会改变事实的边界，日期按明确的年月日值比较；对不同来源采用更保守的近似去重，不能仅凭整段相似度删除差异事实。原文与日记也应遵守事实保留规则。增加日期、姓名、颜色、地点变化的回归样例，不能只提高相似度阈值修补单个例子。

### R3 [P2] 同一文本混用日期格式时，后面的中文日期会遮蔽前面的 ISO 日期

位置：`crates/ling-chat-notes/src/retrieval.rs:379`、`:386`。

日期解析先在整个剩余文本中寻找 `年／月／日`，即使得到的年份包含另一段正文，也先认定中文格式存在。后续校验失败时不会再尝试当前位置实际有效的 ISO 日期。因此既影响正文约束，也影响查询约束。

已验证两个方向：

- 正文为 `2026-10-01收到书签，2026年10月2日整理书架。`，问题为 `2026年10月1日收到什么`，向量完全相同。正确答案被日期过滤，命中 0 项、日期排除 1 项。
- 问题为 `2026-10-01和2026年10月2日分别做了什么`，正文只有 `2026年10月2日整理书架。`。查询中的 10 月 1 日约束消失，候选未按当前“包含全部查询日期”的规则排除。

建议：每个位置仅识别从当前位置连续开始的完整日期，两种格式分别验证；一种格式解析失败不能阻止另一种格式。补充混合格式、相邻多个日期、无效日期前缀及文字间隔的测试。

## 2. P4 检查与优化建议

本次检查并重跑了以下边界：查询／参数／近期语境变化，历史和笔记编辑／删除，读档与感知撤销，角色／存档切换，模型／预处理变化，向量替换与分块缺失，缓存命中期间历史变化，推理期间变化，推理失败恢复，空索引同步，LRU 顺序、字节上限、单项拒绝和禁用缓存。

现有实现命中后仍从当前受限快照恢复正文并在返回前复查范围；查询向量可以跨范围复用，完整结果按范围分别隔离。LRU 淘汰没有删除永久笔记或 SQLite 索引。上述已有测试通过，没有将正在开发的 P5 运行态发送检查算作 P4 已实现内容。

两项可选优化，不作为本轮功能缺陷：

- 查询向量使用 JSON 缓冲。真实 512 维模型校准测试中，10 个缓存项实际计数字节共 83,040，约 8.1 KiB／项；原始 512 个 `f32` 为 2 KiB。后续可评估紧凑数值缓冲，减少序列化和保留空间，同时继续计算分配容量并验证维度、有限值、归一化与模型版本。此对比含当前缓存键和条目开销，不等同于进程 RSS。
- 完整结果命中仍需全量读取当前允许索引，并扫描所有可用向量计算指纹。入口为 `memory_search.rs:87` 与 `:177`。这是当前保持外部修改检测和隔离的设计，不能为加速直接跳过范围检查。大语料下应先按 P7 的 200／2000／10000 分块规模测量数据库读取、解析、指纹和排序各自耗时，再考虑事务维护的稳定版本或受版本保护的快照复用。本次没有大规模性能结论。

## 4. 修复实现

R1：在各路排名与截取前排除不匹配的日期，并保留日期排除计数。正式测试在 25 条错误日期干扰下，分别验证关键词降级、标签、向量与三路融合均能找回正确答案。

R2：去重规范化仅去除已知发言包装和统一空白，保留大小写、标点、单词及数字边界；同时修复近期上下文误判。删除整段模糊相似度去重；共享来源的原文／日记只在日记各句都能在原文中找到一致句子时去重，句末疑问、陈述等标点也保留。不同来源的姓名、颜色、地点差异不再被相似度吞掉。该选择更保守，改写措辞的相同事实可能占用多个候选，仍受原有总条数和字符预算限制；不为去重引入实体抽取或额外模型。

R3：只从当前数字位置识别连续的完整日期，中文和 ISO 格式不会跨过其他文字搜索分隔符；复用既有 chrono 校验真实日历日期和闰年。不新增依赖，不改变正文或原始笔记。

`SearchSettings::version()` 的算法标识升为 `hybrid-rrf-v2`，现有结果缓存键包含该版本，因此新旧规则的结果不会共用同一版本键。缓存容量、LRU 与范围复核逻辑保持现有实现。

新增 7 项 notes 单元测试覆盖上述修复、共享来源日记事实保护、边界与正常去重；新增 1 项宿主集成测试使用临时笔记和 SQLite 实际同步，分别验证日期干扰、混合日期、礼物颜色差异及纪念日差异，并逐项比较冷／热结果及实际推理次数。
