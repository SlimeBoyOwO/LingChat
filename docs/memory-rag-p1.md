# P1：记忆范围、来源与数据契约

日期：2026-10-18。状态：已完成，下一阶段为 P2。总体任务见 [构建计划](memory-rag-plan.md)。

后续进度：P2 及 P0–P2 复审修复已完成；本文件保留 P1 初次验收结果。当前来源／历史指纹已升级为事实投影 `line-v2`／`history-v2`，普通方括号正文与纯动作记录的边界已补齐，详见 [复审修复记录](memory-rag-p012-review.md)。

本阶段确定“哪些资料能成为当前角色的记忆候选”，提供数据结构、素材快照和文档／分块校验。索引表、实际分块、混合排序、LRU、聊天注入和自动日记生成继续在后续阶段实施。

## 1. 模块和接口

| 位置                                                               | 本阶段产物                                                                               |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `crates/ling-chat-notes/src/memory.rs`                             | 文档、来源、范围、分块、事件状态、模型版本、检索结果与范围版本键；笔记适配和内容版本校验 |
| `crates/ling-chat-main/src/ai_service/game_system/memory_scope.rs` | `MemoryScopeSnapshot`：读取当前有效历史和笔记，筛出可见素材，校验候选文档及分块          |
| `crates/ling-chat-main/src/db/managers/save_repo.rs`               | 共用父链重建和感知加载；新增记忆专用严格读取入口                                         |
| `crates/ling-chat-main/tests/memory_rag/p1.rs`                     | 复用 P0 的临时数据库与固定语料，验证来源范围、历史变化和旧笔记兼容                       |

## 2. 数据契约

| 类型               | 关键字段与语义                                                                 |
| ------------------ | ------------------------------------------------------------------------------ |
| `MemoryDocument`   | ID、类型、角色、范围、正文、标签、记录时间、事件时间、事件状态、版本与来源列表 |
| `MemoryKind`       | `raw` 原文、`diary` 事件日记、`note` 手动笔记                                  |
| `MemoryScope`      | `save` 表示属于指定存档；`role` 表示角色级跨存档笔记                           |
| `MemorySource`     | 稳定台词 ID 或笔记 ID，并附带当前内容版本；不使用会变化的数组下标              |
| `MemoryChunk`      | ID、所属文档、顺序、文本、版本和来源；来源必须来自所属文档                     |
| `EventStatus`      | `unknown`、`happened`、`planned`、`hypothetical`；日期未知使用 `None`          |
| `EmbeddingVersion` | 模型标识、维度、预处理版本，供 P2 的向量索引与后续查询缓存使用                 |
| `MemoryScopeKey`   | 存档、角色、历史版本、笔记集合版本，供后续异步结果复核和缓存键使用             |
| `MemorySearchHit`  | 文档 ID／版本、类型、时间与状态、分块及排序分数；本阶段只定义结构              |

文档校验要求：原文和日记属于存档、引用台词；手动笔记属于角色、只引用一条笔记来源。来源不能为空或重复，角色／存档／台词 ID 必须有效，正文和元数据必须与文档版本一致。分块必须关联正确文档，其来源版本与文档一致，文本也必须与分块版本一致。

这些校验能确定来源身份、结构和版本，不能判断日记是否忠实概括了原文。日记生成时的事实、计划、感受与来源语义校验仍属于 P6。

## 3. 范围提取和使用顺序

1. 宿主提供当前存档 ID、角色 ID 和解析后的权威展示名。展示名沿用已有笔记工具的 `ai_name` 语义；不能把模型传入的任意角色名直接当成这里的参数。P1 没有新增可由模型或前端直接调用的入口。
2. 在一个数据库读事务内确认角色存在，并沿 `last_message_id → parent_line_id` 重建当前存档的完整有效链，再读取感知关系。未落盘的运行时台词不能成为持久索引来源。
3. 严格读取遇到缺失父节点、跨存档引用或循环时返回错误，避免把不完整历史当成可检索记忆。既有普通读档仍保留缺失父节点时的截断行为，同时增加循环检测以避免无限遍历。
4. 普通素材要求“发送者是当前角色，或当前角色位于感知列表”。系统消息和空白台词不作为素材；内部思考字段不进入对外提供的记忆正文。素材保留发送者、台词属性与动作文本，供 P2/P6 区分玩家自述、角色发言和工具数据。
5. 完整工具事务要求请求与全部返回均已持久化且对当前角色可见，调用 ID 有效且唯一。支持并行结果乱序与旧版内嵌格式；不完整、损坏、孤立或部分不可见的事务整体排除。
6. 在阻塞线程池中整理来源版本并读取角色笔记，返回不可变快照。文件读取和内容哈希不占用数据库事务，也不需要游戏状态锁。

后续调用顺序是：加载快照 → `eligible_documents` 过滤候选 → 分块范围校验 → 相似度排序。`allows_document` 和 `allows_chunk` 也可在读取派生索引或缓存后复核。

日记的每一条来源都必须仍在当前有效链内、可见且版本一致。任何来源失效时整篇日记停用；即使某个分块只引用仍然有效的子集，也不能绕过父文档校验。涉及工具事务的文档和分块必须保留整组来源，防止请求与结果被分开使用。

## 4. 版本与旧笔记兼容

版本采用带格式标识的 SHA-256 内容指纹，使用固定结构的序列化输入，不依赖进程随机哈希或文件修改时间。

| 版本          | 覆盖内容                                                               |
| ------------- | ---------------------------------------------------------------------- |
| `line-v1`     | 持久化台词字段和排序去重后的感知列表                                   |
| `history-v1`  | 存档、角色及有序有效历史；同一末尾 ID 下编辑正文或感知关系也会改变版本 |
| `note-v1`     | 角色、笔记 ID、正文、标签和创建时间                                    |
| `document-v1` | 文档身份、类型、范围、文本、标签、时间、事件状态及全部来源版本         |
| `chunk-v1`    | 分块身份、父文档 ID、顺序、文本和来源版本                              |
| `notes-v1`    | 角色及权威展示名、按文档 ID 排序后的笔记集合                           |

创建或修改文档／分块后，用 `content_version()` 更新其 `version`，再调用校验。来源的顺序保留语义，当前不对标签和来源列表自动重排。历史版本保守地覆盖整条有效链，范围外台词的变化也可能导致重新校验；P2/P4 再根据实测决定是否优化。

手动笔记继续以 `game_data/notes/<角色展示名>.json` 为权威来源。原 `Note` 结构、增删改查工具和文件路径均未迁移；缺少 `tags` 的旧 JSON 仍默认空列表。适配后的文档 ID 为 `note:<角色ID>:<原笔记ID>`，新版本字段只存在于记忆文档中，不写回原 JSON。

笔记仍跨存档共享给所属角色。自动记忆快照只读取宿主指定的当前角色文件；既有工具显式跨角色只读能力保持原行为，不由新范围接口自动扩展。笔记文件的空白、字段顺序、数组顺序以及缺失／空标签的等价表达不会改变集合版本；正文、标签、时间、删除或缺失文件会反映在新快照中。损坏 JSON、无效或重复 ID 返回错误，避免静默沿用旧笔记。

快照只证明读取时的状态。P4/P5 必须在缓存命中和最终发送前读取或校验当前版本，并复核当前会话的存档／角色；本阶段没有接入撤回事件、缓存清理或聊天发送拦截。数据库与笔记文件不构成跨介质事务，最终发送前的复核仍然必要。

cargo test -p ling-chat-main --test memory_rag_p0 --locked --offline -- --nocapture

合计 80 项测试通过。本阶段新增 15 项测试，覆盖角色／存档／分支过滤、18 条固定查询的来源资格、部分日记来源撤回、同一末尾下正文与感知修改、外部笔记编辑和删除、旧格式 JSON、重启版本稳定、损坏历史链、完整及异常工具事务、未落盘素材、文档与分块版本一致性。

默认忽略的真实 ONNX 测试已在 P0 单独验证，本阶段未重复运行。本次测试只写临时数据库和笔记文件，没有修改用户存档。编译仍包含已有的 `esaxx-rs` MSVC 参数警告与 `proc-macro-error2` 未来兼容提示。未执行完整工作区、前端、桌面界面或安装包验收。

本次没有执行混合检索，因此不报告 `hit@5` 或无答案误召回率。固定查询的检查仅确认预期来源有资格进入候选池、禁止来源被过滤，不表示已经找到最相关答案。

## 6. P2 接入要求

- 由 main 的既有迁移系统建立记忆文档、来源、分块、向量及必要进度记录，notes 继续保持无数据库依赖。
- 原文索引只使用 `MemoryScopeSnapshot::lines()` 返回的素材；角色笔记索引从 `notes()` 获取，保存其版本，原 JSON 继续作为权威来源。
- 产生文档及分块时计算内容版本，保存全部来源；读取时重新用当前快照校验，不能只比较存档 ID 或最后一条台词 ID。
- 分块使用模型实际 tokenizer，保留完整工具事务与来源边界；不依靠超过 512 token 后的静默截断。
- 持久化向量携带 `EmbeddingVersion`，同一内容版本幂等更新，模型／预处理变化可识别并重建。
- 日记类型与来源关系已预留，P2 不调用 LLM 自动生成日记；P6 再接入生成、重试与恢复。
