# 对话文字动画：类 Markdown 标记实现计划

状态：初版已实现，桌面实机演出与模型输出习惯待验证。按讨论结果只保留四种固定效果，不提供强度参数。

## 目标与范围

在当前 dev 的对话管线上实现四种文字演出：加重、抖动、模糊、飘动，与逐字显示和短句合并共存。

从 `codex/text-animation-markdown` 开发，不合并旧 XML 分支，不兼容旧动画标签。旧分支仅供参考动画参数。

首版动画只作用于主对话台词。动作、历史记录、桌宠等显示入口输出去标记的纯文本，不新增动画。保留现有情绪、动作、日语译文协议。

## 语法提案

使用专用解析器识别以下标记，不引入完整 Markdown 渲染：

```text
:emphasis[真的很重要]
:shake[你别过来！]
:blur[记不清了……]
:float[今天心情很好～]
```

效果名只接受小写英文 `emphasis / shake / blur / float`，动画参数固定在前端。不引入强度、中文别名、属性或嵌套。

原讨论中的强度控制不纳入初版，以减少模型需要学习的规则。当前消息预处理还会删除花括号内容，ASCII 圆括号会归一化为动作括号；新语法不占用这些分隔符。

规则：

- 片段正文为 1～30 个 Unicode 字符，不跨行，不包含嵌套标记或方括号；表情符号纳入边界用例。
- 动画区间使用 UTF-16 下标，与现有前端逐字渲染对齐；后端计算区间时不能直接使用 UTF-8 字节下标。
- 未知效果、带参数、未闭合和其他不合法标记保留原文，不吞正文。
- 合法标记无论开关是否启用，都解析成纯文本；开关只决定是否应用动画。
- 标记内容仍按现有对话协议处理，不能把情绪、动作或译文块包入动画正文。

## 数据处理

优先在 Rust 消息处理阶段解析台词，输出纯文本与独立动画区间。后续先检查回复事件、数据库和历史载荷的实际流转，再确定最少字段改动。

片段字段：`start / end / effect`，区间相对于当前回复的纯文本，左闭右开。回复事件新增可选 `textEffects` 字段，缺省为空；现有文本字段维持纯文本。

这样主界面以外的显示入口、TTS 和翻译可以继续消费纯文本，不必各自实现一份标记解析器。模型原始输出或必要的 LLM 历史可以保留标记，需与展示历史明确区分。

需要检查的路径：

1. `fix_ai_generated_text` 保留合法动画标记，避免在真正解析前丢失信息。
2. 消息处理器先沿现有协议拆分台词、动作和译文，再对各文本清理合法动画标记；只为台词生成动画区间。
3. TTS、二次翻译、插件回复钩子和展示历史使用纯文本，不读出标记。
4. 回复事件携带台词动画信息，事件队列和 store 将其传至主对话。
5. 角色切换、存档加载、剧本和无动画回复都以空区间正常工作，不沿用上一句的动画。

若现有持久化结构无法直接保存动画元数据，首版不新增数据库迁移：历史和从存档恢复的台词只显示纯文本。主界面组件重挂载时，如当前回复元数据仍在 store 中，则恢复其动画。

## 前端渲染

- 复用现有 `charRevealCharHtml`，先完成安全转义和字符淡入，再在外层添加受控动画 span，避免两种 transform 相互覆盖。
- 动画样式放入现有全局对话样式文件，不能依赖 scoped 样式命中动态 HTML。
- 主台词打字机消费动画区间；动作打字机继续使用现有字符渲染器。
- 台词追加合并时，按照已拼接纯文本长度和实际分隔符偏移新区间；合并阈值按纯文本计算。
- 正常打字、点击补全和瞬时恢复共用同一套区间，不让标记参与打字时长。
- 加重片段字符共享动画相位，避免逐字出现后各自缩放造成视觉错位。
- 关闭开关时停止当前台词的持续动画，不重启打字、不推进事件、不影响语音。该功能默认关闭，用户主动开启后以应用开关为准，不能被系统减少动态效果偏好静默禁用。

## 开关与提示词

默认关闭。设置页只提供面向用户的效果说明，语法示例写入开发文档和模型提示词。

后端配置作为开关的权威来源，前端读取并同步设置。保存失败反馈用户，避免前端显示开启而后端仍关闭。

每次请求按最新开关注入独立的演出规则，不把可变规则永久拼入角色人设或存档；开启后下一次请求生效，关闭后停止注入。规则要求少量、可选使用，只标记台词，不标记情绪、动作和译文。

新增界面文案只补 `src/locales/zh-CN/`，使用语义 key。

## 实施顺序

1. 确定语法和最小数据字段，补充 Rust 解析器及边界测试。
2. 接通消息处理、纯文本消费路径及回复事件，确认不影响双语和语音。
3. 接入主界面动画、台词合并、补全和瞬时恢复。
4. 接入开关及请求期提示词，补用户反馈与文档。
5. 完成构建、针对性测试和可运行环境下的人工验证。

## 验证与验收

自动检查：

- Rust 用例覆盖四种效果、多个片段、Unicode 下标、长度边界、未知及不完整标记。
- 消息管线用例覆盖中文、双语、动作混排、TTS 和二次翻译输入清理，以及回复字段传递。
- 前端运行完整 `pnpm run build`；Rust 运行针对性测试及 `cargo check --workspace`。不引入前端测试框架，不为此运行全仓格式化。

人工验收：

- 台词逐字出现时对应字符演出，点击补全后动画仍正确。
- 台词自带换行、动作 replace/append、同角色连续短句合并时，颜色、区间和事件推进不受影响。
- 动画开关中途切换、角色切换和组件重挂载无残留动画。
- 合法标记不出现在主界面、历史、桌宠、动作或语音文本中；不合法标记按原文显示。
- 默认关闭时不注入演出规则；打开后的下一次请求只注入一份规则。

桌面运行验证若受本地模型、角色或音频环境限制，应明确记录未验证项，不把编译通过视为演出验收通过。

## 初版实现记录

- 后端统一解析，`EmotionSegment` 和 `ReplyResponse` 携带动画区间；写入展示历史、送入翻译和 TTS 的内容均为纯文本。未新增数据库迁移。
- 主对话消费区间，合并台词时偏移新区间；即使连续两句纯文本相同，动画信息变化也会触发更新。动作和其他显示入口不应用动画。
- 开关位于文字设置，默认关闭；保存成功后广播到各窗口，下一次请求读取最新配置注入规则。保存失败保留原值并提示。
- 日文界面显示译文时不用中文区间；繁体转换改变文本长度时回退到纯文本显示。
- 共用逐字渲染器按 Unicode 字符写入，保留 UTF-16 区间坐标，避免 emoji 被拆成两个节点。

针对性检查命令：

```bash
cargo test -p ling-chat-main text_effects --lib
node scripts/check-text-effects.mjs
cargo check --workspace
pnpm run build
```

前两项分别覆盖六个 Rust 用例，以及生产逐字渲染器的 Unicode、追加、补全、瞬时恢复与清空路径。上述检查不能代替真实角色的模型输出正确率、动画观感和语音联调。
