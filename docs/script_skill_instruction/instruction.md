## 一、创作剧本原则

### 1. 询问剧本类型

- 羁绊剧情：必须要有MAIN角色，其他角色（NPC）是可选项，正常情况下没有其他角色。羁绊剧情在 story_config.yml中需要有额外的配置。
- 独立剧本：可以没有MAIN角色，也可以有其他角色。

### 2. 确定剧本大纲

1. 假如用户没有说具体的剧情，指导用户具体阐明剧情内容。
2. 了解剧本大纲后，根据大纲先进行剧本剧情设计，包括剧情分为几章节，剧本的分支有哪些，每个分支的剧情大概是什么样子。并交给用户确认。
3. 和用户充分沟通，确保剧情的设计符合用户需求后，确定最终的剧本大纲，确定需要登场的人物，所需要的Assets素材，并交给用户确认，要求用户提供所能提供的素材（包括需要的背景，音乐，音效，环境音，图片等）。
4. 用户会与你沟通所能提供的素材，你需要根据所能提供的素材反复修改剧本大纲，进行增删改查，直到确定了一份满足素材，又满足用户剧情需求的大纲，等待用户最终确认。
5. 完成预备工作后，开始逐章节编写剧本。每一章节写完后要求给用户介绍章节内容，并要求用户确认。
6. 直到剧本编写完成，用户确认后，剧本编写工作结束。否则反复修改剧本内容。

### 3. 剧本设计原则

#### 3.1 分章节原则

- 每一个章节的剧情内容最好是关于某个场景的，当剧本出现分支的时候，必须要分章节，不能将多个分支的剧情写在一个章节中。
- 每个章节的内容不宜太短，除非是分支情况，否则每个章节应当有起码20~100个事件。
- 当剧本整体内容不大的时候，可以把所有的章节写在`Chapters`目录下。但剧本内容较多的时候，可以使用多个文件夹分级处理，例如：`Chapters/Chapter1/01.yaml`，`Chapters/Chapter2/01.yaml`等。如果想要在`next_chapter`指向那个章节，可以使用`Chapter1/01`，`Chapter2/02`等。

#### 3.2 每一片段内容设计原则

总体设计原则：

- 对于所有带有 prompt 的对话，只允许轻微的给 AI 提示，不能直接提示出完整的台词。如果需要提示出完整的台词，建议用旁白，以下是示范：

```yaml
name: 错误示范
events:
  - type: narration
    text: |
      深夜，钦灵的房间里只剩下屏幕还亮着。
      她偷偷摸摸地打开了《植物大战僵尸》，嘴上还念念有词……

  - type: modify_character
    action: show_character
    character: MAIN
    emotion: 正常
    duration: 1.5

  - type: ai_dialogue
    character: MAIN
    prompt: 钦灵一边小声嘟囔着“我才不是想玩游戏，是为了研究游戏机制才打开的”，一边心虚地悄悄点下了“开始游戏”，尾巴却因为兴奋已经轻轻摇了起来。
```

```yaml
name: 正确示范
events:
  - type: narration
    text: |
      深夜，钦灵的房间里只剩下屏幕还亮着。
      她偷偷摸摸地打开了《植物大战僵尸》，嘴上还念念有词……

  - type: modify_character
    action: show_character
    character: MAIN
    emotion: 正常
    duration: 1.5

  - type: ai_dialogue
    character: MAIN
    prompt: 钦灵打算用“学习游戏开发”安慰自己大半夜偷偷打游戏，兴奋的不行。
```

> 核心原则：不要直接提示出完整的台词，而是引导这里的 ai 自己创作出符合剧情的台词。

- 假如必须要固定 AI 的台词（在某些特殊情况下，一般不建议这么做），请使用 `dialogue` 事件，并使用 `text` 字段，例如：

```yaml
name: 正确示范 2 （固定 AI 台词，但多数场景不推荐）
events:
  - type: narration
    text: |
      深夜，钦灵的房间里只剩下屏幕还亮着。
      她偷偷摸摸地打开了《植物大战僵尸》，嘴上还念念有词……

  - type: modify_character
    action: show_character
    character: MAIN
    emotion: 正常
    duration: 1.5

  - type: dialogue
    character: MAIN
    text: |
      【嘟哝】嘛，我这样的好学生怎么会大半夜偷偷打游戏呢？
      【调皮】当然是为了研究游戏机制才打开的！一定是这样！
      【兴奋】嘿嘿，小玩一会没什么问题的啦！（摇了摇尾巴）
```

> 对于 AI 台词：必须使用【情绪】台词（可选的动作）这样的格式。为了防止生成错误和剧本过于固定，建议本用法只给戏份不多的NPC或者剧情中需要固定台词的对话使用。

- 剧情中，对于 MAIN 人物，尽可能不使用 dialogue 事件，所有对话必须通过 ai_dialogue 事件实现，prompt 提示。
