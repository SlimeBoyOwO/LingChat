# ASR 热词批量导入 · 设计

- 日期：2026-10-20
- 状态：已被 2026-10-23 的严格格式实现取代；当前格式以 docs/asr/README.md 与 src/utils/hotwordImport.ts 为准，本文保留作历史设计记录
- 范围：前端解析、审查与三处接入；不改后端命令、表结构与保存链路

## 1. 背景与目标

热词目前只能逐条添加。用户常见的词表来源是：把网页、文档或设定集交给 AI 总结，得到一组人名、专有名词和术语，再手工逐条录入。手机端逐条输入尤其低效。

本功能提供一套“粘贴词表 → 实时审查 → 确认导入”的入口，覆盖三个作用域：

| 作用域   | 宿主                    | 导入结果                             |
| -------- | ----------------------- | ------------------------------------ |
| 角色热词 | 角色设置 → 语音识别热词 | 追加到当前角色热词草稿               |
| 全局热词 | ASR 设置 → 全局热词弹窗 | 追加到全局热词草稿                   |
| 热词库   | ASR 设置 → 热词库弹窗   | 追加到词库草稿，可指定新词的目标分类 |

**目标**

- 面向非技术用户：格式直观、可手输、可让 AI 直接生成。
- 导入前完成格式审查，异常行不会进入草稿，也不会进入数据库。
- 三个作用域共用一套解析与审查逻辑，行为一致。
- 沿用现有整表替换的写入模型；导入面板的保存调用现有命令，后端零改动。

**非目标**

- 不做文件导入、导出模板、自动读取剪贴板。
- 不做按 id 覆盖已有热词（upsert）。热词行没有对外的稳定 id，现有保存是整表替换。
- 不在导入时创建新分类。
- 不做完整的 Markdown 解析（链接、表格、嵌套格式不处理）。
- 不修改热词语义、权重口径、容量口径与发送链路。
- 不引入前端测试框架。

## 2. 使用场景

### 2.1 AI 生成后粘贴

用户在任意 AI 工具中总结词表，AI 按下面的格式输出：

```
1. 厄洛替尼盐酸盐
2. DeepSeek-harness（权重 5）
3. 诺一钦灵
```

用户复制结果，粘贴进导入框，校验通过后保存到当前作用域。

### 2.2 手工输入

用户直接一行一个词：

```
厄洛替尼盐酸盐
DeepSeek-harness
诺一钦灵
```

不写权重时统一使用弹窗里的默认权重。

### 2.3 手势与平台

桌面端和移动端使用同一套文本格式。移动端不依赖快捷键、制表符或不可见字符，全部是可见的普通字符。

## 3. 导入格式

### 3.1 基本形式

- 一行一条词条。
- 空行忽略。
- 词条内的空格、逗号、中英文混排原样保留。
- 不使用引号、逗号分隔或制表符分隔。

### 3.2 行首序号与项目符号

行首标记只剥离一次，数字会作为该条目的“编号”用于报错定位。

| 写法       | 编号 | 词条 |
| ---------- | ---- | ---- |
| `1. 热词`  | 1    | 热词 |
| `1、热词`  | 1    | 热词 |
| `1) 热词`  | 1    | 热词 |
| `１．热词` | 1    | 热词 |
| `一、热词` | 一   | 热词 |
| `- 热词`   | 无   | 热词 |
| `* 热词`   | 无   | 热词 |
| `+ 热词`   | 无   | 热词 |
| `• 热词`   | 无   | 热词 |

规则：

- 项目符号 `-` `*` `+` `•` 后必须有空白才剥离。`-40℃`、`*NSYNC` 保持原样。
- 数字序号支持 ASCII 数字和全角数字；分隔符支持 `.` `．` `、` `)`。
- `.` / `．` 后紧跟数字时不当作序号，`3.5mm`、`2026.10.20` 保持原样。
- 中文数字序号 `一、` 到 `百、` 也按序号处理，编号只作为标签，不转成阿拉伯数字。
- 不支持 `第一步：`、`1-1` 等其它编号形式；这些前缀会留在词条里。建议外部 AI 统一使用 ASCII `1. ` 序号。

### 3.3 行尾权重

行尾可用中英文圆括号指定该条权重。支持完整写法和纯数字简写：

```
热词（权重 5）
热词(权重 5)
热词（权重：5）
热词（权重＝5）
热词（权重５）
热词（权重 ５）
热词（5）
热词(５)
```

精确语法：

1. 只考察行尾最后一个括号组，括号内不能嵌套括号。
2. 左括号可为 `（` 或 `(`，右括号可为 `）` 或 `)`，允许混用。
3. 括号内容 trim 后分两种情况：
   - 以 `权重` 开头：按下面的完整写法解析；`权重` 之后依次允许可选空白 → 可选一个 `：` / `:` / `＝` / `=` → 可选空白 → 权重 token。
   - 只由全角或半角数字组成：按纯数字简写解析，直接作为权重 token。
   - 其它内容（如 `诺一（限定）`、`热词（5人）`）整个括号组算词条正文。
4. 权重 token 只允许全角或半角数字；归一后必须是 `1、2、3、4、5、50` 之一。
5. 完整写法中权重 token 为空、非数字、不在合法档位、或 `权重` 后还有其它文字（如 `权重说明`），该行判为 `badWeight`。
6. 纯数字简写中数字不在合法档位同样判为 `badWeight`，例如 `热词（0）`、`热词（6）`。
7. 行尾出现左括号 + `权重` 但没有右括号时，判为 `unclosedWeight`，中英文左括号都识别。纯数字简写缺少右括号时不识别为权重（如 `热词（5` 仍按普通词条处理），避免把正常正文误判为异常。
8. 只有最后一个括号组参与解析。`热词（别名）（权重 5）` 得到词条 `热词（别名）` 和权重 5；`热词（权重 5）（备注）` 不解析权重，整行作为词条；`热词（别名）（5）` 得到词条 `热词（别名）` 和权重 5。

权重是**严格校验**：`0`、`6`、`49`、`51`、空值、非数字都判为异常，不静默归一到合法值。批量导入不应悄悄改掉用户填的权重。

不写权重时使用弹窗里的“默认权重”（默认 4）。

### 3.4 行内与行级 Markdown

AI 输出常带 Markdown 包装，解析器做有限吸收：

| 输入                       | 处理                                     |
| -------------------------- | ---------------------------------------- |
| `1. **厄洛替尼盐酸盐**`    | 剥掉成对的 `**`，词条为 `厄洛替尼盐酸盐` |
| ``1. `DeepSeek-harness` `` | 剥掉成对的反引号                         |
| `1. __诺一钦灵__`          | 剥掉成对的 `__`                          |
| `> 1. 热词`                | 剥掉行首 `>` 后继续解析                  |
| ` ``` ` 围栏行             | 跳过围栏行本身，围栏内的列表正常解析     |
| `## 热词`                  | 跳过标题行                               |
| `---` / `***` / `___`      | 跳过分割线                               |

- 只剥成对且包住整条词条的外层包装；单侧 `*`、`_` 不处理，避免误伤词条正文。
- 权重括号可能在包装内部或外部：`**热词（权重 5）**` 与 `**热词**（权重 5）` 都要能解析。处理顺序为“剥外层包装 → 提取权重 → 再剥一次外层包装”：提取权重前后各剥一次外层包装，每次最多两轮。
- 链接 `[词](url)`、表格、嵌套格式不处理，导入前需用户自行清理。
- 解释性句子无法可靠识别，仍会作为普通词条解析；导入格式只接受词表。

### 3.5 归一与不改写的范围

- 全角数字、全角冒号、全角等号只在**行首序号 token** 和**权重 token** 内归一。
- 词条正文永不做全角转半角或 Unicode 归一。`第５人格`、`ＡＩ角色`、`诺一（钦灵）` 原样保留。
- `trim` 只去掉首尾空白（包括全角空格），不改动词条内部的空格与符号。

### 3.6 保留语法与冲突

行尾以 `（权重 ...）`、`(权重 ...)`、纯数字 `（5）` 或 `(5)` 结尾的形式都是保留语法。若某个词条本身就以这段文字结尾，会被当作权重语法处理，无法按字面导入。该冲突概率极低，文案中说明即可，不做转义机制。

## 4. 审查与导入语义

### 4.1 实时审查

粘贴或编辑文本时实时解析，界面同步更新：

- 左侧显示异常行数；无异常时显示“无异常”。
- 底部保存按钮只在文本为空或保存中禁用；存在异常或超限时按钮仍可点击，点击后展开异常明细，不写入数据库；当前列表本身超容量时改为显示错误文本。
- 可导入条数不体现在按钮可用状态上，只在点击保存后用于判断是否存在可提交行。
- 输入内重复、超限、已忽略行数仍由解析器计算，供保存校验和后续扩展使用，但不在界面上逐项展示。

审查结果只读，不修改用户输入。用户修正文本后统计立即更新。

### 4.2 异常行处理

保存是**全有或全无**：

- 只要存在异常行，点击保存**不写入数据库、不关闭面板**，并在输入框下方展开异常明细。
- 异常明细显示物理行号、词条原文、权重与可读原因，最多展示 20 条；超出时显示“另有 N 条异常”。
- 用户修正文本后异常明细实时收起或更新；再次点击保存重新校验。
- 只有 `importableCount > 0`、`invalidCount === 0`、`overCapacityCount === 0` 且当前草稿行数不超过容量时，保存才会执行。

异常类型：

| 类型             | 判据                                                     | 提示内容         |
| ---------------- | -------------------------------------------------------- | ---------------- |
| 空词条           | 去掉序号、Markdown 包装与权重后为空                      | 原文行           |
| 超长（非 ASCII） | 按字符数超过 15                                          | 当前字符数、上限 |
| 超长（纯 ASCII） | 按空白切分超过 7 个片段                                  | 当前片段数、上限 |
| 权重非法         | 不是 `1/2/3/4/5/50`，或为空、非数字、`权重` 后带其它文字 | 原始权重内容     |
| 权重括号未闭合   | 行尾出现 `（权重` 或 `(权重` 但没有闭合括号              | 原始行           |

一行同时存在多个问题时只报第一个：权重语法/合法性 → 空词条 → 长度。

### 4.3 重复合并

重复不是异常，按 `text` 合并：

- 粘贴内容内部重复：保留首次出现的位置，权重取最大值。
- 与当前草稿已有词条重复：由宿主现有的 `dedupeRows` 合并到已有行上，权重取最大值，位置不变。
- 重复项不占用容量额度。
- **词库侧的目标分类只作用于新增词**。重复词保留原分类，只更新权重；需要换分类时在词库列表里直接改，不由批量导入隐式移动。

### 4.4 容量

| 作用域   | 容量 |
| -------- | ---- |
| 角色热词 | 200  |
| 全局热词 | 200  |
| 热词库   | 2000 |

容量基数是**当前草稿的原始行数**，与现有超限提示和后端“先按原始行数判断上限”的口径一致。

- 剩余额度 = `max(0, 容量 - 当前草稿行数)`。
- 新增唯一词条超过剩余额度时，保存被阻止，不写入数据库；异常明细中列出超限行。
- 与已有词条重复的合并不占额度，即使额度已满也可以更新权重。
- 当前草稿本身已超容量（行数 > 容量）时，所有导入保存都被阻止，即使只导入重复词；状态行显示“当前列表已超上限”，新增词仍标为超限。

这样不会出现“部分保存”的中间态，也不会让草稿因为本功能超过容量。

### 4.5 保存语义与范围

底部“保存”是唯一的提交动作，点击后直接写入数据库并关闭面板：

- 角色热词：追加到宿主持有的草稿，调用 `saveRoleHotwords` 只保存热词表；角色设置的其他改动仍由角色面板的保存按钮提交。
- 全局热词：追加到宿主持有的草稿，调用 `saveGlobalHotwords`。
- 热词库：追加到 `HotwordLibraryDialog` 持有的 `draft.words`，调用 `saveHotwordLibrary` 保存整个词库草稿（分类也随之一并保存）。
- 保存成功后同步更新宿主草稿，避免宿主之后的保存用旧草稿覆盖新数据。
- 保存失败时停留在面板内，显示可读错误；用户可重试。
- 取消导入或关闭导入面板不写入数据库，也不会修改宿主草稿。

**保存范围**：导入保存写入的是宿主当前热词列表的完整快照，草稿中尚未提交的编辑与删除会一并落库。用户在角色热词列表里改过若干行后再通过批量导入保存，这些改动已经写进数据库；此后取消角色设置面板不会回滚它们。这是接受的取舍：导入保存复用宿主现有的整表替换链路，不做逐行差异提交。面板在角色/全局上下文显示 `saveScopeHint`，文案说明“保存会同时写入当前热词列表的改动”；词库上下文改为显示 `duplicateCategoryHint`，不重复显示该键。

**顺序**：保存后的词条追加到列表末尾，保持粘贴顺序。现有 ASR 设计“顺序即优先级”，发送层超出 provider 容量时从尾部丢弃；因此新增词在容量紧张时可能最先被丢弃。面板始终显示 `appendHint`，文案写明“追加到列表末尾”。

## 5. 交互设计

### 5.1 入口

| 位置                    | 改动                               |
| ----------------------- | ---------------------------------- |
| 角色设置 → 语音识别热词 | 标题行“从词库添加”旁新增“批量导入” |
| 全局热词弹窗            | 复用同一热词组件，入口自动出现     |
| 热词库弹窗              | 右栏“添加词条”旁新增“批量导入”     |

### 5.2 弹窗结构

新增共享弹窗 `HotwordImportDialog.vue`，三处复用。单列布局，移动端接近全屏：

```
┌ 批量导入热词 ──────────────────────────────────────┐
│ 每行一个词，可带序号和行尾权重。                    │
│ 形式参考：1. 钦灵（权重 5）                         │
│                                                    │
│ ┌ 多行文本框 ────────────────────────────────────┐ │
│ │                                                │ │
│ │                                                │ │
│ └────────────────────────────────────────────────┘ │
│ 异常 2 行                                          │
│                                                    │
│ 默认权重 [4 ▾]   目标分类 [未分类 ▾]*               │
│                                  [取消] [保存]      │
└────────────────────────────────────────────────────┘
* 仅热词库上下文显示
```

- 目标分类默认跟随词库左栏当前选中项：数字下标直接沿用；“全部”和“未分类”都映射为未分类。
- 目标分类只列出已有分类与“未分类”，不在导入流程内创建分类。
- **目标分类只在热词库上下文显示**。角色热词与全局热词没有分类字段，不渲染目标分类控件；字段行只保留默认权重，左对齐，空出的右侧区域不放置占位说明。
- 字段行采用横向布局：默认权重 160px，目标分类填满剩余宽度；不再显示字段说明小字。
- 状态行采用横向自动布局：左侧只显示异常行数。
- 说明文案：`appendHint` 始终显示；角色/全局显示 `saveScopeHint`；词库显示 `duplicateCategoryHint`。
- 底部只有“取消”和“保存”两个按钮；“保存”是唯一提交动作。
- 点击保存时先校验：有异常、超限或当前列表已超上限则不保存、不关闭，并展开异常明细或显示错误文本；校验通过则写入数据库并关闭。
- 保存成功后同步宿主草稿；取消或点击遮罩关闭导入面板时保留已粘贴内容，不写入数据库；关闭宿主（关闭设置弹窗、词库或切换热词 tab）时导入组件随宿主卸载，粘贴内容重置。

### 5.3 状态行与异常明细

输入框正下方是一行横向自动布局：

- 左侧显示“异常 M 行”，红色；无异常时显示“无异常”，弱化颜色。
- 超限未导入不为 0 时，在异常计数后追加“超限 X 行”，琥珀色。
- 当前草稿行数超过容量时，状态行显示琥珀色“当前列表已超上限”。
- 不再显示“可导入 N 条”文字。
- 保存按钮只在文本为空或保存中禁用；存在异常、超限或当前列表超上限时按钮仍可点击，点击后展开明细或显示错误文本，不写入数据库。
- 点击保存且存在异常或超限时，在状态行下方展开异常明细：
  - 每行显示物理行号、词条原文、权重、原因。
  - 最多展示 20 条，超出显示“另有 N 条异常”。
  - 异常明细只在保存被拒绝后出现，修正输入后自动更新或收起。
- 后端保存失败时，在状态行下方显示红色错误文本（例如网络错误、后端校验失败），面板保持打开。
- 底部只保留“取消”和“保存”，不再放第二个导入按钮。

### 5.4 响应式、层级与无障碍

- 桌面端弹窗最大宽度与现有热词弹窗一致，文本框占主体高度。
- 移动端高度接近全屏，控件换行。
- 导入弹窗必须 `Teleport to="body"`：宿主弹窗带 `backdrop-blur` 与 `overflow-hidden`，会形成包含块并裁切 fixed 子层。
- 层级：宿主弹窗 `z-[10000]`，导入弹窗与全局 `Notification` 均为 `z-[10001]`，`AppDialog` 保持 `z-[10002]`，保证导入弹窗内或宿主后续弹出的全局提示仍在最上层。
- `Notification` 根节点使用 `Teleport to="body"`，层级 `z-[10001]`，避免被宿主的 `backdrop-blur` / `overflow-hidden` 容器裁切；保存成功后导入面板随即关闭，通知保持可见。
- 按钮有可读文案；状态行的异常计数同时使用颜色和文字，不只依赖颜色。

### 5.5 保存后的可见反馈

- 保存成功后关闭面板，并复用全局 `Notification` 在左上角显示约 3 秒：
  - `type: "success"`
  - `title: "已保存 N 条热词"`（词库上下文为“已保存 N 条词条”）
  - `message`：作用域名称（角色热词 / 全局热词 / 词库）
  - 必须传 `skipTipsCheck: true`；否则没有 tips.txt 的角色会静默跳过通知
- `Notification` 由 `App.vue` 在主窗口挂载，根节点 `Teleport to="body"`、层级 `z-[10001]`；导入面板同步为 `z-[10001]` 且先关闭，通知不会被裁切或遮挡。
- 角色/全局：新词已写入数据库并追加到宿主列表末尾。
- 词库：保存成功后清空搜索词，并把左栏筛选切到目标分类（未分类则切到“未分类”），确保新词立即可见。
- 保存失败时面板不关闭，错误显示在面板内，可修正后重试；不使用通知承载需要阅读的详细错误。

## 6. 解析内核

### 6.1 文件与职责

新增 `src/utils/hotwordImport.ts`，只包含纯函数与类型，不依赖 Vue、不调用 IPC。为便于 `tsc` 独立编译验证，模块内使用相对路径导入现有 helper，不使用 `@/` 别名。

```ts
export interface ImportRow {
  text: string;
  weight: number;
}

export interface ImportDetail {
  kind: "invalid" | "overCapacity";
  line: number;
  label?: string;
  text: string;
  weight: number | string;
  reason: ImportReason;
}

export type ImportReason =
  | "empty"
  | "tooLongChars"
  | "tooLongSegments"
  | "badWeight"
  | "unclosedWeight"
  | "overCapacity";

export interface ImportReview {
  rows: ImportRow[];
  importableCount: number;
  newCount: number;
  /** 与当前草稿已有词条重复、将通过去重合并的行数 */
  mergeCount: number;
  /** 粘贴内容内部重复、合并到首现行的行数（不计入可导入） */
  inputDuplicateCount: number;
  invalidCount: number;
  overCapacityCount: number;
  ignoredCount: number;
  details: ImportDetail[];
}
```

输入参数：原始文本、默认权重、当前草稿行数组（取文本集合与原始行数）、容量。

`ImportDetail.weight` 在权重相关异常中保存原始权重文本；其余情况保存该行将使用的有效权重（默认权重或合法显式权重）。`empty` 与 `unclosedWeight` 的 `text` 保存原始行；`unclosedWeight` 无法提取权重时 `weight` 为空字符串。

### 6.2 处理顺序

1. 去掉开头 BOM，统一换行为 `\n`；行号按物理行从 1 开始。Vue 的 textarea 绑定值本身已是 LF，这里做防御性归一。
2. 每行 trim（含全角空格）；空行忽略。
3. 剥掉行级 Markdown 包装：
   - 先逐层剥掉行首 `>` 引用标记，再 trim；引用块不是忽略，剥完后继续解析。
   - 代码围栏行、Markdown 标题行、分割线在剥掉引用标记后整行跳过，计入 `ignoredCount`。
4. 提取行首序号或项目符号，得到可选 `label` 与剩余文本；规则见 3.2。
5. 剥掉成对的 `**`、`__`、反引号外层包装，再 trim。
6. 提取行尾权重括号；规则见 3.3。权重 token 的全角数字归一只作用于该 token。纯数字简写与 `权重 N` 走同一档位校验。
7. 再剥一次成对的外层包装，处理 `**热词**（权重 5）` 这种权重在包装外的情况。
8. 词条文本为空则记为 `empty`。
9. 长度校验复用 `hotwordLimitKind`，与后端 `validate_text_len` 同口径。
10. 输入内按 `text` 去重：保留首次出现的位置，权重取最大值，被合并掉的行计入 `inputDuplicateCount`。
11. 与当前草稿比较：命中已有文本的记入 `mergeCount`，其余为新增。
12. 新增词条按顺序计算剩余额度；超出的唯一词条记入 `overCapacityCount` 与明细，原因为 `overCapacity`。
13. 输出全部合法解析行与明细；点击保存后，只有 `invalidCount === 0`、`overCapacityCount === 0`、当前草稿行数不超过容量且 `importableCount > 0` 时才真正提交。

一行同时存在多个问题时只报第一个：权重语法/合法性 → 空词条 → 长度。

### 6.3 统计口径

| 字段                  | 含义                                                                     |
| --------------------- | ------------------------------------------------------------------------ |
| `importableCount`     | 实际会交给宿主的行数，含与已有词条合并的行；等于 `newCount + mergeCount` |
| `newCount`            | 额度内、草稿中不存在的新增词条数                                         |
| `mergeCount`          | 与草稿已有词条重复、将通过去重合并的行数                                 |
| `inputDuplicateCount` | 粘贴内容内部重复、合并到首现行的行数，不计入可导入                       |
| `invalidCount`        | 异常行数                                                                 |
| `overCapacityCount`   | 超出剩余容量的新增唯一词条数；存在时阻止保存                             |
| `ignoredCount`        | 被跳过的 Markdown 噪音行数，不含空行与引用块                             |

“可导入”包含只更新权重的合并行。UI 只展示“异常 M 行”与超限/超容量提示；可导入条数不决定按钮是否可用，只在点击保存后用于判断是否存在可提交行；其余统计字段保留在解析结果中，供后续需要时使用。

### 6.4 与后端口径的一致性

| 口径     | 前端来源                                                        | 后端来源                                        |
| -------- | --------------------------------------------------------------- | ----------------------------------------------- |
| 文本长度 | `hotwordLimitKind` / `hotwordCharCount` / `hotwordSegmentCount` | `validate_text_len`                             |
| 权重档位 | 严格接受 `1/2/3/4/5/50`                                         | `normalize_weight` 对任意整数做归一，不负责拒绝 |
| 去重键   | trim 后的 `text`                                                | `validate_and_merge` 的归并键                   |
| 容量     | `MAX_HOTWORDS_PER_ROLE` / `MAX_LIBRARY_ROWS`                    | `MAX_ROWS_PER_ROLE` / `MAX_ROWS_PER_LIBRARY`    |

前端只做导入前拦截，后端保存仍是最终权威。前端比后端更严格：导入拒绝 `6..49`，后端会把它们归一为 5；这是刻意选择，避免批量导入静默改权重。

### 7.3 数据流

```
粘贴文本
  └─▶ parseHotwordImport(text, defaultWeight, existingRows, capacity)
        └─▶ ImportReview { rows, stats, details }
              ├─▶ 状态行（异常计数）
              └─▶ 用户点击“保存”
                    ├─ 有异常 / 超限 → 展开异常明细，不写库、不关闭
                    └─ 校验通过 → 宿主追加到草稿 + dedupeRows
                          └─▶ 宿主调用现有保存命令（整表替换）
                                ├─ 失败 → 面板内显示错误，保持打开
                                └─ 成功 → 关闭面板 + 宿主显示“已保存 N 条”
```

### 7.4 弹窗接口与挂载方式

```ts
defineProps<{
  visible: boolean;
  existing: { text: string }[];
  capacity: number;
  /** 仅词库上下文传入 */
  categories?: string[];
  defaultCategoryIndex?: number | null;
  /** 由宿主实现：追加到草稿并保存；抛错时面板保持打开并显示错误 */
  onSave: (rows: ImportRow[], categoryIndex: number | null) => Promise<void>;
}>();

defineEmits<{
  close: [];
}>();
```

- 角色/全局忽略 `categoryIndex`；词库使用它写入新增词的 `category_index`。
- `existing` 是当前草稿，不是数据库；审查跟随未保存的编辑。
- `role_id` 由宿主追加时补上（角色侧真实 id，全局侧 0 占位），导入弹窗不感知。
- `defaultCategoryIndex` 越界时按未分类处理。
- `onSave` 负责真正的写库：角色/全局调用 `saveRoleHotwords` / `saveGlobalHotwords`，词库调用 `saveHotwordLibrary`。
- 导入弹窗的生命周期跟随宿主打开会话：宿主打开期间只切换 `visible`，组件内部用 `v-if="visible"` 控制 DOM，不卸载组件；取消导入（含点击遮罩）后再次打开，粘贴内容保留。关闭宿主（关闭设置弹窗、关闭词库、切换热词 tab）时组件随宿主卸载，粘贴内容重置。
- 词库宿主必须把 `<HotwordImportDialog>` 放在宿主 `v-if="visible"` 的遮罩容器内。若放在容器外，关闭词库后组件仍然存活，下次打开会残留上一次的粘贴文本。

### 7.5 宿主协同修复

这两项是批量导入暴露出的既有缺陷，不修会让“保存成功但内容丢失/无法重试”：

1. **角色脏检查**：`SettingsCharacterInfo.vue` 的 `hasChanges` 目前只比较角色设置与资源版本，不含 `hotwordDraft`。只改热词后关闭弹窗不会弹出“放弃编辑”确认。加载热词时记录基线，把热词草稿纳入 `hasChanges`。
2. **角色保存顺序**：当前实现先 `commitCharacterEdit` 并清空 `editId`，再 `saveRoleHotwords`。热词保存失败时角色设置已提交、Save 被禁用，用户无法重试。改为先保存热词，再提交角色设置并清空 `editId`；热词保存是整表替换，重试幂等。`refreshSceneHotwords` 仍必须排在运行时热更之后，避免角色改名后派生旧名字。

全局热词弹窗与词库弹窗没有“放弃草稿”确认，取消/遮罩关闭即丢弃草稿，这是既有行为，本次不改变；导入弹窗自身的取消会保留粘贴内容，降低误触损失。

## 8. 错误处理与边界

| 场景                         | 行为                                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------------------ |
| 粘贴内容为空                 | 保存按钮禁用                                                                               |
| 全部行异常                   | 不保存，状态行显示异常行数；点击保存展开明细                                               |
| 当前草稿已满                 | 新增词全部标为超限，保存被阻止；重复词合并仍可保存                                         |
| 当前草稿超过容量             | 显示“当前列表已超上限”，新增词全部标为超限，保存被阻止                                     |
| 草稿已超容量且只导入重复词   | 状态行显示“当前列表已超上限”，阻止保存；即使没有新增词、导入内容全部是重复词也不写入数据库 |
| 保存成功                     | 关闭面板，左上角通知显示“已保存 N 条热词”约 3 秒                                           |
| 保存失败                     | 面板不关闭，显示可读错误，可修正后重试                                                     |
| 重复词权重更低               | 合并取最大值，已有权重不变                                                                 |
| 重复词权重更高               | 合并后已有行权重提升                                                                       |
| 词库重复词换分类             | 保留原分类，只更新权重；目标分类只作用于新增词                                             |
| 词条恰好以 `（权重 N）` 结尾 | 按保留语法解析，不按字面词条导入                                                           |
| 括号内权重非法               | 该行计入异常，保存被阻止，明细显示原因                                                     |
| 权重括号未闭合               | 该行计入异常，保存被阻止，明细显示原因                                                     |
| 全角数字/符号                | 只归一序号与权重 token，词条正文不变                                                       |
| 混用中英文括号               | 识别                                                                                       |
| 行内加粗/反引号              | 成对剥离外层包装                                                                           |
| Markdown 引用块              | 剥掉行首 `>` 后继续解析                                                                    |
| 链接/表格/嵌套格式           | 不处理；提示用户粘贴前清理                                                                 |
| 大段文本                     | 解析 O(n)，状态行只显示异常计数                                                            |
| CRLF / BOM                   | 统一换行、去 BOM 后再解析                                                                  |
| 角色只改热词后取消           | 纳入脏检查，弹出放弃确认                                                                   |
| 角色热词保存失败             | 导入面板内显示错误，角色设置不受影响，可重试                                               |

## 9. i18n

新增共享命名空间 `settings.hotwordImport`，四套 locale 同步：

- 入口、弹窗标题、格式说明、文本框占位符。
- 默认权重、目标分类、未分类。
- 状态行：异常、无异常、超限、当前列表已超上限。
- 异常明细：行号、原文、权重、原因、超出显示上限。
- 按钮：取消、保存、保存中。
- 说明文案（均在 `settings.hotwordImport.dialog` 下）：
  - `appendHint`：始终显示，说明新增词追加到列表末尾、顺序即优先级。
  - `duplicateCategoryHint`：仅词库上下文显示，说明重复词保留原分类，目标分类只作用于新增词。
  - `saveScopeHint`：仅角色/全局上下文显示，说明保存会同时写入当前热词列表的已有编辑与删除。
  - `listOverLimit`：显示“当前列表已超上限”；当前草稿行数超过容量时出现在状态行，并作为点击保存后的阻止原因。

## 11. 验证

### 11.1 可复跑的解析 fixture

脚本自行用 tsc 编译并打桩，不引入测试框架：

```
node scripts/verify-hotword-import.cjs
```

`hotwordImport.ts` 使用相对路径导入 `../api/services/hotword`，并在 Node 侧打桩 `@tauri-apps/api/core`。脚本覆盖当前严格格式的解析与回归项：

- 格式：`序号.词条(权重)`、全角数字与括号、格式错误与空词条。
- 权重：仅接受 `1/2/3/4/5/50`，`0/6/49/51` 拒绝。
- 长度：非 ASCII 15/16 字符、纯 ASCII 7/8 片段、emoji 码点。
- 去重：输入内重复、与草稿重复、词库目标分类判重。
- 容量：新增与合并、额度耗尽。
- 换行：CRLF、BOM、全角空格。
- 统计：`importableCount = newCount + mergeCount`，异常计数与超限计数。

脚本随功能提交，作为可复跑的验证工具，不入口 CI 门禁、不引入测试框架。

### 11.2 手工矩阵

- 三处入口各保存一次，确认写库、关闭面板、宿主列表出现新增行。
- 通知可见性：三处分别保存成功，确认左上角通知在角色设置、全局弹窗、词库弹窗之上可见，不被 `backdrop-blur` / `overflow-hidden` 裁切或遮挡，约 3 秒后消失。
- 输入含异常行时点击保存，确认保存按钮可点击、不写库、不关闭，异常明细展开。
- 修正异常后再次保存，确认写库并关闭。
- 词库在“搜索 + 分类筛选”状态下保存，确认搜索清空、筛选切到目标分类、新词可见。
- 词库重复词换分类保存，确认原分类不变、权重更新。
- 角色只改热词后取消宿主面板，确认脏检查仍生效。
- 角色热词保存失败（例如网络错误），确认面板保持打开且可重试。
- 保存中输入：保存请求未完成时继续在文本框输入或切换字段，确认新输入不会被成功回调清空，快速连点保存不会重复提交。
- 关闭词库再打开：在词库导入面板粘贴文本后取消导入，确认再次打开仍保留文本；关闭词库后重新打开，确认粘贴内容已重置。
- 超容量重复词：构造当前草稿行数超过容量且导入内容全部是重复词，确认状态行显示“当前列表已超上限”，点击保存不写库、不关闭。
- CRLF 文本保存后确认状态行计数正确。
- 窄屏词库：窄屏下打开词库，确认内容区纵向排列、左栏占满宽度、工具栏换行、词条行不横向溢出，导入弹窗可正常操作。
- 导入弹窗在角色设置（`z-50`）、全局弹窗（`z-[10000]`）、词库弹窗（`z-[10000]`）上均不被裁切，全局提示与通知不被遮挡。
- 移动端全屏布局、软键盘弹出、状态行与异常明细换行。

### 11.3 验收标准

- 角色热词、全局热词、热词库三处都能打开批量导入。
- 自然列表、行首序号、项目符号、行尾权重（中英文括号、混用、全角数字）均可识别。
- 存在异常行时保存被阻止，面板不关闭，异常明细显示行号、原文、权重与原因。
- 无异常时点击保存写入数据库并关闭面板，左上角通知显示“已保存 N 条热词”。
- 重复词按 text 合并取最大权重，位置不变；词库重复词保留原分类。
- 容量额度按当前草稿原始行数计算；超限时保存被阻止并显示超限明细。
- 保存失败时面板不关闭，错误可读，可重试。
- 取消或关闭面板不写入数据库。
- 四套 locale 均有新增文案。
- `pnpm build` 通过。
- 11.1 的 fixture 全部通过。

## 12. 风险与取舍

| 风险                                                | 取舍                                                                                         |
| --------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 行尾权重是保留语法，词条本身恰好长这样会被误判      | 接受；概率极低，不引入转义机制                                                               |
| `（权重说明）` 这类非权重括号内容会被判为权重非法   | 接受；只要行尾括号以“权重”开头就视为保留语法                                                 |
| 外部 AI 输出可能附带解释句或链接/表格，无法可靠过滤 | 只吸收加粗、反引号、引用等常见包装，其余按普通词条解析                                       |
| 原生 textarea 无法可靠地逐行染色                    | 不做逐行标红；保存被拒时在输入框下方展开异常明细                                             |
| 导入面板直接写库，可能绕过宿主草稿                  | 保存前追加到宿主草稿并同步；角色只保存热词，词库保存整库草稿；保存成功后宿主草稿与数据库一致 |
| 全局通知会因 tips.txt 缺失而跳过                    | 保存反馈显式传 `skipTipsCheck: true`；通知只是确认，宿主列表更新才是主要反馈                 |
| 相同标题与文案的通知在 3 秒内被去重                 | 导入计数或作用域变化会改变文案；连续同量导入时省略第二次通知可接受                           |
| 导入词追加到末尾，发送层容量紧张时最先被丢弃        | 文案明确说明；不在本次引入排序或插入位置                                                     |
| 角色保存顺序调整影响既有链路                        | 先热词后角色；热词整表替换幂等，失败可重试；手工回归三条路径                                 |
| `AppDialog` 层级提高影响全局                        | 只提高一层，仍为最高层；手工检查设置、资源同步等弹窗                                         |
| 解析器没有测试框架保护                              | 提交独立 fixture 脚本作为可复跑验证，不入口 CI 门禁；这是仓库“无前端测试框架”约定下的取舍    |

## 13. 已确认的决策

| 决策         | 取值                                                                                         |
| ------------ | -------------------------------------------------------------------------------------------- |
| 作用域       | 角色热词、全局热词、热词库三处                                                               |
| 输入方式     | 仅粘贴文本，不做文件导入，不自动读取剪贴板                                                   |
| 导入格式     | 自然列表，一行一条；行首序号/项目符号可选；行尾 `（权重 N）` 可选                            |
| 权重校验     | 严格接受 `1/2/3/4/5/50`，非法值报异常，不静默归一                                            |
| 权重写法     | 支持 `（权重 5）` 与纯数字 `（5）` 两种行尾写法                                              |
| 目标分类     | 仅热词库上下文显示；角色热词、全局热词不渲染该控件                                           |
| 异常处理     | 全有或全无：有异常时保存被阻止，不写库、不关闭，显示异常明细                                 |
| 保存按钮状态 | 仅在文本为空或保存中禁用；异常、超限或当前列表超上限时按钮仍可点击，点击后展开明细或显示错误 |
| 重复处理     | 按 text 合并取最大权重，保留首现位置                                                         |
| 词库重复词   | 保留原分类，目标分类只作用于新增词                                                           |
| 容量处理     | 按当前草稿原始行数计算剩余额度；超限时保存被阻止并显示明细                                   |
| 超容量草稿   | 当前草稿行数超过容量时阻止所有导入保存，包括只导入重复词                                     |
| 词库分类     | 弹窗内选择，默认跟随左栏当前分类；保存成功后切到目标分类                                     |
| 导入位置     | 追加到列表末尾，保持粘贴顺序                                                                 |
| 提交方式     | 底部“保存”是唯一提交动作，直接写入数据库并关闭面板                                           |
| 保存范围     | 写入宿主当前热词列表的完整快照，草稿中的编辑与删除一并落库；宿主取消不回滚                   |
| 宿主会话     | 导入弹窗随宿主打开而挂载、随宿主关闭而卸载；宿主打开期间取消导入保留粘贴内容                 |
| 成功后反馈   | 复用全局 Notification，左上角显示“已保存 N 条热词”约 3 秒                                    |
| 通知层级     | Notification 使用 `Teleport to="body"` + `z-[10001]`；`AppDialog` 保持 `z-[10002]`           |
| 实现架构     | 共享导入弹窗 + 纯函数解析内核 + 宿主提供的保存回调                                           |
| 宿主修复     | 角色脏检查纳入热词；热词先于角色设置保存                                                     |
| 后端         | 零改动                                                                                       |
