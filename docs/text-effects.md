# 台词文字演出

文字演出让角色通过类 Markdown 标记，为主对话台词添加加重、抖动、模糊或飘动效果。它使用专用解析器，不是完整的 Markdown 渲染，也不支持 HTML/XML 动画标签。

## 开启与关闭

在设置的文字页面开启「台词文字演出」，默认关闭。

开启后，下一次模型请求会附带标记说明和示例，无需重载角色或重启应用。普通对话中模型可以不用标记，不保证每轮都有动画。关闭时立即停止当前台词的演出，并停止向后续请求注入演出规则；打字进度和语音不受影响。

这是主动开启的功能，以应用内开关为准，不会被系统「减少动态效果」偏好静默禁用。需要减少动态效果时，可关闭此开关。

## 四种标记

| 效果 | 写法                     | 表现             |
| ---- | ------------------------ | ---------------- |
| 加重 | `:emphasis[真的很重要]`  | 加粗并循环缩放   |
| 抖动 | `:shake[别突然靠近！]`   | 左右抖动         |
| 模糊 | `:blur[记不清了……]`      | 模糊程度循环变化 |
| 飘动 | `:float[今天心情很好～]` | 轻轻上下漂浮     |

模型回复仍需保留原有情绪、动作和翻译格式。例如：

```text
【紧张】你:shake[别突然靠这么近啦！]我的心跳都要乱掉了。
（退后一步）
<急にそんなに近づかないでよ！心臓の鼓動がおかしくなっちゃう。>
```

语法规则：

- 效果名使用表中的小写英文，不支持中文别名、强度参数或其他属性。
- 方括号内为 1～30 个 Unicode 字符，不能跨行、嵌套或包含方括号。
- 只标记台词，不要将情绪、动作或译文块包进标记。
- 提示词要求每句最多标记一处，避免演出过密。
- 未知效果、未闭合、超长等不合法标记保留原文，不自动修复或吞掉正文。

## 显示范围与保存

动画作用于主对话的台词白字，与逐字显示、点击补全和同角色短句合并共存。动作灰字、历史记录和桌宠气泡只显示去标记后的纯文本。

合法标记无论开关是否开启都会被解析；关闭开关后也不会露出标记。翻译、TTS 和写入历史的台词使用纯文本，语音不会读出合法标记。

动画区间不存入数据库，因此读档或重新加载页面后不会从历史恢复动画。组件重挂载时，如果当前回复的动画信息仍在 UI store 中，可以恢复该句动画。

日文界面显示译文时不套用中文台词的动画区间；繁体转换改变台词长度时也回退到无动画显示，避免标错字符。

## 测试与排查

想单独测试某种效果，可让模型只回复一条指定内容，例如：

```text
请只回复下面这一句，原样保留冒号和方括号，不要解释：
【愉快】:float[今天心情很好～]
```

没有动画时，沿下面的路径检查：

1. **原始模型输出**：查看终端直接打印的回复是否真的包含合法标记。模型说「文字飘起来了」或「已经加上标签」不代表实际输出了标记。历史记录和下一轮请求中的台词已被清理，不能用来判断原始输出是否带标记。
2. **当前展示的句子**：模型一轮可能输出多句，只有被标记的那句会演出；先确认事件队列已经推进到它。
3. **回复事件**：开发工具控制台的 `[Tauri] 收到 ai:reply` 载荷应包含 `textEffects`。若原始回复有合法标记而对应事件没有区间，再检查后端解析；若根本没有标记，应先调整测试指令。
4. **渲染与开关**：主对话台词应生成 `tw-fx-emphasis`、`tw-fx-shake`、`tw-fx-blur` 或 `tw-fx-float` 节点；开启时父容器带有 `text-effects-enabled`，节点的计算样式 `animation-name` 应为对应动画名。

## 开发说明

后端在拆分情绪、台词、动作和译文后，统一解析演出标记，生成纯文本与动画区间。`ReplyResponse` 通过 `ai:reply` 发送可选的 `textEffects` 字段；空区间省略，普通回复和未携带元数据的剧本台词继续按纯文本处理。

上面的单句飘动示例对应：

```json
{
  "message": "今天心情很好～",
  "textEffects": [{ "start": 0, "end": 7, "effect": "float" }]
}
```

`start`、`end` 使用相对纯文本的 UTF-16 下标，左闭右开，与 JavaScript 字符串下标一致；不要直接使用 Rust 的 UTF-8 字节下标。解析器的 30 字限制则按 Unicode 字符计数。

前端在字符淡入 span 外包裹演出 span，使持续演出与字符淡入的 transform 不冲突。台词合并时，按照已有纯文本和实际分隔符长度偏移新区间。共用逐字渲染器按 Unicode 字符插入节点，保留 UTF-16 坐标，避免将代理对拆成两个节点。

主要入口：

- [后端解析与请求期提示词](../crates/ling-chat-main/src/ai_service/message_system/text_effects.rs)
- [消息处理](../crates/ling-chat-main/src/ai_service/message_system/processor.rs)和[回复载荷](../crates/ling-chat-main/src/ai_service/message_system/responses.rs)
- [对话事件处理](../src/core/events/processors/dialogue-processor.ts)和[主对话渲染](../src/components/game/standard/GameDialog.vue)
- [逐字渲染器](../src/utils/typewriter/charReveal.ts)和[全局动画样式](../src/assets/styles/dialogue-text.css)

配置键为 `text.text_effects`，由后端持久化。前端启动时读取，保存成功后通过 `text-effects:changed` 同步到各窗口。演出规则只注入当前请求副本，不永久拼入角色人设。

修改解析或事件协议后运行针对性 Rust 测试；修改前端后运行完整构建：

```bash
cargo test -p ling-chat-main text_effects --lib
pnpm run build
```

Rust 用例覆盖四种效果、长度与嵌套边界、Unicode 下标、双语及 TTS 清理、请求期提示词和事件序列化。桌面验证还需检查实际模型输出、动画观感、开关、点击补全及台词合并，不能只以构建成功代替。
