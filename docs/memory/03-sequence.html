一次压缩周期 · 时序图

关键点：触发判定是同步的，压缩本身是异步的。上图第 ①②③ 步全部发生在持有 GameStatus 锁的主线程里， 只有第 ④ 步的四段 LLM 调用被 tokio::spawn 甩到后台。正常追加台词不会作废在跑的压缩—— 只有撤回 / 读档 / 清空状态 / 工具回填会调 invalidate_history()（见右下角两个分支）。

也不进 60s 冷却（下次追加可立刻重试） ★ 普通 add_line 不在此列——追加不作废在跑的压缩 分支 B：压缩失败 ⇒ record_failure() 槽位为空 / 任一段 Err / 空串 ⇒ 记 last_failure_at_ms + fail_count++ ⇒ 指针不动（下轮重试同一批），但 60s 内判定 C 直接挡回 ★ LLM 一直失败时，表现为"压缩永不发生"且只有一条 warn
