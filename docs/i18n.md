# 界面国际化（i18n）开发指南

LingChat 界面支持 **中文 / 繁體中文（香港 · 粤语文体）/ 日本語 / English** 四种语言。
本文档说明新增 UI 文案时该怎么做，以及日常维护约定。

## 架构一览

- **库**：`vue-i18n@10`（`src/main.ts` 注册，composition 模式）
- **内置语言包**：`src/locales/<语言>/<命名空间>.ts`
  - 语言目录：`zh-CN`、`zh-HK`、`ja`、`en`
  - 命名空间文件：`common / nav / advance / settings / game / views / pet / stores / ui / api / misc`，各自 `export default { ... }`，由该目录的 `index.ts` 聚合
- **运行时语言文件**：数据目录 `data/locales/<locale>.json`
  - 首次启动用内置词条播种（缩进格式，**用户可直接编辑，无需重新编译**）
  - 前端加载后与内置词条**深合并**：用户编辑优先，缺失键内置兜底
  - 切换语言时重读文件，编辑立即生效
- **语言选择持久化**：`stores/modules/settings` 的 `display.locale`（persist 插件统一存 localStorage）

## 新增 UI 文案：只写中文

**约定：新功能只需要在 `src/locales/zh-CN/<对应命名空间>.ts` 加中文词条。**

- `fallbackLocale: 'zh-CN'`：其他语言缺键时运行时自动回落中文，界面不会坏
- 日/粤/英可以攒一批后统一补翻（找维护者或用翻译 agent 批量生成，成本低）
- key 命名：`<命名空间>.<页面/组件>.<元素>.<语义>`，如 `settings.history.backtrack`
- 插值用命名参数：`t('key', { name })`，词条里写 `……{name}……`

```vue
<template>
  <button>{{ $t('settings.history.backtrack') }}</button>
</template>

<script setup lang="ts">
import { useI18n } from 'vue-i18n'
const { t } = useI18n()
</script>
```

非组件环境（stores/composables/api）用 `import { i18n } from '@/locales'` + `i18n.global.t(...)`。

## 为什么不把中文直接当 key

- 文案改一个字/标点/空格，key 就变了，所有语言文件与调用点都要同步改，漏一处**静默失效**（不报错，直接显示原 key）
- 语义 key 是稳定锚点，文案随便改不影响查找
- 可读性交给 i18n-ally 解决（见下）

## i18n-ally（强烈推荐）

仓库 `.vscode/` 已配置好：安装推荐扩展 **i18n-ally**（`lokalise.i18n-ally`）后——

- 代码里每个 key 旁边**内联显示四种语言译文**
- 悬停查看/编辑全部语言，一键跳转到语言文件
- 已配置 `namespace` 模式（`{locale}/{namespace}.ts`）与 `zh-CN` 源语言回退

## 翻译纪律：这些**不要**翻译

- **LLM 提示词模板**（会改变 AI 行为）
- 日志 / `console.*` 输出
- 角色设定、剧本、彩蛋文案等**内容数据**
- 情绪枚举值、后端协议值、数据匹配键（如 `narrationNames`、配置树分类名）
- 磁盘路径、URL、环境变量名

## 各语言包维护注意

- **zh-HK 是粤语文体**（嘅/喺/咗/唔係/冇/傾偈），人工维护；`scripts/generate-zh-hk.mjs` 仅用于最初的 OpenCC 引导生成，**不要重跑**（会覆盖粤译）
- `data/locales/*.json` 播种后不会随内置包自动更新（保护用户手改）；需要官方新版时删除对应文件重启重新播种
- 日文界面下对话显示模型自带的日语译文（`tts_content`）；繁体界面下对话显示层简转繁（`hkify()`）——都是显示层行为，不动数据
