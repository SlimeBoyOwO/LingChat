# 笔记语义检索

`memory_get_notes` 支持按语义检索角色笔记：不传 `query` 时返回全部笔记，传 `query` 时用句向量后端返回最相关的 Top-K。排序只使用向量相似度，不做词法融合。

## 工具行为

| 参数    | 说明                                             |
| ------- | ------------------------------------------------ |
| `role`  | 要读取的角色名，省略时读取当前角色               |
| `query` | 检索关键词或简短问句；省略或为空白时返回全部笔记 |
| `top_k` | 返回条数，范围 1–20，默认 8                      |

检索成功时返回：

```json
{ "ok": true, "notes": [], "total": 137, "returned": 8, "retrieved": true }
```

`notes` 元素结构与旧版一致。无检索时保持 `{ "ok": true, "notes": [] }`。查询文本直接使用 `query.trim()`，不加 bge 指令前缀。

## 嵌入后端

句向量由统一的 `Embedder` 契约提供，检索链路不区分本地与云端：方法一律同步阻塞，由调用方放进 `spawn_blocking`。

- **本地**：`ling-chat-notes` 内的 ONNX 引擎（bge-small-zh-v1.5，512 维），模型与分词齐备才可用，运行期失败即置禁用位。
- **云端**：实现在宿主侧（`ling-chat-notes` 位于依赖链最底层，不能引 HTTP 栈）。路由器按用户配置在本地与云端之间选路，下游只看得到一个嵌入器。
- **重试与熔断**：单次云端调用至多尝试 5 次，间隔按 400ms 递增退避；全部失败进入熔断态，同一熔断周期只向前端发一次告警。熔断期间不切回本地——向量空间归属仍按云端判定，只是不再向量化，避免同一份笔记半本地半云端。保存云端配置或重启会清除熔断。
- **维度探针**：云端后端在首次成功响应前不知道维度，检索时先用一次短探针确定并缓存，之后同一后端纯查表。探针失败即报错，走降级路径。

保存云端配置后会启动一次后台预热，逐角色补齐笔记向量并附带 Tool RAG 语料，进度以事件回报；同一时刻只跑一轮，新的保存会中止上一轮。

## 实现

- **文本表示**：正文与标签用空格拼接。正文或标签变化会改变内容指纹，从而触发向量重建。
- **向量库**：每个角色、每个嵌入后端一个 sqlite-vec 文件，位于
  `<data_dir>/vector_index/notes/<后端命名空间>/<角色名>.db`。命名空间本地取模型目录名，
  云端取「提供商 + 模型名」；换后端等于换一整棵目录树，不同向量空间永不混用。与
  `game_data` 分开存放，不会被资源同步覆盖；索引可完全由笔记文件重建，不需要备份。
- **增量维护**：向量 ID 为 `note_id:内容指纹`。每次检索先加载笔记，对账已有向量，
  删除已删除笔记和内容变化留下的旧条目，再批量嵌入缺失项。
- **批量嵌入**：每 32 条调用一次后端。本地批内按最长序列补齐，取 CLS 行并做 L2 归一化；
  首次检索把查询与缺失笔记放在同一批里，缓存命中后只嵌入查询本身。
- **并发**：推理放在 `spawn_blocking` 中；同一角色的向量库由内部互斥锁串行化，不同
  角色使用独立数据库文件。笔记检索与 Tool RAG 共用同一个嵌入器实例：本地是一条 ONNX
  会话，两者同时检索会排队；云端是 HTTP 请求，可并发发出。

## 降级

引擎未启用、已熔断、嵌入失败、阻塞任务失败、查询为空白或笔记为空时，均返回与旧版一致的
全量结构，不向模型抛错。引擎禁用只告警一次，运行期检索失败每次告警。

## 设计依据

离线评测（400 条笔记 / 120 条查询，bge-small-zh-v1.5 uint8）显示：正文拼接标签的
纯向量召回优于仅正文；RRF、门控追加与分数融合没有稳定收益，因此不做融合。Top-8
在多目标查询上仍有明显收益，作为默认值。
