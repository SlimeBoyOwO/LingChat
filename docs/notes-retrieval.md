# 笔记语义检索

`memory_get_notes` 支持按语义检索角色笔记：不传 `query` 时返回全部笔记，传 `query` 时用本地句向量模型返回最相关的 Top-K。排序只使用向量相似度，不做词法融合。

## 工具行为

| 参数    | 说明                                             |
| ------- | ------------------------------------------------ |
| `role`  | 要读取的角色名，省略时读取当前角色               |
| `query` | 检索关键词或简短问句；省略或为空白时返回全部笔记 |
| `top_k` | 返回条数，范围 1–20，默认 8                      |

检索成功时返回：

```json
{ "ok": true, "notes": [], "total": 137, "returned": 8, "retrieved": true }
```

`notes` 元素结构与旧版一致。无检索时保持 `{ "ok": true, "notes": [] }`。查询文本直接使用 `query.trim()`，不加 bge 指令前缀。

## 实现

- **文本表示**：正文与标签用空格拼接。正文或标签变化会改变内容指纹，从而触发向量重建。
- **向量库**：每个角色、每个嵌入模型一个 sqlite-vec 文件，位于
  `<data_dir>/vector_index/notes/<模型目录>/<角色名>.db`。与 `game_data` 分开存放，
  不会被资源同步覆盖；索引可完全由笔记文件重建，不需要备份。
- **增量维护**：向量 ID 为 `note_id:内容指纹`。每次检索先加载笔记，对账已有向量，
  删除已删除笔记和内容变化留下的旧条目，再批量嵌入缺失项。换模型时使用新目录，
  不会与旧模型空间的向量混用。
- **批量嵌入**：`EmbeddingEngine::embed_batch` 每 32 条调用一次推理，批内按最长序列
  补齐，取 CLS 行并做 L2 归一化。首次检索把查询与缺失笔记放在同一批里；缓存命中后
  只嵌入查询本身。
- **并发**：推理放在 `spawn_blocking` 中；同一角色的向量库由内部互斥锁串行化，不同
  角色使用独立数据库文件。与 Tool RAG 共用同一个嵌入会话，两者同时检索会排队。
- **超时**：工具超时提示为 15 秒，覆盖默认的 2 秒，用于首次为整份笔记建索引。

## 降级

引擎未启用、嵌入失败、阻塞任务失败、查询为空白或笔记为空时，均返回与旧版一致的
全量结构，不向模型抛错。引擎禁用只告警一次，运行期检索失败每次告警。

## 设计依据

离线评测（400 条笔记 / 120 条查询，bge-small-zh-v1.5 uint8）显示：正文拼接标签的
纯向量召回优于仅正文；RRF、门控追加与分数融合没有稳定收益，因此不做融合。Top-8
在多目标查询上仍有明显收益，作为默认值。
