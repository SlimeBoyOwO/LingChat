# 笔记语义检索

`memory_get_notes` 默认同时检索当前存档和当前角色的全局笔记：不传 `query` 时返回全部笔记，传 `query` 时用句向量后端分别召回，合并后按相似度排序、按内容去重，再用下一条较高分候选补足 `top_k`。

## 存档笔记与全局笔记

手动笔记分两层：

- **存档笔记**（默认写入）：进入某个存档后，笔记默认读写当前存档。同一存档内所有角色共享同一份，不区分角色。
- **全局角色笔记**（关键信息）：只有用户明确要求跨存档长期保留的内容，才用 `scope=role` 写入当前角色的全局笔记。

读取默认合并两层；可用 `scope` 只查 `save` 或 `role`。`role` 参数用于指定要读哪个角色的全局笔记，省略时用当前角色。

尚未产生存档时，笔记先暂存在 `GameStatus` 内存里；首次创建存档或首次自动存档时一次性写入该存档。新建或覆盖其他存档时，用当前会话的笔记整体替换目标档（存档是快照）；读档则切换为该档自己的笔记，并把该档笔记预加载到内存，后续检索不再查库。读档、新游戏、清空对话等会话边界会丢弃未落盘的暂存。

存储位置：存档笔记落 SQLite 的 `save_note` 表（主键 `(save_id, id)`，另有 `content` / `tags` / `created_at`），随存档删除由应用层清理。全局角色笔记仍是 `<data_dir>/game_data/notes/<角色展示名>.json`。

## 工具行为

| 参数          | 说明                                                                        |
| ------------- | --------------------------------------------------------------------------- |
| `scope`（读） | `merged`（默认，存档 + 角色全局）/ `save` / `role`                          |
| `scope`（写） | 新增默认 `save`，可用 `role` 写当前角色全局；改删不传时先找存档再找角色全局 |
| `role`        | 要读取其全局笔记的角色名；省略时用当前角色                                  |
| `query`       | 检索关键词或简短问句；省略或为空白时返回全部笔记                            |
| `top_k`       | 返回条数，范围 1–20，默认 8                                                 |

检索成功时返回：

```json
{ "ok": true, "notes": [], "total": 137, "returned": 8, "retrieved": true }
```

每条笔记在原有 `id` / `content` / `tags` / `created_at` 之外带 `source`：`save` = 当前存档，`role` = 角色全局。无检索时保持 `{ "ok": true, "notes": [] }`。查询文本直接使用 `query.trim()`，不加 bge 指令前缀。

混合检索时每个来源最多取 20 条候选，合并后按相似度降序；同分时存档优先。内容相同的笔记只保留分数更高的一条，空出的位置由下一条候选补足。

## 嵌入后端

句向量由统一的 `Embedder` 契约提供，检索链路不区分本地与云端：方法一律同步阻塞，由调用方放进 `spawn_blocking`。

- **本地**：`ling-chat-notes` 内的 ONNX 引擎（bge-small-zh-v1.5，512 维），模型与分词齐备才可用，运行期失败即置禁用位。
- **云端**：实现在宿主侧（`ling-chat-notes` 位于依赖链最底层，不能引 HTTP 栈）。路由器按用户配置在本地与云端之间选路，下游只看得到一个嵌入器。
- **重试与熔断**：单次云端调用至多尝试 5 次，间隔按 400ms 递增退避；全部失败进入熔断态，同一熔断周期只向前端发一次告警。熔断期间不切回本地——向量空间归属仍按云端判定，只是不再向量化，避免同一份笔记半本地半云端。保存云端配置或重启会清除熔断。
- **维度探针**：云端后端在首次成功响应前不知道维度，检索时先用一次短探针确定并缓存，之后同一后端纯查表。探针失败即报错，走降级路径。

保存云端配置后会启动一次后台预热，逐角色、逐存档补齐笔记向量并附带 Tool RAG 语料，进度以事件回报；同一时刻只跑一轮，新的保存会中止上一轮。

## 实现

- **文本表示**：正文与标签用空格拼接。正文或标签变化会改变内容指纹，从而触发向量重建。
- **向量库**：每个笔记归属、每个嵌入后端一个 sqlite-vec 文件。全局笔记在
  `<data_dir>/vector_index/notes/<后端命名空间>/<角色展示名>.db`，存档笔记在
  `<data_dir>/vector_index/save_notes/<后端命名空间>/save_<存档 id>.db`。两者分目录，
  归属键不会与角色展示名撞名。命名空间本地取模型目录名，云端取「提供商 + 模型名」；
  换后端等于换一整棵目录树，不同向量空间永不混用。与 `game_data` 分开存放，不会被
  资源同步覆盖；索引可完全由笔记数据重建，不需要备份。删除存档时尽力清理该档索引文件，
  已打开的连接可能让清理失败，索引本身可重建。
- **混合检索**：存档侧与角色侧各自召回最多 20 条候选，合并后按相似度降序；同分时存档优先。
  正文按空白折叠、忽略大小写后去重，重复项跳过并由下一条候选补位。
- **暂存打分**：尚未存档的暂存笔记没有持久索引，检索时用同一嵌入器按批现场计算点积
  （向量已 L2 归一化）。
- **增量维护**：向量 ID 为 `note_id:内容指纹`。每次检索先加载笔记，对账已有向量，
  删除已删除笔记和内容变化留下的旧条目，再批量嵌入缺失项。
- **批量嵌入**：每 32 条调用一次后端。本地批内按最长序列补齐，取 CLS 行并做 L2 归一化；
  首次检索把查询与缺失笔记放在同一批里，缓存命中后只嵌入查询本身。
- **并发**：推理放在 `spawn_blocking` 中；同一角色的向量库由内部互斥锁串行化，不同
  角色使用独立数据库文件。笔记检索与 Tool RAG 共用同一个嵌入器实例：本地是一条 ONNX
  会话，两者同时检索会排队；云端是 HTTP 请求，可并发发出。

## 降级

引擎未启用、已熔断、嵌入失败、阻塞任务失败、查询为空白或笔记为空时，均返回与旧版一致的
全量结构，不向模型抛错。引擎禁用只告警一次，运行期检索失败每次告警。

## 设计依据

离线评测（400 条笔记 / 120 条查询，bge-small-zh-v1.5 uint8）显示：正文拼接标签的
纯向量召回优于仅正文；RRF、门控追加与分数融合没有稳定收益，因此不做融合。Top-8
在多目标查询上仍有明显收益，作为默认值。
