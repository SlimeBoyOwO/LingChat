# P4 验收记录：缓存与 LRU

日期：2026-10-18。状态：已完成。

后续 P3–P4 复审已修复检索的日期和事实去重问题，并补充经 SQLite 索引的冷／热结果一致性测试，见 [复审与修复记录](memory-rag-p34-review.md)。下文数量和耗时为 P4 初次交付的记录。

P4 为现有 `MemorySearcher` 接入两层进程内缓存，减少重复查询的向量推理和混合排序。SQLite 中的文档向量、原始聊天、笔记和日记都不由 LRU 淘汰。

## 1. 实现入口

| 模块                                                                           | 职责                                                     |
| ------------------------------------------------------------------------------ | -------------------------------------------------------- |
| `crates/ling-chat-main/src/ai_service/game_system/memory_cache.rs`             | 有界 LRU、条数与字节上限、命中／淘汰统计、清空入口       |
| `crates/ling-chat-main/src/ai_service/game_system/memory_search.rs`            | 两层缓存键、查询向量复用、候选复原、范围与版本复核       |
| `crates/ling-chat-main/src/ai_service/game_system/memory_cache_tests.rs`       | 最近使用顺序、字节预算、实际缓冲容量、损坏缓存与关闭验证 |
| `crates/ling-chat-main/tests/memory_rag/p4.rs`                                 | 隔离数据库的命中、失效、并发、淘汰与降级验收             |
| `crates/ling-chat-main/src/ai_service/game_system/memory_search_real_tests.rs` | 真实模型冷／热结果一致性及命中统计                       |

使用同一个 `MemorySearcher` 实例服务多次请求，或用 `Arc<MemorySearcher>` 在宿主共享。每次重新创建实例会建立新的空缓存。现阶段仍是内部服务，未挂入 AppState 或聊天流程。

- `MemorySearcher::new(shared_engine)`：使用默认容量。
- `with_cache_config(shared_engine, config)`：宿主配置两层容量。
- `MemoryCacheConfig::disabled()`：关闭两层缓存，检索行为保持一致。
- `cache_stats()`：读取两层命中、未命中、插入、淘汰、拒绝、失效、保留字节和实际混合检索次数。
- `clear_caches()`：释放目前缓存的临时内容，统计计数继续累计；正在执行的有效任务之后仍可按当前版本填充缓存。
- 每次响应的 `cache.result_hit`、`cache.query_vector_hit` 分别说明本次实际访问的缓存层；完整结果命中不会再访问向量缓存。

## 2. 缓存内容与键

| 层       | 保留内容                                                       | 键                                                                                                        |
| -------- | -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 查询向量 | 通过维度、有限值和归一化校验的向量                             | 模型与预处理版本、模型 token 上限、完整规范化有效查询                                                     |
| 检索结果 | 候选文档／分块 ID 与版本、评分与命中说明、原检索统计、向量状态 | 存档、角色、历史／笔记版本、实际索引指纹、模型／预处理版本与 token 上限、问题与有限近期语境、检索参数版本 |

两层均以 SHA-256 版本键索引，不用“两个问题的向量接近”判断缓存命中。普通问题只改变近期上下文时，结果键改变；若它没有触发指代补充、有效查询未变，仍可复用查询向量。指代问题的语境改变会同时影响有效查询和结果键。

索引指纹除代数、检查点、文档／分块版本及分块配置，还纳入实际可用向量内容。即使派生数据被外部替换而检查点未更新，也不会把旧排序当成新排序。相关计算、分词、推理与排序在阻塞线程执行。

结果缓存不保留旧正文或旧参考文本。命中后从新加载、已按当前范围过滤的索引重新查找候选，核对文档与分块版本，再用当前正文、来源、时间和状态重新生成参考文本，重新检查字符预算。找不到候选或预算不符时按未命中重新检索。

缓存命中仍读取当前范围及持久化索引，不声称跳过数据库或文件检查。响应的检索诊断是被复用结果的原始诊断；本次是否重做排序由缓存标志与 `hybrid_searches` 计数判断。

## 3. 容量与最近使用规则

默认查询向量最多 128 项、结果最多 64 项；每层保留字节预算 1 MiB，每项最多 32 KiB，任一边界先达到就限制或淘汰。

缓存保留序列化字节缓冲，字节计数包含键与缓冲的实际分配容量及已占用条目结构大小，避免只计算内容长度而漏掉超大分配。计数不是整个进程的 RSS，未把队列空槽、锁、临时反序列化结果或并行任务计入。默认条数同时限制队列结构的规模。

- 每次实际命中或成功写入，把该层对应项移到最近使用端。
- 满容量时从最久未使用端淘汰，直到条数和字节预算都满足。
- 单项超限直接跳过缓存，保留本次检索结果，不挤掉其他有效条目。
- 容量为零可以单独禁用任一层。
- 完整结果命中只触碰结果 LRU；查询向量未被实际读取，不刷新该层顺序。

缓存锁只保护短时查找、复制及写入，不跨越数据库访问、await、tokenizer、推理或混合检索。不增加外部缓存服务和依赖，也不做并发请求合并；同时到达的首次相同请求仍可能各自计算。

## 4. 失效与降级

版本改变立即阻止旧键复用，旧版本条目可以留在有界 LRU 内等待淘汰，不会因此重新成为当前可用结果。相同问题的查询向量可以跨历史版本、角色与存档共享，完整结果必须分别检查范围。

覆盖：笔记修改／删除／外部编辑、源记录修改／撤回、当前分支和感知变化、切换角色／存档、索引重建、分块或向量删除／替换、模型／预处理变化、检索参数或近期语境变化。

搜索返回前再次读取历史与笔记版本；即使已经命中结果缓存，期间发生变化仍丢弃整次结果。未通过最终复核的搜索不写入结果缓存；已经成功生成的查询向量是与历史无关的计算，可以保留。

推理失败、非法向量、tokenizer 失败和超长查询的降级结果不进入结果缓存，避免暂时失败阻止后续恢复。成功结果以及稳定的空查询／无可用索引向量结果允许缓存；索引建立或向量补齐时，新的索引指纹使旧结果失效。损坏的临时缓存按未命中处理。

缓存不代替 P5 的最终发送检查：当前运行态切换但旧存档内容未变时，仍需宿主核对当前请求所属的角色、存档和生成任务。

## 5. 验收

最终验证：

- 全工作区测试通过 192 个：main 单元测试 98、P0–P4 数据库集成测试 49、notes 测试 29、plugins 测试 16；桌面壳与文档测试通过。5 个依赖外部资源的测试默认忽略。
- 另外分别执行 3 个真实 ONNX 记忆检索测试，全部通过，包含下表的缓存命中与结果一致性验证。
- `cargo check --workspace --locked --offline` 通过。
- 既有 esaxx-rs MSVC 选项和 proc-macro-error2 未来兼容性提示仍存在；本阶段未修改前端，未做前端构建或桌面打包。

P4 定向数据库测试 15 项，另有 5 项 LRU 单元测试验证底层边界。测试使用临时数据库与测试角色笔记，不写用户数据。

验收既检查命中标志，也检查实际编码调用次数、tokenizer 调用次数与混合检索次数。重复查询只做一次向量推理和排序；只失效结果层时，复用已有查询向量。淘汰后重新检索仍能找到永久笔记，同时数据库中的持久化向量行数保持不变。

真实模型继续使用 P3 的校准、回归保留集和新增独立保留集；每个问题追加一次相同查询，比较完整片段、正文、来源、评分与说明，并核对热请求没有增加向量缓存未命中数或混合检索次数。

24 个重复请求全部复用结果，且逐项结果一致；补充 4 个相近主题负例仍无误召回。校准集在统计时保留的查询向量缓冲约 81.1 KiB、候选缓存约 12.3 KiB；两份保留集的查询向量各约 48.7 KiB，候选分别约 7.2 KiB、6.2 KiB。以上为本次运行的计数字节和单次累计耗时；每个冷／热请求仍执行完整范围与索引读取，因此不能等同于纯 LRU 查找耗时或固定加速承诺。

真实模型测试分别运行于独立进程。小型固定语料的冷／热耗时仅是本机实测，不代表大规模性能承诺；200、2000、10000 分块的完整性能评估保留在 P7。
