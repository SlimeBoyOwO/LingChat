# 聊天记忆与检索设计

## 目标与边界

角色的对话上下文由人设、近期可见台词和可选的永久记忆摘要组成。随着聊天增长，摘要能保留主要经历，但可能遗漏具体细节。记忆检索在当前问题需要时，从当前存档中该角色可见的历史及角色笔记里找相关片段，作为本轮回答的参考。

检索索引是可重建的派生数据：聊天台词及存档是历史来源，角色笔记文件是笔记来源。检索不替代现有摘要或近期上下文，也不会把检索结果再作为新经历保存。永久记忆的压缩调度见 [永久记忆压缩调度](persistent-memory-compression.md)；原有笔记工具的独立向量检索见 [笔记语义检索](notes-retrieval.md)。

举个例子：玩家问“上次约好去哪里”，近期对话和摘要先帮助角色理解当前话题；检索再尝试找出与约定相关的旧台词或笔记。如果找不到，角色仍然可以正常回复，但不应该把猜测当成确实发生过的事。

## 模块与数据流

```mermaid
flowchart TD
    History[存档历史] --> Scope[角色与存档范围快照]
    Notes[角色笔记] --> Scope
    Scope --> Index[文档分组与分块]
    Index --> DB[SQLite 分块及可选向量]
    Query[当前问题或 memory_search] --> Search[关键词、标签与向量检索]
    DB --> Search
    Cache[查询向量与结果缓存] <--> Search
    Search --> Verify[复核来源、去重和预算]
    Verify --> Auto[自动回忆：放在最近一条用户消息正文前]
    Verify --> Tool[主动回忆：通过工具结果返回]
    Auto --> Reply[生成回复]
    Tool --> Reply
```

主要代码位于 `crates/ling-chat-main/src/ai_service/game_system/memory/`，由 `mod.rs` 导出：

- `builder` 从角色可见台词构造对话消息，`persistent` 负责已有的摘要压缩。
- `scope` 按角色和存档生成来源快照；`index` 维护增量索引。
- `search` 执行检索及来源复核；`cache` 管理缓存；`recall` 管理单轮会话和引用预算。

`ling-chat-notes` 提供记忆数据结构、分块和混合排序；主程序负责访问存档、权限和数据库。`db/managers/memory_index_repo.rs` 负责索引读写，自动回忆从消息生成器进入，`memory_search` 工具通过相同的 `MemoryRecall` 服务检索。

## 来源和索引

检索范围由宿主确定为当前角色和活动存档，模型不能通过工具参数指定其他角色或存档。历史沿存档有效链读取，再按角色感知权限筛选；笔记按宿主解析的角色展示名读取。完整工具调用和结果需要配对且均可见，孤立或不完整的工具结果不进入索引。

可见历史按对话轮次组织成文档，笔记各自成为文档，再按模型 token 上限分块。含工具事务的文档保持整体。`memory_document` 保存全文，`memory_chunk` 保存分块位置和对应的可选向量，`memory_index_state` 保存角色与存档的索引状态。

文档代表一轮对话或一篇笔记，保存完整正文、角色范围、标签、来源和版本。分块记录保存文档 ID、顺序、版本、UTF-8 字节范围和可选的向量。加载时从文档还原片段正文和来源，再校验分块和向量版本。没有向量的分块仍可参与关键词和标签检索。

范围按分块顺序累计计算，避免重复段落被定位到同一个位置。写入时要求分块按顺序覆盖原文，读取时检查范围是否连续、是否越界，以及是否落在合法字符边界上；损坏或缺失的分块由后续增量同步补齐。删除文档时一并清理关联分块和向量。

从独立向量表升级时，迁移把与当前分块版本匹配的向量移入分块记录，旧索引状态在下次同步时按新规则重建。向量仍须通过模型和内容校验。迁移仅处理派生索引。

分块时先尽量保留完整句子和换行边界，只有单句超过预算才按字符边界继续切分；带工具调用的完整事务不拆开。这样普通历史能获得更准确的局部命中，工具事务也不会被拆成缺少上下文的片段。事务过长或向量模型暂时不可用时，索引仍保留关键词和标签路线，由宿主决定是否稍后重试向量化。

每次需要检索时，服务先对照来源版本同步索引，复用未变化的完整分块及向量，为新增或变化的内容重新计算。检索直接使用同步后的文档和索引指纹，指纹涵盖分块规则、模型、内容及实际向量。提交前核对来源和数据库里的旧索引指纹。角色或存档删除时清理对应索引。

当前记忆索引使用本地 `bge-small-zh-v1.5` 量化模型，与工具／笔记检索共享本地模型实例；上游新增的云端向量路由尚未接入记忆索引。模型不可用时索引可保留词法内容，向量路线不可用。

## 检索与缓存

查询分别生成关键词、标签和向量候选；对可解析的日期查询会先按时间信息筛选，再通过倒数排名融合（RRF）排序，最后按相关性阈值、来源和预算过滤。短问句包含“那次”等指代时可补充近期上下文。自动回忆和工具检索共用单轮去重及预算，默认最多引用 5 条、1800 字符，同一文档默认最多 2 条。

混合检索本身是纯内存计算：宿主先加载并限制可见文档，再交给检索器计算三路候选。检索器返回命中内容、关键词和标签命中、向量相似度、各路排名以及弱相关、日期不符、重复和预算不足等诊断；权限、索引刷新和缓存失效由主程序负责。

这三条路线各有作用：关键词适合找明确的人名和物品，标签补充笔记里已有的分类，向量负责寻找措辞不同但意思接近的内容。融合后仍要经过阈值过滤，避免把每次搜索都强行凑满结果。

只有问句的原始聊天片段会降低融合排序权重，减少旧提问因措辞相似而挤占答案资料；查询明确回顾以前问过什么时保留原排序。混有陈述、引语或补充信息的片段及笔记保留原权重。这只是保守的排序规则，不判断内容真假，也不保证每次都能找到答案。

两层内存 LRU 分别缓存查询向量和检索结果：默认上限为 128／64 条、各 1 MiB，单条最多 32 KiB。结果缓存键包含角色、存档、历史及笔记版本、索引和检索参数；查询向量缓存绑定模型与查询。即使命中缓存，返回前仍重新读取范围并复核来源。临时分词或推理失败不缓存结果，后续可重试。

## 会话与失败处理

自动回忆在构建当前角色上下文后进行。`memory_search` 可在工具循环中按需调用，接受 `query`、可选 `max_hits` 和 `kinds`，权限由工具权限配置决定。两者统一由回忆服务复核来源、去重并扣减整轮预算。自动回忆把资料作为临时旁白放在本轮上下文里最近一条 `user` 消息的正文前。主动回忆通过配对的工具消息返回，保存到历史时只保留调用配对和临时标记。

工具的 `references` 只包含本轮新增引用。`reference_status` 区分已提供新资料、资料本轮已提供、资料已在近期上下文、预算不足、没有可引用片段及检索不可用，同时返回命中数、本轮已提供数和预算排除数。空引用不能直接解释成“没有历史记录”；角色应按返回原因使用本轮已有资料。角色旧发言只证明当时这样说过，不能直接当作用户确认的事实；有明确更正时采用更正内容，无法判断的冲突需如实说明。

会话快照包含存档、角色、玩家身份、历史与生成版本。检索返回、工具执行、回复落地和发布等环节会复核相关状态；修改笔记时撤销旧引用并重建上下文。请求没有活动存档、检索关闭、繁忙、超时或失败时，不阻塞普通聊天。默认等待 2 秒，配置限制在 100–10000 毫秒；超时后后台任务仍占用唯一许可直到结束，避免推理任务持续堆积。

例如模型查到了旧笔记，随后又在同一轮修改这篇笔记，后续请求会从基础上下文重新构建，避免继续使用修改前的正文。工具触发角色切换时，沿用未注入回忆的用户消息。切换角色或存档时会重新检查所属范围和回复是否仍然有效。

`diary` 类型保留在数据契约中，当前没有接入自动日记生成与联动。桌面实际聊天、不同模型的召回效果及大规模索引性能仍需结合真实使用验证。
