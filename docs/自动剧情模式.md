# 自动剧情模式

## 概念

自由对话中主要只有 `AI` 和 `玩家` 两个对象。顶多偶尔加一点其他角色。上帝Agent（也被称为`导演`，后续我们称为`导演Agent（异步）`，是上帝Agent的一种变体，比如现在上帝Agent的变体有`好感Agent（异步）`,`选人Agent（同步）`）只有在剧情模式中才会操作游戏，而且剧本是之前写死的内容

为了让剧情更加“AI开放式”，加上工具函数的基石也搭建完毕了。现在允许上帝Agent导演执行以下功能：

1. 玩家可以开启`自由剧情模式`，自由剧情模式下，上帝Agent会随时调用剧本事件，对游戏世界进行操作
2. 首先，会为`上帝Agent（导演）`注册所有剧本事件的工具函数，比如插入旁白，转换场景，切换角色，操作舞台等。
3. 每对话一段时间，`导演Agent`会根据对话内容生成一段`小剧本`，添加旁白为对话引入新的变量，调用工具函数，对游戏世界进行操作。
4. 前端右边侧栏可以打开与`导演Agent`的对话窗口，方便玩家查看导演思路，也可以引导导演安排自己想要的剧情走向。

## 实现步骤

### 1. 在前端新增一个侧栏，用于显示与`导演Agent`的对话

首先做好侧边栏，定义好`导演Agent`的上下文窗口，先把`Agent`对于剧本的感知，基础的玩家对话问答给做出来。

### 2. 将所有剧本事件注册为工具函数，这些函数可以由`导演Agent`调用

把本项目的所有剧本事件注册为工具函数，这些函数可以由`导演Agent`调用。如果玩家和`导演Agent`对话希望安排剧情，`导演Agent`会调用这些工具函数，对游戏世界进行操作。

### 3. `导演Agent`根据对话内容生成一段`小剧本`

提供`导演模式开关`，开启状态下，每过X轮对话，`导演Agent`会根据对话内容生成一段`小剧本`，大约在10个事件左右。

## 项目基础

### 1. 剧本事件概念

本项目的前端的变化由后端发送的事件来驱动，这些事件被称为`剧本事件`，在`crates\ling-chat-main\src\ai_service\game_system\script_engine\events`。在自由模式中，由后端推送的事件主要有：

1. `AI对话`：也就是`dialog_event`事件，主要用于推送`AI`回复的内容
   而剧情模式中，包含更多剧本模式事件。（这提醒我了，能不能自由模式中的切换角色，切换场景，切换特效之类的东西，统一走这里的事件引擎统一逻辑呢？）

也就是说，只要后端发送这些事件，就完成了对游戏的操作。

### 2. 台词表概念

`LingChat`对各Agent驱动的核心由台词表构成，上帝Agent的感知上下文可以参考好感度系统，选人系统等。

## 实现进度（2026-11-17）

### 已定架构

上帝 Agent 是平台层，持有模型槽位、最高权限工具、世界上下文与各 Agent 的生命周期；新增 Agent 一律作为它的分支，按运行形态分两类：

- 无头决策分支：`capabilities/` 下的 speaker、affection，一次任务一次结果，不持有会话；
- 交互会话分支：`director/`（导演，本期），持有会话、落库、流式推事件。未来的剧本 Agent 也归入这一类。

分支实例由 `GodAgentCore` 持有（如 `pub director`），共用同一个 LLM 槽位；中枢只存字段、转发命令，不承接分支的会话细节。暂不抽 trait、不建分支注册表，等第二个交互分支出现再提炼共性。

### 步骤 1 已完成

**存储层**（提交 `3cf87db3`）

- 原 `skill_agent_conversation` / `skill_agent_message` 泛化为 `agent_conversation` / `agent_message`，新增 `kind`（`skill` / `director`）与 `save_id`，索引 `(kind, save_id, updated_at)`；
- 一档一条导演线，取最新一条；删档级联清理；局域网同步排除带 `save_id` 的导演会话；
- 通用读写留在 `ai_service/skill_agent/db.rs`，导演会话有专用入口，不再出现裸查询。

**后端运行层**

- 代码位置：`crates/ling-chat-main/src/ai_service/god_agent/director/`（`mod.rs` 放消息、上下文快照与事件协议，`core.rs` 放会话同步、上下文装配与流式运行），命令层在 `api/director.rs`；
- 六个命令：`director_get_state`、`director_start_chat`、`director_stop_chat`、`director_clear`、`director_get_context`、`director_get_tool_history`；
- 流式经 `tauri::ipc::Channel` 推送，事件类型为 status / message_delta / reasoning / tool_call / tool_result / done / error；
- 停止用取消令牌在 chunk 之间中断，不用 abort 硬杀；停止、出错、正常结束都会把已产出的正文落库；
- 导演与上帝 Agent 共用 LLM 槽位，热切换自动生效；无可用模型时返回 `available=false`，前端只显示空态。

**上下文装配**

- 每轮现拼 system：人设、当前现场（模式、时间、场景、背景、音乐、氛围、天气、当前发言者）、在场角色（名称、副标题、简介、是否在舞台，最多 12 位）、最近台词；
- 台词取上帝 Agent 配置的 `recent_window`（默认 20 条）；单条台词截 240 字、角色简介截 200 字、对话段截 6000 字、system 总长 10000 字；
- 会话历史超过 12000 字时按整块裁剪，assistant 与其工具结果算一块、不拆配对，裁剪条数进入统计；
- 「查看记忆」展示上次实际请求的快照（`source=last_run`），也可按当前现场重新装配（`source=rebuilt`），两者互不覆盖。

**存档绑定**

- 有存档时逐条落库、读档可见；自由对话只在内存，重启即失；
- 每条命令入口比较当前存档与已同步存档：自由对话转有档时把内存对话收编进新档（自动存档触发是常态路径），换档重新载入，回到自由对话则清空；
- 切档时若还没聊过，不提前建空会话行，首次发言才建。

**前端侧栏**

- 主聊天页右侧把手与面板：默认 420、最小 320、最大 `min(720, 55vw)`，窄屏退化为抽屉；
- 三个 tab：主对话（流式正文、思考过程折叠、停止、清空）、查看记忆（来源标注、重新装配、字符与条数统计、system 分段、消息序列）、工具调用历史（本期空态）；
- 只持久化开合、宽度与当前 tab；消息、快照、工具历史属运行时状态，不进 localStorage；
- 打开设置面板时自动收起，关闭后重新拉一次导演线（读档与开新档都发生在设置里）。
