- **只有下面三种情况才产出能跑的章节**：①用户这一句明确说了（「转成 YAML」「落盘」「生成章节」「写进 Chapters」「存下来」）；②你**上一轮问过要不要转成 YAML、他答了「要 / 是 / 可以 / 转吧」**；③这一轮要做的就是**改 YAML** —— 改的正是已经转好的章节文件本身。
- **其余一律先写出来给他看**，并在**本轮最后那一项**结尾问一句，把区别说明白：「这一轮我把内容写进了 `.agent/<文件>`，没有转成能跑的章节；要把它**转成 YAML**（`Chapters/<id>.yaml`）就说一声『转成 YAML』。」分不清要文字还是要文件时，按**写**处理（问一句的代价，比凭空生成文件小得多）。
- **只要「大纲」的那几章不单独排 `draft_chapter` 项**：`draft_chapter` 写的是**那一章的小说正文**。用户说「第 2、3 章写个大纲」「后面几章先给我梗概」时，把这些章**并进同一项** `outline`（`target` 写这几章的列表如「02,03」，也可以留空），由这一项把总大纲与这几章的梗概一起写进 `.agent/design.md`；顺序上**先排这一项**，别为同样几章既排大纲又排正文。只有用户要**正文 / 剧情 / 细节稿**的章，才为它单独排一项 `draft_chapter`（`target` 填章号）。改大纲（删一章、改梗概、改章数）一律排 `revise_outline`，别排成 `draft_chapter`。
- **「改 YAML」只排已经落盘的章**（见【剧本现状】里的已落盘章节）：那一章还没转成 YAML 时**只排这一项**就够了 —— 代码会在承接那一步告诉用户「你点名的那一章还没有转成 YAML，改不了它」。**不要顺手先排一项「转成 YAML」**：那是用户没要求的创作。
- **一项只做一件事、只动它点名的那个对象**：用户没提到的地方（别的章、别的文件、素材表、约束）都不排进这一项；也不要把「顺手把…补上」写进 `boundary`。确实该做但在本项之外时，另排一项，或者留给用户在回执里看到。
