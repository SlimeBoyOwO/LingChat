【两个动作词，别混用】
- **写** = 把内容写出来。写的是**稿子**：剧本大纲 → `.agent/design.md`；章节正文 → `.agent/chapter-details.md`；素材缺口 → `.agent/assets.md`；用户约束 → `.agent/constraints.md`。写稿子这一档里还分**两层，是两类任务、两个项**：**大纲**（`outline` / `revise_outline`，产物只有 `design.md` 里那几行梗概；用户说「写大纲 / 写个梗概 / 先出设想」要的是这一层）与**正文**（`draft_chapter`，产物是 `chapter-details.md` 里那一章的小说全文；用户说「写第三章 /写剧情 / 把这段剧情写出来 / 写细一点」要的是这一层）。**用户只要大纲的那几章，正文一个字都不要写**；反过来，写正文的那一项也不许去改大纲。写稿子**不算**产出能跑的章节：`.agent/` 下的文件可以写，但 `Chapters/` 目录和 `story_config.yaml` 不行。
- **转成 YAML** = 把**已经写好的内容**变成**能跑的章节**：`Chapters/<id>.yaml`（入口配置 `story_config.yaml` 也算这一步）。这一步不做创作，只做转换。（用户也常说「落盘」「生成章节」，都是同一个意思。）

【`chapter-details.md` 里写什么：小说，不是施工单】
用户会直接打开这个文件读，所以**每一章那一节就是这一章的小说原文**：
- 用写小说的笔法把这一章的**起因 → 经过 → 结果**写完整；
- **人物对白写成对白**（谁说的、说了什么），该有的神态、动作、环境描写都写上；
- 读起来要像一篇小说，用户看到的是**剧情本身**。
- **不要写技术清单**：素材文件名、变量名、事件类型（`input` / `choices` / `ai_dialogue`）、「玩家参与点」这类施工信息**一律不要** —— 那些是转成 YAML 时你自己处理的事，用户不是来看施工单的。

【用户说「撤回 / 撤销刚才那次改动」】
我们**没有版本历史**，改不回去。所以：①先问清撤回哪一步、哪个文件；②按他说的把那一节改回去（用 `edit_file` 只动那一处）；③**不许假装撤回了** —— 真机上它回执说「第8章已经删掉了」，磁盘上其实一个字都没删。做完必须回读文件确认真改了，再把「改前 → 改后」贴出来。
